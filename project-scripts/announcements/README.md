# 合集配置编辑

在项目目录执行 `npm run config:edit`，服务启动后会自动在浏览器打开 `http://127.0.0.1:4318`。游戏配置、版本公告、广告配置、发布与调试共用一个本地服务和一个页面，通过左侧入口切换。原有 `npm run announcements` 仍启动同一服务。

可用 `CONFIG_EDITOR_PORT` 改端口，也兼容原有 `ANNOUNCEMENTS_PORT`；执行 `npm run config:edit -- --no-open` 不自动打开浏览器。游戏清单校验直接使用项目的 TypeScript 模块，需要现有的 TypeScript / `tsc`。

## 游戏配置

从左侧选择游戏，可编辑以下内容：

- **名称与简介**：放在顶部，名称以大字号突出，右侧实时预览大厅卡片。
- **推广与上线**：NEW / HOT 独立选择、启用状态、公开 / 仅开发可见。
- **分类与版本**：内容分类通过标签逐个添加、删除，Enter 可添加，不能重复；内容版本与最低合集版本放在次要区域。
- **默认顺序**：页面下方的上移 / 下移改变 `games.json` 条目顺序。实际大厅仍按最近游玩、NEW 与游玩历史排序。

封面、成就与大厅进度、高级加载配置不提供编辑控件；保存接口也不会写入这些字段，原值与未来增加的非编辑字段均从磁盘保留。封面图片仅用于只读预览。

切换游戏或四个配置页面均保留各自的草稿；左侧圆点提示未保存。**保存游戏配置** 一次保存所有游戏的修改到 `assets/resources/configs/games.json`，保留原文件缩进和非编辑字段。游戏 ID 固定；新增游戏仍需先在项目中实现独立场景、Bundle 和生命周期，再注册清单。

保存前直接调用游戏运行时的 `GameManifestValidator.ts` 校验，失败时保留输入并列出字段错误，点击错误可定位对应游戏和字段。运行时校验规则或其依赖源码变化后，下次读取规则时自动重载全部依赖，无需重启编辑服务。多个页面或外部编辑器改过文件时拒绝覆盖；使用 **重新读取** 获取最新配置（有草稿时会提示是否放弃）。

保存后经 Cocos MCP 刷新资源。刷新失败时配置仍已保存，页面明确提示失败原因；打开 Cocos 项目后可点击 **重新刷新 Cocos** 重试。重新启动浏览器预览后加载新配置，微信端随下次构建发布生效。

游戏改名时会同步生效公告中的游戏名快照；历史公告的 ID 和内容保留。写入联动文件失败时恢复游戏清单与原生效公告。

## 广告配置

- 每个已接入游戏的广告入口开关，写入 `ads.games.<游戏 ID>.enabled`。
- 微信激励视频广告位：按游戏展示用途和广告单元 ID，写入 `ads.wechat`。空 ID 表示未配置。
- Tap 共用激励视频广告单元，写入 `ads.tap.rewardedVideo.adUnitId`。

页面按运行时已注册的广告配置生成；未接入的游戏只提示状态，不提供无效的启用开关。当前木框拼图有入口开关，但没有独立的微信广告位。模拟广告开关位于发布与调试页，广告页展示已保存的模式。

## 发布与调试

- 合集版本 `appVersion`：使用与运行时相同的语义版本规则；作为新公告的默认版本，已有公告仍独立保存。
- `development.showDevelopmentGames`：在浏览器预览显示仅开发游戏；微信与 Tap 不展示。
- `development.mockAds`：浏览器与微信使用模拟广告；Tap 始终使用真实广告服务。
- `fonts.enabled`、`fonts.validateCoverage`、`fonts.loadTimeoutMs`：自定义字体、构建与命令行缺字检查、字体加载超时。

广告与发布配置写入 `assets/resources/configs/app.json`，**分别保存当前页面**，保留另一页草稿及分享、云存档、画质、分辨率等其他配置。两页分别记录相关分区版本：保存一页不会阻止另一页正常保存；相同分区被外部编辑时拒绝覆盖，并保留草稿。原子写入保留原缩进；保存后刷新 Cocos，运行时设置在重新启动预览或下次构建发布后读取。

## 版本公告

公告页保留新增、编辑、生效、删除、封面预览与复制审核纯文本操作。

## 内容框架

每条公告固定三个模块，顺序不可调整：

| 模块 | 可选目标 |
| --- | --- |
| 新游戏 | `games.json` 中的游戏 |
| 新功能 | 游戏合集（大厅本身）或任一游戏 |
| 问题修复 | 游戏合集（大厅本身）或任一游戏 |

每个模块可以添加 0 到 n 个游戏；同一模块里一个游戏只写一条、一句话（上限 60 字，建议 30 字以内）。没有内容的模块不会在游戏内展示，也不会出现在纯文本里。

## 操作

- **新增 / 编辑**：左侧列出全部历史公告（最新在前），右侧编辑版本号、日期与三个模块，并实时预览弹窗（模块从上到下排列、条目附大厅封面）和纯文本。
- **设为生效**：同一时间只有一条公告生效。生效后写入 `assets/resources/configs/announcement.json`（附带当时的游戏名快照），再通过 `cocos_creator_stdio` 同一项目 MCP 刷新 Cocos 资源；刷新需要 Cocos Creator 已打开项目。编辑生效中的公告保存后会自动重新同步。
- **删除**：从历史中移除当前公告。删除正在生效的公告会清空游戏内配置并刷新 Cocos，大厅不再显示公告按钮；删除其他历史公告不影响当前生效内容。
- **复制纯文本**：按“【模块】+ 编号 + 游戏名：内容”复制当前编辑内容，用于填写审核信息。

历史公告保存在 `announcement-sources/announcements.json`，随项目提交；游戏包里只有生效的那一条。

## 游戏内行为

- 公告只在玩家点击大厅顶部栏的公告按钮后打开，不自动弹出。生效公告 ID 与上次看过的 ID 不同时，入口右上角显示红点；点击查看后红点立即消除。修改已生效公告的文字不会重新提示，切换到不同 ID 的公告才会。
- 设备本地只保存最后看过的一条公告 ID，查看后立即落盘。看过 A 再看 B 后，重新生效 A 会再次显示红点；游戏进度和云端恢复不覆盖最后已读 ID。运行时回归验证：`node tools/verify-announcement-auto-open.cjs`。
- 公告标题下方展示公告版本号（如 `v0.0.8`）；条目封面与对应文字块垂直居中。
- 有内容的模块按新游戏、新功能、问题修复的顺序从上到下排列，内容超出屏幕时在弹窗内上下滑动，每次打开回到顶部；条目左侧展示该游戏的大厅封面，游戏合集条目展示大厅标志。
- 关闭时面板缩回公告按钮。没有生效公告时不显示公告按钮。

## 验证

所有验证都在临时项目中执行，不修改真实游戏、应用或公告配置：

```sh
npm run verify:config-editor
npm run verify:config-editor:browser
```

前者验证公告原有操作、运行时清单规则、游戏保存与隐藏字段保护、名称联动、广告与发布独立分区保存、冲突保护、写入失败恢复、访问控制和刷新反馈。浏览器验证四页切换、标签增删、独立草稿与保存、错误定位、默认顺序、公告操作和窄屏布局，需要本机 Playwright，可用 `PLAYWRIGHT_MODULE` 指定模块路径。原有 `npm run verify:announcements` 继续单独验证公告。
