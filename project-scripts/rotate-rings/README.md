- 立体感：陶瓷着色器收紧暗部、加边缘遮蔽和釉面高光，投影加深加大。
- 选关：关卡格换成与棋盘同材质的陶瓷 C 形环（`createRingArcMesh` 按原网格路径约定生成）；已通关按七色釉轮换、缺口朝向各异且不再显示星星；当前关为模式主色、放大并缓慢转动缺口、带呼吸光晕；未解锁为浅灰釉，缺口朝下卡着锁。标题两侧各一只陶瓷环。各部件分层摆放以便合批。

源目录是 `tmp/rotate-rings/` 中已还原的 Unity 关卡、Bundle、图片及音频。导入工具只读源数据；正式运行不依赖 `tmp`。

## 重新导入

在项目根目录执行：

```sh
node project-scripts/rotate-rings/import-levels.cjs
tmp/rotate-rings/tools-bin/venv/bin/python project-scripts/rotate-rings/import-original-meshes.py
python3 project-scripts/rotate-rings/build-level-packs.py
python3 sprite-atlas-sources/build.py --game rotate-rings
```

网格导入需要 UnityPy、Pillow；关卡合包使用 Python 标准库 zlib，音频导入需要 FFmpeg，短音效输出到audio-bank-sources/rotate-rings并自动调用公共合包工具；显式重打包可执行python3 audio-bank-sources/build.py --game rotate-rings。逻辑与原网格先输出到忽略提交的 `local/rotate-rings-build-source/configs/`，由 `build-level-packs.py` 生成正式资源；不会把原始逐关 JSON 和大网格放回 Bundle。只更新动画配置时可单独运行 `tmp/rotate-rings/tools-bin/venv/bin/python project-scripts/rotate-rings/original_config.py`，不会覆盖已压缩的图片。随后按 `sprite-atlas-sources/README.md` 的导入、元数据同步、编辑器 `save_meta`、压缩和校验流程处理这款游戏的3页图集；每批改动后使用 `cocos_creator_stdio` 刷新对应资源。法线和 SDF 是数值纹理，源图保持无损。按用户授权对包含它们的成品图集进行 Tinify 有损压缩时，保留压缩前备份并校验压缩前后的实际棋盘渲染；压缩后的采样值不再保证逐像素一致。

图片素材已按「晴空糖环」主题全部重绘：生图提示词、批量生成与后处理脚本在 `tools/rotate-rings/reskin-*.py|sh`，后处理后的源图在 `sprite-atlas-sources/rotate-rings/visual/`，正式资源仅保留生成图集和等比缩小的背景。圆环的 `ring-normal`、`ring-sdf` 与 `ring-texture` 的 alpha 是决定形状的数值数据，保持原样；`ring-texture` 只重绘表面明暗。音频来源记录在 `original-audio.json`。原始入场、受阻回弹、按钮点击配置保存于 `rotate-rings-sources/`，弹窗、连击与碎片粒子配置保存在 `feedback-config.json`。所有图片按实际显示尺寸1:1缩小后合图，碎片按最大显示尺寸72像素、爆炸序列帧按140像素。

正式关卡采用逐字节形状去重与 [DEFLATE 无损压缩](https://www.rfc-editor.org/rfc/rfc1951)：7769个部件实例只包含3265种不同网格，颜色和部件ID保存在逐关引用表，相同形状只存一次。保留全部 Float32 XY/路径距离/路径长度、UNorm16 横向 UV、SNorm16 切线 XY、Int8 切线手性和材质样式及 Uint16 三角形索引，不量化、不简化多边形。原 `RRM2` 读取器仅用于离线对照，正式运行读取新小包。

`configs/levels.bin` 将384个关卡记录合入一个原生文件，`configs/geometry.bin` 将52个共享网格分段合入另一个文件，`configs/collisions.bin` 保存92种原碰撞轮廓。关卡目录的 packing.version 为2。两个合包采用 `RRA1`：magic、Uint32记录数、逐项 Uint32 ID/偏移/长度和连续记录内容。每条记录仍独立使用 `RRZ1`（magic、原始长度、Adler32、raw-DEFLATE），只读取索引和字节切片，不整体解压。关卡记录为 `[关卡对象, [[部件ID, 形状索引, RGB整数], ...]]` 的ASCII JSON，bodyIndex引用共享碰撞轮廓；网格分段内部仍是最多64种形状的 `RRG3`。读取器核对合包索引、重复ID、范围、尾部、压缩校验和与网格引用。原生二进制文件由437个减至3个，保留全部关卡和网格字节。

资源由独立 `game-rotate-rings-assets` Bundle和公共 `AssetService` 加载。Manifest的resourceDirectories包含visual与configs，进入加载阶段准备3个关卡/网格/碰撞原生文件、清单、图片和材质；初始化准备2首音乐和1个短音效包，静音进入也完整解码22段短音效。微信资源Bundle保持isRemote=true和merge_all_json：此设置只合并Cocos导入JSON，不会合并原生.bin、.mp3、.png。关卡与网格按索引合包后，关内切关仍只解压当前关和需要的网格分段；短音效合包沿用公共AUDIOBNK格式，不重复下载、不重新编码。退出清理解码缓存和本局音效Scope，资源/派生音频缓冲由AssetService随Bundle释放。

原网格由 Cocos 2D Sprite 批处理显示，保留原路径 UV、七种颜色、法线和 SDF；`rings-ceramic.effect` 转译原半 Lambert、Screen 光照与线性色彩公式。主网格与阴影使用独立单 Pass 材质，避免 Cocos UI 多 Pass 共用深度状态；原卡扣的 Z=-0.001 转成 Cocos 相机前方深度，阴影代理位于主网格后方。网格缓冲由 UI 渲染器持有和释放，材质实例通过 `AssetService` 追踪，退出时统一销毁。

游戏入口直接进入本地记录的上次模式和关卡，恢复圆环角度、滑杆位置、消除状态、炸弹状态、分数、步数与游玩时间；首次进入直接玩普通第一关。触摸结束、暂停和退出立即保存，关内每秒保存一次。首关使用引导手图片循环演示滑动，演示只改变显示姿态；玩家首次有效转动后记为完成教学。通过设置菜单进入选关，保留普通/困难分页；当前关卡没有额外纯色外描边，点击直接进关，无关卡详情页。选关列表按前/当前/后三页轨道跟手拖动，拖到一半停住时停在手指位置，松手按距离135或速度600翻页、否则回弹（停住超过100ms再松手不算甩动）；关卡格不单独吃触摸，点按由翻页区判定。

正式圆环的阻挡、炸弹接触和命中使用原本体多边形与统一变换，保留内外轮廓、圆头、缺口及闭合环孔洞。碰撞补齐环带与环带、环带与滑杆检测，继续检查两条实体爪、硬挡板等；浮点穿透容差从0.05收紧至0.002；卡扣两条碰撞爪整条位于画出的卡扣之外（内缘离可见边0.04），爪与环带碰撞额外允许压入这段余量，接触点与画面上卡扣边缘一致，避免看着有空隙却被卡住。沿完整旋转路径细分探测，最远端每步移动不超过0.025，避免快速拖动跨过细爪。按住时只更新合法姿态和收集炸弹接触，经过可解姿态也可继续转动；松手才按最终姿态重新检查每条仍在场的套接，并检查新叉住的其他邻居。尚未消除的关系不再记忆此前的对准状态；闭合环的叉口仍有环带时保持锁定，修复旧逻辑反向判定造成66关初始部件误消除。每次有效手势计一步，消除、得分、连击和通关均在松手提交。滑杆出口在独立探测中先处理沿途实际炸弹接触，再检查实体阻挡，成功后保留最后可见位置用于碎片发射。
