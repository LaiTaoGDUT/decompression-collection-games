# 游戏文案审校

在项目目录执行 `npm run copy:review`，打开终端显示的本地地址（默认 `http://127.0.0.1:4317`）。服务器也会保存可直接打开的 HTML 到 `local/copy-review/review.html`。写回需要本地服务仍在运行，以及 Cocos Creator 3.8.8 的项目 MCP 已打开。

页面按大厅、公共界面与八个子游戏分组。原文、推荐修改和最终文案并排展示；只有需要调整的条目提供建议。新文案默认采用建议，无建议的条目保持原文。可以逐条恢复原文、采用建议或自行修改，也可以对当前筛选列表批量操作。

编辑会自动保存在浏览器本地，也可以导出 / 导入 JSON 草稿。脚本、场景、预制体中的相同文案按游戏分组去重，修改后更新全部对应引用。游戏清单的名称与简介归入对应游戏组。点击来源可以查看原文件、行号、代码和动态值。

`{0}`、`{1}` 等代表原模板中的动态表达式，`{N}`、`{CATS}` 等是游戏自身使用的替换标记。编辑时必须完整保留占位符及顺序。其他文字可以修改，换行可以直接在输入框中输入。写回使用 TypeScript AST 的具体位置，只改字符串或模板的静态片段，不替换评论、类型、表达式和业务逻辑。

点击“应用新文案”后，本地服务会核对源码版本、备份原文件、写入修改、检查字体覆盖、执行 `tsc --noEmit -p tsconfig.json` 与 `git diff --check`，最后通过与 `cocos_creator_stdio` 相同的项目 MCP 调用刷新 `db://assets`。只有刷新返回成功才报告应用完成；校验或刷新失败会恢复原文件并再刷新。备份和应用日志位于 `local/copy-review/backups/`，保存的是应用前的工作区文件，包含当时已有的未提交修改。

同一服务运行期间可以“撤销上次应用”。若应用后文件又被外部修改，自动撤销会拒绝覆盖。源码发生冲突时，先“重新扫描”；原文未变化的草稿会保留，原文已变化的旧草稿会显示在冲突区。导出需要保留的内容并处理过期草稿后再应用。

图片中的文字按用户要求不纳入本次整理和修改。清单包含错误兜底、初始 Label 占位文字、保留的调试界面文案，部分初始文字会被运行时覆盖；纯动态数字、注释、资源地址、类型和设计元数据不作为文案修改。

若手动文案引入当前字体没有的字，本工具可以用项目已有的字体构建脚本补字。配置环境变量 `COPY_REVIEW_FONT_SOURCE`（含 `ResourceHanRoundedCN-Regular.ttf`、`ResourceHanRoundedCN-Bold.ttf` 的完整字体目录）与 `COPY_REVIEW_PYTHON`（有 `fontTools` 的 Python），或在被 Git 忽略的 `local/copy-review/config.json` 中保存 `fontSource` 和 `python`。字体也会参与备份和恢复。缺少完整字体或 Python 时应用会回滚并给出具体说明，不会把字库覆盖文件伪造为已支持新字符。

本地服务只监听 `127.0.0.1`，检查 Host、来源和页面会话令牌，接受当前清单内的条目 ID，不接受客户端文件路径。重新启动后旧页面令牌失效，重新打开页面即可继续；草稿仍保留。

运行 `npm run verify:copy-review` 验证实际源码提取、模板占位符、嵌套表达式、场景 JSON、精确写回、冲突检测、失败回滚、撤销、并发锁及 HTTP 访问控制。测试使用临时项目，不修改游戏文件。
