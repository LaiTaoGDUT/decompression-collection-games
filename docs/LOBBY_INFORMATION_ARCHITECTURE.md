## 1. 大厅职责

大厅只负责让用户识别产品、查看可玩内容与历史成绩、进入游戏、调整公共设置和确认版本信息。首发大厅不承担活动运营、排行榜、账号、任务、推荐算法或内容分类职责。

大厅只消费经过校验的 `GameManifest`、公共存储和公共服务，不导入 `WatermelonGame`、`Blocks3DGame` 或任何游戏专属资源。

## 2. 首发页面结构

```text
Lobby / Canvas
└─ SafeArea
   ├─ Header
   │  ├─ ProductTitle：解压小游戏
   │  ├─ ProductSubtitle：随时来一局，轻松一下
   │  └─ SettingsButton：设置
   ├─ MainScroll
   │  └─ GameGrid：固定双列标准卡列表
   │     ├─ GameCard[0]：第一个真实游戏
   │     ├─ GameCard[1...n]：其余真实游戏，按 Manifest 顺序
   │     └─ ComingSoonCard：固定追加在全部真实游戏之后
   ├─ EmptyOrErrorState：与游戏网格占用同一内容区域
   └─ Footer
      ├─ VersionLabel：版本号
      └─ NecessaryNotice：必要说明入口

Overlay
├─ SettingsDialog
├─ LoadingLayer
├─ ErrorLayer
└─ ToastLayer
```

产品首发显示名称冻结为“解压小游戏”，副标题冻结为“随时来一局，轻松一下”。文案必须通过大厅配置或集中常量提供，不散落在 Prefab 或多个脚本中；后续品牌调整不得改变页面信息层级。

## 3. 信息层级

| 优先级 | 信息 | 用户问题 | 呈现位置 |
| ---: | --- | --- | --- |
| 1 | 产品标题 | 我在哪里？ | 顶部品牌区 |
| 2 | 游戏封面与名称 | 有什么可以玩？ | 标准游戏卡上半区 |
| 3 | 进入操作 | 如何开始？ | 整卡触摸区与卡内统一按钮/操作提示 |
| 4 | 游戏短说明 | 玩法大概是什么？ | 游戏卡名称下方 |
| 5 | 历史最高分 | 我之前玩到什么水平？ | 游戏卡信息区 |
| 6 | 更多游戏预告 | 后续还会有内容吗？ | 真实游戏列表末尾的敬请期待卡 |
| 7 | 设置 | 如何关闭音乐、音效或振动？ | 顶部独立入口 |
| 8 | 版本与必要说明 | 当前是什么版本、需要了解什么？ | 页面底部 |

大厅不设置轮播图、主推横幅、主推角标、“热门”排序、跨列大卡或卡外独立开始按钮。所有游戏的名称、说明、成绩和进入操作都在各自卡片内闭合。

## 4. 固定双列网格规则

- 游戏列表固定为两列等宽网格；所有真实游戏卡使用相同宽度、高度、内部结构和交互权重，敬请期待卡使用相同外部尺寸但明确不可交互。
- 排列数据先取可见 Manifest 列表顺序，再在末尾追加一个 `ComingSoonCard`，整体按从左到右、从上到下的行优先顺序渲染。
- 索引为偶数的卡片位于左列，索引为奇数的卡片位于右列。
- 合并敬请期待卡后的总卡片数为奇数时，最后一张卡保留在左列；右列留空，不跨列、不居中、不放大。
- 首发普通用户只有“合成大西瓜”一张真实游戏卡：该卡占第一行左列，敬请期待卡紧随其后占第一行右列。
- 网格位于纵向滚动区域；标题、设置入口和安全区不随卡片数量改变结构。
- 不按历史成绩、最近游玩、设备性能或广告状态动态改变排序。
- 被开发配置隐藏的游戏不占空格；真实游戏索引基于最终普通用户可见列表重新计算，然后追加敬请期待卡。
- 敬请期待卡不写入 Manifest、不使用虚假游戏 ID、不参与可玩资格过滤，也不触发 `GameRuntime`。
- 有至少一个真实游戏时才追加敬请期待卡；目录为空或加载失败时展示对应页面状态，不用敬请期待卡掩盖异常。

具体卡片尺寸、列间距、圆角与字体由第 6、8 步确定，但不得破坏以上结构规则。

## 5. 标准游戏卡内容

每张卡只包含以下信息，顺序一致：

| 区域 | 字段 | 数据来源 | 首发规则 |
| --- | --- | --- | --- |
| 封面区 | `cover` | `GameManifest.cover` | 使用本游戏 Bundle 外可供大厅读取的正式大厅封面；失败时使用统一安全占位，不跨 Bundle 导入游戏资源 |
| 标题区 | `name` | `GameManifest.name` | 单行优先；过长时按统一规则截断，不缩小某一张卡形成特例 |
| 说明区 | `description` | `GameManifest.description` | 最多两行，说明核心动作，不展示开发术语 |
| 成绩区 | 历史最高分 | `StorageService` 中该 `gameId` 的 `highScore` | 有纪录显示“最高分 {score}”；无纪录显示“尚无纪录” |
| 操作区 | 进入操作 | 卡片本地状态 + `GameRuntime.enterGame(manifest)` | 默认“开始”；等待“加载中”；禁用显示原因；失败显示“重试” |

整张卡与卡内进入操作共享同一个进入请求和同一个触摸语义，不允许一次点击触发两次。卡内按钮用于明确可操作性，不建立第二条独立导航路径。

首发卡片不显示以下内容：游戏版本、Bundle 名称、渲染模式、设备档位、标签、广告标识、排行榜名次、玩家头像、推荐角标或独占主推文案。

## 6. 敬请期待卡

敬请期待卡是大厅自身的静态系统卡，不是禁用游戏卡，也不是 Manifest 数据：

| 字段 | 冻结内容 |
| --- | --- |
| 节点语义 | `ComingSoonCard` |
| 主文案 | 更多游戏 |
| 辅助文案 | 敬请期待 |
| 尺寸 | 与标准游戏卡完全相同 |
| 位置 | 所有真实游戏卡之后 |
| 图形 | 使用与大厅视觉规范一致的简单装饰或加号/星光意象，不使用游戏封面占位图 |
| 交互 | 无按钮、无点击反馈、无进入请求 |
| 无障碍语义 | “更多游戏，敬请期待，不可操作” |
| 数据来源 | 大厅集中配置/文案常量，不进入 `games.json` |

该卡不得显示“开始”“重试”“暂不可用”等游戏操作文案，不记录游戏曝光/点击事件，也不得通过透明按钮或 Toast 暗示当前可进入。

## 7. 首发目录与开发回归边界

### 6.1 普通用户目录

普通用户首发列表只包含：

| 顺序 | 游戏 ID | 显示名称 | 位置 |
| ---: | --- | --- | --- |
| 0 | `watermelon` | 合成大西瓜 | 第一行左列 |
| 1 | 无（系统占位） | 更多游戏 / 敬请期待 | 第一行右列 |

实际隐藏 `blocks3d` 的 Manifest/配置实施保留到第 11 步。本步骤冻结产品结构，不提前修改 `games.json` 或 `GameRegistry`。

### 6.2 开发回归目录

`blocks3d` 仅能通过开发配置或调试入口显式开启。开启后也使用相同标准卡和双列排序，不获得主推样式；敬请期待卡移到全部真实游戏卡之后。`blocks3d` 卡片内容不得出现在候选构建或普通用户截图中。

### 6.3 可见性来源

- 游戏是否面向普通用户展示必须由 Manifest 或环境配置决定，大厅脚本不得写 `if (gameId === 'blocks3d')` 一类硬编码隐藏逻辑。
- `enabled`、`minimumDeviceTier` 和 `minAppVersion` 继续作为运行资格条件。
- 若后续需要区分“开发可见”和“普通用户可见”，必须在配置/目录边界扩展明确字段或目录来源，并先记录协议迁移；不能借 UI 排序或透明卡片实现隐藏。

## 8. 大厅与卡片状态

### 7.1 大厅内容状态

| 状态 | 页面内容 | 可用操作 |
| --- | --- | --- |
| 正常 | 品牌区、双列卡片、列表末尾敬请期待卡、设置、页脚 | 进入真实游戏、设置；敬请期待卡不可操作 |
| 目录加载中 | 品牌区和页脚保留，网格显示统一骨架/等待 | 设置可用；游戏进入禁用 |
| 空目录 | 显示“暂时没有可玩的游戏”和“重新加载” | 重试、设置 |
| 目录失败 | 显示简化原因、“重试”和必要诊断编号 | 重试、设置；不显示半份列表 |
| 游戏进入中 | 目标卡显示“加载中”，全局加载层接管输入 | 不重复进入其他游戏 |
| 从游戏返回 | 恢复原滚动位置，刷新该卡历史最高分 | 进入游戏、设置 |

### 7.2 单卡状态

| 状态 | 封面/信息 | 操作区 | 交互 |
| --- | --- | --- | --- |
| 默认 | 完整显示 | “开始” | 整卡可点击 |
| 按下 | 信息不位移、不消失 | 保持“开始” | 只提供视觉/声音反馈，不提前导航 |
| 加载中 | 保持内容，显示局部等待反馈 | “加载中” | 整卡禁用，重复点击不创建 Session |
| 禁用 | 信息保持可读并弱化 | “暂不可用”及简短原因 | 不进入游戏；点击可提示原因 |
| 封面失败 | 使用统一占位封面 | 仍为“开始” | 封面失败不阻断进入 |
| 进入失败 | 保持原卡内容并标记失败 | “重试” | 与统一错误页的重试共用一个进入动作 |
| 敬请期待 | 固定主/辅助文案与大厅装饰 | 无操作文案 | 无触摸、无请求、无 Session |

设备或版本不满足运行资格的内容原则上不进入普通用户列表；若资格在列表呈现后发生变化，卡片转为禁用态并说明原因，不静默点击无响应。

## 9. 设置与页脚信息

### 8.1 设置入口

- 设置按钮位于标题区，与任一游戏卡无从属关系。
- 设置弹窗只包含音乐、音效、振动三个开关和关闭操作。
- 设置值来自公共存储并即时生效；失败时回滚到最后一次成功值。
- 平台不支持振动时显示禁用状态和原因，不隐藏整个设置项。

### 8.2 版本与必要说明

- 页脚显示 `v{appVersion}`，版本来源为应用配置，不手写在场景文本中。
- 必要说明入口只承载隐私、广告、素材许可或测试版本提示等必须信息；没有内容时不显示空入口。
- 首发不在大厅放置公告流、社交链接、营销横幅或重复的版权长文本。

## 10. 导航与数据刷新

```text
启动成功
  → 大厅默认态
      ├─ 设置 → 设置弹窗 → 关闭 → 原大厅位置
      ├─ 合成大西瓜卡 → 加载中 → 游戏
      │                         └─ 返回大厅 → 原滚动位置 + 刷新成绩
      ├─ 敬请期待卡 → 无操作
      ├─ 进入失败 → 错误页 → 重试 → 游戏
      │                    └─ 回大厅 → 目标卡失败态
      └─ 目录失败/空 → 重试 → 大厅正常态或保持可恢复状态
```

- 大厅首次出现时读取可见 Manifest 和对应历史成绩。
- 从游戏返回时只刷新受影响游戏的历史成绩和卡片状态，不重排列表。
- 设置弹窗关闭后保持网格滚动位置和卡片状态。
- 进入请求期间不响应其他卡片；失败恢复后解除锁定。
- 所有导航继续通过 `GameRuntime` 和公共服务完成，卡片不直接加载 Bundle、运行场景或创建 Session。

## 11. 文案基线

| 用途 | 冻结文案 |
| --- | --- |
| 产品标题 | 解压小游戏 |
| 产品副标题 | 随时来一局，轻松一下 |
| 无历史成绩 | 尚无纪录 |
| 历史成绩 | 最高分 {score} |
| 默认进入 | 开始 |
| 进入等待 | 加载中 |
| 禁用 | 暂不可用 |
| 进入失败 | 重试 |
| 空目录 | 暂时没有可玩的游戏 |
| 目录重试 | 重新加载 |
| 占位卡主文案 | 更多游戏 |
| 占位卡辅助文案 | 敬请期待 |
| 设置标题 | 设置 |
| 版本 | v{appVersion} |

第 6 步可以统一标点、字号和语气，但不能改变信息含义或用夸张营销文案制造主推层级。

## 12. 第 5 步验收口径

- 页面只保留产品标题/副标题、设置、双列游戏卡、版本和必要说明。
- 游戏名称、短说明、历史最高分和进入操作全部位于各自标准卡内。
- 所有卡片同尺寸、同结构、同权重，不存在主推位或跨列大卡。
- 排列为行优先双列；敬请期待卡固定追加在真实游戏列表末尾；合并后的奇数尾项固定留在左列，任何卡都不跨列放大。
- 普通用户只有合成大西瓜可玩，第一行右列显示同尺寸、不可交互且不进入 Manifest 的敬请期待卡；`blocks3d` 仅属开发回归且仍由配置决定可见性。
- 大厅、卡片、设置、目录空态、目录失败、封面失败、禁用和进入失败均有明确反馈与恢复操作。
- 大厅数据来源限制为 Manifest、公共存储、应用配置和公共服务，不依赖具体游戏实现或专属 Bundle。
