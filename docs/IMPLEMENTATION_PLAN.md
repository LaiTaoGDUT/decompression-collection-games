## 1. 本计划的范围

本计划是整体产品计划的第一部分，目标是完成：

- 可持续扩展的架构底座。
- 大厅到小游戏再返回大厅的正式运行链路。
- 第一个完整小游戏“合成大西瓜”。
- 第二个极简 3D 小游戏对 2D/3D 架构扩展性的验证。
- 微信分包和真机运行闭环。

本计划暂不包含：

- 大批量生产和上线更多玩法。
- 正式美术资源的规模化制作与完整品牌包装。
- 正式广告位、商业化参数及收入优化。
- 正式数据平台、运营后台和远程内容管理系统。
- 活动、任务、成就、排行榜、分享裂变等运营系统。
- 全量兼容测试、提审、发布和上线后的增长迭代。

以上内容将在本计划通过质量门禁后，拆分为后续独立计划。本阶段建立接口和扩展点，但不会用临时实现破坏未来边界。

## 2. 执行规则

1. 严格按照编号顺序执行，除非先更新本计划并说明原因。
2. 每次只执行一个步骤，不顺带实现下一步。
3. 每一步完成后先验证，再将复选框改为已完成。
4. 验证失败时只修复当前步骤，不通过堆叠后续功能掩盖问题。
5. 修改核心协议、状态机、Bundle 边界或存档结构前，先更新架构文档。
6. 每一步应保持 Cocos Creator 可打开，TypeScript 可编译。
7. 不覆盖与当前步骤无关的用户改动。
8. 在满足功能的前提下选择最简单实现，不为未确认的需求提前增加抽象。
9. 每一步完成后必须 Review 当步改动及其与既有代码的交互，再决定是否勾选完成。
10. Review 至少检查：职责是否单一、依赖方向、重复代码、命名、异常路径、监听/计时器/资源释放、类型安全和测试覆盖。
11. Review 发现的问题在当步修复；涉及架构变更时先更新架构文档，不把已知债务推给后续步骤。
12. 每一步的 Review 结论记录在 [REVIEW_LOG.md](./REVIEW_LOG.md)。

## 4. B：实现最小核心设施

- [x] **第 6 步：实现事件总线**
  - 只实现订阅、取消订阅、发布和清空。
  - 验收：支持多个监听者；取消和清空后不残留引用。

- [x] **第 7 步：实现服务容器**
  - 只实现注册、获取、存在检查和重复注册保护。
  - 验收：缺失服务给出明确错误；业务无需自行创建全局服务。

- [x] **第 8 步：实现状态机本体**
  - 只实现状态转换，不处理场景。
  - 验收：合法转换成功；非法转换被拒绝；转换事件正确；重复转换无副作用。

- [x] **第 9 步：定义平台接口**
  - 只创建 `Platform` 接口，不写平台实现。
  - 验收：业务所需能力均有抽象；接口不暴露 `wx` 类型。

- [x] **第 10 步：实现浏览器平台适配**
  - 只实现安全区、启动参数、可注入设备档位、前后台模拟、振动和分享的安全空实现。
  - 验收：Creator 浏览器预览不依赖微信环境；所有方法均可安全调用。

- [x] **第 11 步：实现微信平台适配**
  - 只封装微信平台基础能力与设备档位，不接广告。
  - 验收：`wx.*` 仅存在于平台层；设备信息被标准化；前后台监听可解除；非微信环境不会误执行。

## 5. C：建立应用启动流程

- [x] **第 12 步：创建 App.scene**
  - 只创建 Canvas、PersistentRoot、ServiceRoot、AudioRoot、LoadingLayer 和 SceneContainer。
  - 验收：场景可预览；层级符合架构基线；不包含大厅或游戏业务。

- [x] **第 13 步：实现 App 启动组件**
  - 只负责持久节点、平台判断、服务容器创建和进入 `booting`。
  - 验收：初始化只执行一次；场景切换后常驻节点仍存在。

- [x] **第 14 步：接入前后台生命周期**
  - 只连接平台 `onHide`、`onShow` 与暂停恢复请求。
  - 验收：不会重复暂停或恢复；非游戏状态不会错误进入 `playing`。

- [x] **第 15 步：增加启动错误处理**
  - 只为启动流程增加统一错误捕获。
  - 验收：失败时进入 `error`；错误包含失败阶段；不出现无响应空白画面。

## 6. D：配置和游戏注册

- [x] **第 16 步：创建本地应用配置**
  - 只创建应用版本、默认语言、设计分辨率、渲染层、3D 画质档位、超时和开发开关。
  - 验收：配置格式可校验；字段缺失时有默认值。

- [x] **第 17 步：实现 ConfigService 本地读取**
  - 暂不获取远程配置。
  - 验收：可以读取本地配置；失败时回退默认值；不暴露原始 JSON。

- [x] **第 18 步：创建 games.json**
  - 只登记一个占位游戏。
  - 验收：符合 `GameManifest`；ID、Bundle、场景和展示信息完整。

- [x] **第 19 步：实现 Manifest 校验器**
  - 只校验必填项、格式、重复 ID、版本、2D/3D 模式、最低设备档位和资源路径。
  - 验收：错误信息包含字段和原因；单条错误不会导致校验器崩溃。

- [x] **第 20 步：实现 GameRegistry**
  - 只实现载入、保存、按 ID 查询和启用列表查询。
  - 验收：重复注册被拒绝；禁用或设备档位不兼容的游戏不能作为可玩游戏返回。

- [x] **第 20.1 步：接入本地游戏目录启动加载**
  - 只让配置层读取 `games.json`，完成校验后将清单载入 `GameRegistry`，并把 Registry 注册到服务容器。
  - 验收：启动后 Registry 包含一个占位游戏；目录读取或校验失败时进入明确的启动错误阶段；不由 Registry 直接读取 Cocos 资源。

## 8. F：建立游戏运行链路

- [x] **第 27 步：实现 GameSession**
  - 只管理 Session ID、游戏 ID、开始时间、状态和结果。
  - 验收：每次进入 ID 不同；不能重复结束；时长计算正确。

- [x] **第 28 步：实现 Asset Bundle 加载**
  - `AssetService` 此时只实现 Bundle 加载。
  - 验收：并发加载合并；失败错误明确；不重复创建加载任务。

- [x] **第 29 步：创建占位游戏 Bundle**
  - 只创建独立 Bundle、场景、入口组件和退出按钮。
  - 验收：不依赖其他游戏；场景可以独立加载。

- [x] **第 30 步：让占位游戏实现 MiniGame**
  - 实现全部生命周期方法，但不增加真实玩法。
  - 验收：调用顺序可观察；错误顺序可以被发现。

- [x] **第 31 步：实现游戏入口定位**
  - `GameLoader` 只负责寻找并校验入口组件。
  - 验收：正常入口可定位；缺失或协议不符时返回明确错误。

- [x] **第 32 步：实现进入游戏流程**
  - 只打通创建 Session、加载 Bundle/场景、初始化和开始。
  - 验收：状态顺序正确；快速点击不创建多个 Session；失败时不进入 `playing`。

- [x] **第 33 步：实现退出游戏流程**
  - 只打通请求退出、暂停、销毁和返回大厅。
  - 验收：游戏不直接切场景；多次退出只执行一次；最终回到 `lobby`。

- [x] **第 34 步：实现 Bundle 释放**
  - 只在退出完成后释放当前游戏 Bundle。
  - 验收：游戏 Bundle 不驻留；公共资源不被误释放；可以再次进入。

- [x] **第 35 步：实现统一加载界面**
  - 只处理显示、隐藏、文案和触摸拦截。
  - 验收：加载期间不能操作大厅；成功或失败都会关闭。

- [x] **第 36 步：实现统一错误页**
  - 只处理游戏加载错误。
  - 验收：可以重试或返回大厅；重试不复用已损坏的 Session。

## 10. H：实现第一个正式小游戏

- [x] **第 44 步：创建合成大西瓜 Bundle**
  - 只创建目录、`game-watermelon` Bundle 和场景。
  - 验收：资源全部位于自身 Bundle；不引用占位游戏。

- [x] **第 45 步：搭建合成大西瓜静态界面**
  - 只搭建投放区、容器边界、失败警戒线、当前分数和下一个水果预览，不做玩法逻辑。
  - 验收：安全区和常见竖屏比例适配正确；玩法区域不被系统 UI 遮挡。

- [x] **第 46 步：定义水果等级和物理配置**
  - 定义水果等级链、尺寸、质量、碰撞参数、分值和对应 Prefab，不生成运行时水果。
  - 验收：等级连续且唯一；每级配置完整；最高级西瓜没有不存在的下一等级。

- [x] **第 47 步：实现水果预览和投放**
  - 只实现下一个水果生成、水平瞄准和松手投放；初始生成池不直接产生高级水果。
  - 验收：投放位置不越过容器边界；一次输入只投放一个水果；上一水果释放前不能重复投放。

- [x] **第 48 步：实现同级水果碰撞合成**
  - 两个相同等级水果碰撞时，在稳定位置合成为下一等级水果。
  - 验收：一次碰撞只合成一次；不同等级不合成；已锁定或已销毁节点不会重复结算。

- [x] **第 49 步：实现分数和合成进度**
  - 根据合成等级累积分数并记录本局最大水果等级。
  - 验收：连锁合成逐次正确计分；重开后分数与最大等级完全重置；最高级西瓜不继续越级合成。

- [x] **第 50 步：实现越线结束和反馈**
  - 水果稳定越过警戒线达到规定时间后结束游戏，生成标准 `GameResult`，并通过公共服务接入投放、碰撞、合成和失败反馈。
  - 验收：短暂越线不会误判；结束只结算一次；公共结果弹窗可展示；音效和振动设置立即生效且无直接平台调用。

- [x] **第 51 步：接入存档和统计**
  - 只记录游玩次数、最高分、历史最大水果等级及开始、结束、重开、退出事件。
  - 验收：中途退出和越线结束可区分；最高分只在刷新时写入；不重复存储或上报。

## 12. 本计划完成条件

只有同时满足以下条件，本计划才能标记为完成：

- 56 个步骤均完成并通过各自验收。
- 架构基线中的首期质量门禁全部通过。
- 第二个小游戏接入没有修改大厅或核心加载流程。
- 极简 3D 游戏完成三档画质与退出资源释放验证。
- 微信真机完成从启动到两个游戏再返回大厅的闭环。
- 已记录测试结果、剩余风险和后续计划输入。

完成结论：以上条件均已满足。第 56 步由用户于 2026-08-09 确认真机验收完成；本阶段建立的架构边界、生命周期、资源隔离和微信运行闭环作为后续阶段的稳定基线。
