## 1. 目标与范围

新增一款面向普通用户大厅的 2D 休闲游戏“滑块拼图”。它模拟传统拼图玩具：把一张正方形图片切成 `n × n` 的方格，保留右下角空位，玩家只能通过滑动相邻方块把图片复原；复原时右下角仍为空位即算完成。

本计划只固化产品规则、架构边界、页面状态、资源清单和验收口径，不在本次变更中创建游戏代码、场景、配置或媒体文件。

### 1.1 已确认决策

| 项目 | 决策 |
| --- | --- |
| 游戏名称 | 滑块拼图 |
| 可见范围 | 加入普通用户大厅，由 Manifest 注册 |
| 棋盘规格 | `3×3`、`4×4`、`5×5`、`6×6` |
| 默认设置 | `4×4` + 随机一张系统预置图 |
| 图片来源 | 随机一张系统预置图，或用户自定义本地图片 |
| 系统预置图 | 6 张原创方形图片；不提供缩略图列表，只提供“随机一张”入口 |
| 自定义图片 | 微信小游戏相册、浏览器文件选择 |
| 微信来源 | 只允许相册，不开放相机 |
| 图片格式 | PNG/JPG，单张不超过 10 MB |
| 运行时处理 | 本地解码、裁切和压缩为不超过 `1024×1024` 的方形纹理 |
| 裁切方式 | 方形裁切编辑器；拖动图片位置，双指缩放；浏览器支持滚轮缩放 |
| 隐私边界 | 图片只在本地处理，不上传服务器，不记录图片路径或图片内容 |
| 打乱规则 | 只通过合法移动生成，保证可解；不采用随机排列后再猜测可解性 |
| 操作方式 | 棋盘只支持滑动；不提供点按方块自动移动 |
| 完成条件 | 所有方块按顺序排列，右下角为空位 |
| 完成反馈 | 完成动效、用时、步数；提供“再来一局”和“回大厅” |
| 记录 | 不增加本地最佳成绩系统 |
| 局内恢复 | 暂停可恢复同一局；前后台切换进入安全暂停，不自动移动 |
| 离开恢复 | 离开游戏或重新进入后重新开始；不做跨会话自定义图片保存 |
| 声音 | 独立音乐、滑动/落子/完成音效和振动反馈 |
| 视觉主题 | PZ1“复古木质拼图玩具”，与大厅、猫咪、2048、棋类视觉完全隔离 |

### 1.2 “再来一局”快捷路径

结算页点击“再来一局”时，先进入滑块拼图开始页，而不是直接开局。开始页显示醒目的“继续上一局的拼图”快捷选项，并保留“重新选择图片/难度”入口。

“继续上一局的拼图”只复用上一局的：

- 图片来源及图片内容（预置图或已载入的本地图片）；
- 方形裁切位置、缩放比例和最终方形纹理；
- 方块数量，即 `n × n`。

点击后重新生成一份保证可解的打乱棋盘，开始一局新拼图；它不是恢复已经完成的棋盘，也不是恢复上一次的步数和计时。

快捷项只在“本次运行中由拼图结算页点击再来一局”到达开始页时显示。以下情况不显示：

- 首次进入游戏；
- 从大厅新进入游戏；
- 已经离开游戏后再次进入；
- 应用重启或运行时被销毁后重新进入。

玩家改选图片或方块数量时，使用普通的“开始拼图”路径，不影响快捷项的语义。离开大厅时清理内存中的上一局图片引用，并释放临时 URL/平台临时资源。

## 2. 用户路径与页面状态

```text
大厅
  → 加载 game-sliding-puzzle
  → 滑块拼图开始页
      ├─ 选择 3×3～6×6
      ├─ 随机一张预置图
      ├─ 选择本地图片
      │    → 图片选择等待/失败
      │    → 方形裁切编辑器
      ├─ 结算页再来一局时显示“继续上一局的拼图”
      └─ 开始拼图
           → 游戏中
               ↔ 暂停
               ↔ 参考图缩略图/放大预览
               → 拼图完成
                   ├─ 再来一局 → 开始页 + 快捷继续项
                   └─ 回大厅
```

### 2.1 开始页

- 默认选中 `4×4` 和“随机预置图”。
- 显示当前图片的小预览；点击预览可打开大图查看，但不改变棋盘。
- 提供“随机一张预置图”和“从相册选择”两个图片来源入口。
- 选择自定义图片后必须先完成裁切，裁切成功后才允许开始。
- `3×3` 到 `6×6` 使用互斥、清晰的方块数量选择器；不引入未确认的额外难度名称。
- 从结算页再来一局进入时，优先展示“继续上一局的拼图”卡片，并同时展示普通重新选择入口。

### 2.2 裁切编辑器

- 中央固定方形裁切框，图片在框内移动和缩放。
- 拖动改变图片偏移；双指捏合改变缩放；浏览器滚轮改变缩放。
- 图片始终覆盖裁切框，禁止产生透明边或拉伸变形。
- 取消返回开始页并保留上一次有效图片；确认后生成本地方形纹理。
- 解码失败、格式不支持、超过 10 MB 或压缩失败时保留在编辑器/开始页，显示原因和重试入口。

### 2.3 游戏中

- 棋盘上方显示裁切图片缩略图、当前用时、步数和暂停入口。
- 缩略图可点开放大参考图；参考图层是阻断式覆盖层，关闭后回到同一局。
- 单次手势只处理一个方向；动画期间合并或拒绝重复输入，不产生多步。
- 只有能沿手势方向滑入空位的相邻方块才移动；无效手势不计步。
- 顶部胶囊和底部安全区由平台布局信息避让，棋盘在矮屏上等比缩小而不裁切。

### 2.4 暂停与完成

- 暂停时冻结棋盘输入、计时和动效；继续后恢复同一棋盘、步数和计时。
- 完成后锁定输入，只播放一次完成动效和完成音效。
- 结果展示用时、步数、棋盘规格和图片来源类型；不展示或记录本地图片路径。
- 结果页“再来一局”进入开始页；“回大厅”释放会话、图片纹理、临时 URL 和游戏 Bundle。

## 3. 规则模型

### 3.1 棋盘表示

棋盘使用一维数组表示，长度为 `n²`：

- `0` 表示空位；
- `1` 到 `n²-1` 表示图片方块的稳定编号；
- 完成状态固定为 `[1, 2, …, n²-1, 0]`；
- 空位在完成状态和初始状态都位于右下角；游戏过程中空位会随移动改变位置。

方块的视觉内容由同一张方形纹理按 `n × n` 网格采样，不为每个方块生成独立图片文件。

### 3.2 合法移动

空位每次只能与上下左右相邻的一个方块交换。玩家在棋盘上滑动时，只有位于空位反方向、且可沿手势方向滑入空位的方块响应；斜向、短距离、无相邻方块或被暂停/完成状态拦截的手势均不产生移动。

每次有效交换：

1. 更新模型数组；
2. 步数加一；
3. 触发方块移动反馈和轻振动；
4. 检查是否回到完成数组；
5. 完成时冻结后续输入并进入结果态。

### 3.3 保证可解的打乱

- 从完成数组出发执行合法随机移动，确保任何生成的棋盘都能通过反向合法移动复原。
- 随机打乱必须避开立即反向的上一步，避免无效来回和过短开局。
- 默认打乱步数配置：`3×3: 40`、`4×4: 80`、`5×5: 160`、`6×6: 280`；最终可调参数放入游戏配置。
- 生成结果不得与完成状态相同；若随机结果仍完成，重新生成。
- 固定随机种子接口仅用于测试和问题复现，正式游戏使用平台安全的伪随机源即可。

### 3.4 计时与结果

- 计时从点击“开始拼图”并完成棋盘初始化后开始。
- 暂停、参考图放大、前后台安全暂停和加载遮罩期间不计时。
- 步数只统计有效方块移动，不统计无效手势、暂停、重新打开参考图和重新生成棋盘。
- `GameResult.extra` 只包含 `boardSize`、`moves`、`puzzleDurationMs`、`imageSource` 和结束原因等非敏感字段。

## 4. 平台与隐私边界

游戏业务只调用平台抽象，不出现 `wx.*`、浏览器文件输入或对象 URL 的直接实现。

计划新增平台能力：

```ts
export interface LocalImageSelection {
    readonly uri: string;
    readonly mimeType?: string;
    readonly sizeBytes?: number;
    readonly release: () => void;
}

export interface Platform {
    pickLocalImage(): Promise<LocalImageSelection | null>;
}
```

实现约束：

- `WebPlatform` 使用隐藏的 `<input type="file" accept="image/png,image/jpeg">`，取消选择返回 `null`；成功读取后创建的 Object URL 必须在 `release()` 或游戏销毁时释放。
- `WeChatPlatform` 首选 `wx.chooseMedia({ mediaType: ['image'], sourceType: ['album'] })`；对低版本基础库提供 `wx.chooseImage` 兼容回退；不传相机来源。
- 选择器只返回本地临时引用和元信息，不提供上传方法，不把图片字节交给统计、广告或远程配置服务。
- MIME、扩展名和大小在平台返回后再次校验；超过 10 MB、非 PNG/JPG 或解码失败必须可重试且不污染上一张有效图片。
- 图片解码、裁切、缩放、压缩和棋盘采样全部在客户端完成；结果事件不记录原始文件名、临时路径、Object URL 或图片哈希。
- 游戏退出、重新选择、应用销毁和 Bundle 释放前都必须释放纹理、解码缓存、临时 URL 和平台临时资源引用。

### 5.3 状态与生命周期

游戏内部状态建议固定为：

```text
setup
  → picking-image
  → crop-editing
  → starting
  → playing
  → paused
  → reference-preview
  → completed
  → disposed
```

`picking-image`、`crop-editing`、`reference-preview` 和 `completed` 都属于当前游戏 Bundle 内的页面/覆盖层状态，不新增全局 `AppStateMachine` 状态。进入、重开、退出和 Bundle 释放仍通过 `MiniGameContext` 与公共运行层完成。

重开语义：结算页“再来一局”先回到 `setup`；在用户点击快捷继续或普通开始后，创建新的 `GameSession`/`sessionId`，再进入 `playing`。如果局内重置失败，按架构约定回退到完整退出和重新加载流程。

## 6. 视觉、动效与声音交付

- 视觉方向冻结为 PZ1“复古木质拼图玩具”，具体令牌见 [SLIDING_PUZZLE_VISUAL_SPEC.md](./SLIDING_PUZZLE_VISUAL_SPEC.md)。
- 6 张预置图必须是项目原创、方形构图、缩小后仍可辨识的图片；选择器只显示“随机一张”，不建立缩略图列表。
- 木质棋盘、纸质/木质方块边缘、空位阴影、按钮、暂停层、完成层和图标均由滑块拼图独立设计；不能把大厅卡片、W1 纸雕 UI、T48 霓虹块或棋类木雕直接改色复用。
- 图片类素材在生成前按 `image-prompt` skill 输出可复制提示词，生成后记录工具、提示词、日期、原始输出、后处理、许可和最终 Bundle；未完成记录的素材只能保持“计划中”。
- 音频类素材在制作前按 `audio-prompt` skill 输出每条音乐/音效的独立提示词，人工生成和验收后才可导入；不运行音频生成脚本，不把预览文件当候选素材。
- 预置图、封面、图标、木质纹理、BGM、按钮音、滑动音、落子音、完成音和振动映射都必须进入 [ASSET_LEDGER.md](./ASSET_LEDGER.md)。

## 8. 验收矩阵

### 8.1 规则模型

- 每个规格都能从完成数组出发通过合法移动生成。
- 所有有效移动只交换空位和一个正交相邻方块；无效移动不改变数组、步数或音效计数。
- 初始棋盘不为完成态，且在 3×3、4×4、5×5、6×6 上都能复原。
- 完成只在 `[1…n²-1,0]` 成立时触发一次；完成后不能继续移动。
- 暂停、参考图、重开和回大厅不会重复结算或泄漏计时器。

### 8.2 图片与隐私

- Web 可选择 PNG/JPG、取消、重复选择和错误文件；微信只出现相册入口。
- 超过 10 MB、不可解码或不支持格式有明确错误，不覆盖上一张有效图片。
- 拖动、双指缩放和滚轮缩放都能稳定完成方形裁切；图片不拉伸、不露透明边。
- 自定义图片从选择到棋盘采样不发生网络请求；日志、统计和结果不包含路径、文件名或图片内容。
- 离开、重新选择和销毁后，纹理、Object URL、临时文件引用和监听均释放。

### 8.3 快捷继续

- 首次进入和大厅新进入没有快捷继续项。
- 结算页点击“再来一局”进入开始页并显示快捷项。
- 快捷项复用上一局图片、裁切和规格，但产生新的合法打乱、步数为 0、计时重新开始。
- 直接点击“重新选择图片/难度”仍可更换图片和方块数量。
- 回大厅、重新加载或应用重启后不显示上一局自定义图片的快捷项。

### 8.4 架构与发布

- 大厅只依赖 Manifest；游戏代码不直接调用 `wx.*`，Bundle 之间无视觉资源交叉引用。
- 场景 Canvas 的 `_cameraComponent` 能解析为有效 `cc.Camera`，并覆盖窄屏、高屏、顶部胶囊和底部安全区。
- `dispose()` 后无计时器、事件、平台回调、音频实例、节点、纹理、临时 URL 或 Bundle 引用残留。
- TypeScript 编译、`git diff --check`、`npm run verify:game-bundles` 和 `npm run verify:wechat-package-size` 均通过。

## 9. 兼容、回滚与禁止事项

- 本游戏不新增持久化活动局或自定义图片存档，因此没有根存档迁移；同运行时快捷项只存在内存。
- `Platform` 接口扩展需要 Web/WeChat 两个实现同时落地；任一平台未实现时不得把自定义图片入口伪装成可用。
- 如果平台选图能力暂时不可用，开发预览可以保留预置图路径用于规则开发，但候选版本不能宣称已完成自定义图片能力。
- 不能通过随机排列后检测逆序数来“碰运气”保证可解，也不能提供完成态右下角方块图片。
- 不能把本地图片上传到服务器、远程配置、广告或统计服务；不能把用户图片写入跨会话存档。
- 不能通过复制其他游戏的按钮、面板、图标、棋盘、音色或完成特效来缩短制作时间。

若实现需要改变全局状态、存档语义、Bundle 边界或平台接口，必须先更新 `ARCHITECTURE.md`、本文件和 `REVIEW_LOG.md`，记录原因、兼容影响、迁移与回滚，再修改代码。
