# 第二阶段范围与用户路径基线

> 状态：已冻结（2026-08-12 增补 2048）
>
> 生效日期：2026-08-09
>
> 对应计划：[CONTENT_PRODUCTION_PLAN.md](./CONTENT_PRODUCTION_PLAN.md) 第 1 步

## 1. 版本目标

第二阶段交付一个可供真实用户试玩的微信小游戏候选版本。普通用户从冷启动开始，可以在大厅进入“合成大胖橘”或“霓光 2048”并直接开始游玩；两款游戏都必须具备暂停、结算、重开和返回大厅的完整闭环。

首发可玩内容包含“合成大胖橘”和“霓光 2048”，游戏列表末尾追加一张不可交互的“更多游戏，敬请期待”系统占位卡。`blocks3d` 仅作为架构和 3D 能力的开发回归样例保留，不属于本阶段的产品需求、UI、美术、玩法调优、广告或用户试玩范围。

## 2. 普通用户主路径

```text
微信冷启动
  → 启动初始化
  → 大厅
  → 选择“合成大胖橘”或“霓光 2048”标准游戏卡
  → 游戏资源加载
  ├─ 合成大胖橘游戏中
  │   ↔ 暂停 → 继续游戏
  │   → 越线失败 → 单局一次续玩选择 → 结算
  └─ 霓光 2048 游戏中
      ↔ 暂停 → 继续游戏
      → 合并数字 → 达成 2048 后继续或结算 / 无可用移动后结算
  → 再来一局或回大厅
```

首次和后续进入使用同一条直接开局路径。资源已缓存时允许缩短加载过程，但不得改变路径中的状态边界。

## 3. 必须成立的返回与恢复路径

| 所在状态 | 用户可执行操作 | 必须到达的结果 |
| --- | --- | --- |
| 大厅 | 进入任一正式游戏 | 加载成功后直接进入所选游戏；失败时留在可操作的大厅错误态 |
| 游戏中 | 暂停 | 进入暂停态并冻结玩法输入与结算 |
| 暂停 | 继续 | 恢复同一局游戏 |
| 暂停 | 重开 | 开始一局新的合成大西瓜 |
| 暂停 | 回大厅 | 释放本局会话并回到可操作大厅 |
| 失败待续玩 | 观看、跳过或放弃 | 成功观看后恢复同一局；其余结果进入结算 |
| 结算 | 再来一局 | 开始新一局，不创建重复会话 |
| 结算 | 回大厅 | 释放本局会话并回到可操作大厅 |
| 2048 达成目标 | 继续挑战或完成本局 | 继续时保留棋盘与分数且不重复弹出；完成时进入可重开、可回大厅的结算层 |
| 2048 无可用移动 | 再来一局或回大厅 | 保存最高分后进入新局或释放会话返回大厅，不恢复已锁死棋盘 |
| 任一广告等待态 | 广告失败、超时或不可用 | 保留结算、重开或回大厅能力，不形成死路 |
| 前后台切换 | 回到前台 | 回到安全暂停态或原可操作状态，不自动产生投放、奖励或重复结算 |

页面和交互的完整状态枚举由第 2 步建立；本文件只冻结用户路径及每条路径必须可返回、可恢复的产品约束。

## 4. 首发可见内容边界

### 4.1 普通用户可见

- 大厅品牌区、设置入口、版本或必要说明。
- 固定双列网格中的“合成大胖橘”和“霓光 2048”标准游戏卡。
- 紧随真实游戏列表的“更多游戏，敬请期待”系统占位卡；与标准卡同尺寸，但不包含游戏 ID 且不可点击。
- 合成大胖橘的游戏 HUD、暂停、续玩、结算和错误反馈。
- 霓光 2048 的棋盘、滑动/键盘输入、撤销、暂停、达成目标、无步可走、结算、独立动效与声音反馈。
- 与本阶段核心路径相关的音效、振动、动效和广告反馈。

### 4.2 仅开发回归可见

- `blocks3d` 游戏及其现有独立 Bundle、Manifest 记录和回归入口。
- 架构诊断、Mock 控制、日志和调试入口。

开发回归内容必须由开发配置或调试入口显式开启，候选构建和普通用户大厅不得展示。实际目录配置切换在第 11 步实施，本步骤不提前修改运行时配置。

### 4.3 明确不在本阶段

- `blocks3d` 的产品化、视觉升级、玩法扩展或商业化。
- 第 3 款及后续正式小游戏。
- 登录、账号、云存档、排行榜、社交分享、活动、任务、成就和运营后台。
- 正式提审、灰度发布和全量上线。

## 5. 冻结的产品决策

- 首发平台为微信小游戏，单手竖屏，设计基准为 750 × 1334。
- 普通用户大厅有“合成大胖橘”和“霓光 2048”两款可玩内容；两张标准卡占据第一行左右列，“更多游戏，敬请期待”系统占位卡位于第二行左列，所有卡片均不跨列放大。
- 大厅通过 Manifest 或配置决定展示内容，不硬编码具体游戏 ID。
- 首次和后续进入均直接开始游戏，不显示新手引导弹层、不执行分步教学，也不保存引导完成状态。
- 首局可理解性由清晰 HUD、瞄准与投放反馈、合成反馈和失败提示承担，不以阻断式教学实现。
- 每局最多提供一次激励视频续玩；只有完整观看才发放续玩结果。
- 广告失败、跳过、超时或不可用不得阻断结算、重开或返回大厅。
- 首局不强制展示插屏；插屏只允许出现在安全的自然局末或返回大厅时点。
- 游戏不直接调用 `wx.*`，继续通过 `MiniGameContext` 与公共服务完成平台能力请求。
- 霓光 2048 在正式微信广告接入前完成；它使用独立 Bundle、独立深色霓光视觉和电子音色，不复用猫咪游戏的纸片猫屋皮肤或音频文件。

## 6. 验收口径

第 1 步在以下条件同时满足时通过：

- 主路径明确覆盖两款正式游戏的“启动 → 大厅 → 游戏 → 暂停/继续 → 结算 → 重开/回大厅”；合成大胖橘额外覆盖失败续玩，霓光 2048 额外覆盖达成目标与无步可走。
- 每个可能阻断主路径的加载、广告和前后台异常都有可恢复结果。
- 普通用户首发内容与开发回归内容边界明确。
- `blocks3d` 被明确排除在产品需求和美术制作范围之外，但保留架构回归能力。
- 后续页面清单、玩法规格、UI、美术、广告和测试步骤均可引用本基线，不需要重新解释首发范围。

## 7. 变更控制

新增首发游戏、扩大 `blocks3d` 范围、引入账号或在线系统、改变广告类型或修改主路径，都视为范围变更。变更前必须先更新本文件和 `CONTENT_PRODUCTION_PLAN.md`，在 `REVIEW_LOG.md` 记录原因、影响、迁移与回滚方式，再进入实施。
