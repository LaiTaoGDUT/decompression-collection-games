# 《桌面大清理》全 3D 物品升级基线

## 1. 不变的玩法契约

- 每局仍生成 54 个完整三件组，共 162 件；幸运徽章仅三件，七格槽位、180 秒、三消、道具、广告继续、存档和结算规则保持不变。
- 同组三件分散到不同出生波次。第三件必须先完整飞入槽位并稳定至少一帧，再执行 240ms 汇聚、烟雾遮盖和模型提交。
- 拾取 200ms、槽位压缩 140ms；清除工具使用 55ms 错峰和 280ms 抬升/缩小/淡出。磁吸、继续、重排、动画看门狗和 operation generation 防重时序保持不变。
- 存档使用独立的 `catch-3d` 命名空间和 `dataVersion: 1`，不保存中途局面，不迁移或覆盖原 `catch` 用户数据。

## 2. 3D 资产基线

- `art_sources/桌面大清理/3d/desktop-cleanup-items-v1.blend` 是 20 类原创低模的可编辑 Blender 源文件；运行时使用 `assets/games/catch-3d/models/desktop-cleanup-items-v1.glb`。
- 每类根节点稳定命名为 `ITEM_<type>`，子 Mesh 命名为 `MESH_<type>`；统一米制、变换已应用、枢轴置于近似质心。
- 全目录共享软陶材质和粗糙度贴图，通过顶点色保留各物品主色与可识别细节。
- 每类包含 1–3 个 `COLLIDER_<type>_<index>_<shape>` 代理，运行时配置位于 `desktop-cleanup-item-colliders-v1.json`；只允许 Box、Sphere、Capsule，动态物品禁止 MeshCollider。
- 联系表、Blender/脚本版本和原创来源记录位于 `art_sources/桌面大清理/3d/`。旧 2D 图集只作为造型参考，不再进入运行时资源加载。

## 3. 世界层与 UI 层

- `WorldCamera` 使用正交 3/4 视角，渲染胡桃木背景、奶油色桌板、桌面物品和带正式纹理的 3D 槽体底板；Canvas/UI Camera 继续渲染七格槽位锚点、HUD、道具卡和弹窗。
- 奶油色桌板保持原 1:1 方形外观、配色和屏幕占位，可用带原纹理的水平平面实现。四周只设置略收于可视边缘的隐藏静态墙，不出现锅、盘、锅沿或可见围栏。
- WorldCamera、UI Camera、Canvas 和 Layer 通过场景引用注入，不在业务代码中写死 Layer ID。
- 现有 Fit Width 与安全区布局仍是唯一 UI 坐标基线；通过 WorldCamera 射线和桌面平面求交，把桌板与七格中心的设计坐标投影为 3D 锚点。

## 4. 物理世界

- `DesktopCleanupPhysicsWorld` 是空间状态唯一真相；逻辑模型不保存平面坐标、伪高度、线速度、角速度、显示层或露出权重。
- 物品从奶油色桌板下方的隐藏出生口连续冒出，短促升到桌面并同步放大；每批睡眠或达到安全超时后再投下一批，全部稳定后才开放输入和倒计时。
- 穿透桌板、越界或速度异常的物品回收到桌板内安全高度重新投放。重排工具暂停倒计时，并把剩余物品重新加入出生队列。
- 加速度计保持慢速基线滤波、触发阈值、280ms 累计窗口和 240ms 冷却；每次有效动作只产生一个横向加向上的离散冲量，桌板本身不做可见倾斜或位移。
- 低/中/高设备同时唤醒上限为 32/64/96。每次冲量优先选择最高、最外露且接近冲量方向的物品；深层睡眠物品保留静态接触，稳定后重新休眠。
- 暂停、规则页、广告、后台和退出冻结刚体并保存速度，恢复时只恢复原先活跃的刚体；销毁时释放物理回调、临时材质、Mesh/Prefab 引用和 GPU 资源。

## 5. 拾取与表现事务

- 输入使用 `WorldCamera.screenPointToRay()` 和 3D 物理最近命中。上层实体遮挡处命中上层，通过真实间隙可命中下层；阴影、透明区域和完全被挡住的实体不能截获点击。
- 按下和移动只更新候选，抬起时必须重新射线检测。候选使用临时材质实例柔和高亮，取消、销毁或重建时立即恢复并释放。
- 拾取后关闭刚体碰撞，同一个 3D 节点在 200ms 内飞到实际槽位 3D 锚点，之后仍以同一模型显示在七格正式槽体上方。
- 合成、磁吸、清除、继续和重排继续复用现有事务 token、提前释放、看门狗与提交顺序；任何快速连点都不得超过七格或创建重复结算。

## 6. 配置、兼容与回滚

- `configs/gameplay.json` 使用 schema v2，配置分批出生、睡眠、摩擦、反弹、回收阈值、颠锅冲量和分档唤醒参数。
- 解析器继续接受 schema v1；旧配置只保留共同玩法字段，空间参数统一回退到 v2 默认值。
- `catch-3d` Manifest 使用独立版本，`renderMode` 为 `3d`，`minimumDeviceTier` 保持 `low`；本轮不设置 `game-catch-3d` 或微信整体包体大小门槛。原 `catch` Manifest 和 Bundle 保持 `renderMode: 2d`。
- 回滚只需隐藏或移除完整 `game-catch-3d` Bundle、Manifest 和 gameplay 配置，不能混用 2D 视图与 3D 逻辑；原 `catch` 用户存档无需迁移、回滚或清空。

## 7. 验收门槛

- Blender/GLB：20 类齐全、名称唯一、变换和枢轴合规、单共享材质/贴图、每类 1–3 个基础碰撞代理、无相机/灯光/动画残留。
- 模型：162 件、所有数量可被三整除、幸运徽章三件、七格容量、三消、工具、广告、胜负和旧存档读取全部回归。
- 物理：分批出生、睡眠、32/64/96 上限、颠锅方向和单次触发、越界回收、暂停恢复、重排和销毁释放全部覆盖。
- 交互：奶油色方形桌板不出现可见围栏；物品真实碰撞、翻滚和堆叠；射线只拾取可见实体；入槽后仍为同一 3D 模型；所有既有动画顺序不变。
- 预览：Cocos 刷新资源后检查窄屏、750×1334、矮屏和高屏，再在低/中/高微信真机验证加速度计与峰值性能。
- 性能：最差颠锅场景低档不低于 30 FPS、中档不低于 45 FPS、高档接近 60 FPS；无持续抖动、穿透、刚体爆炸或退出后资源残留。
- 最终门槛：TypeScript 检查、`git diff --check`、Bundle 边界、Canvas/WorldCamera 绑定和微信浏览器构建验证全部通过。
