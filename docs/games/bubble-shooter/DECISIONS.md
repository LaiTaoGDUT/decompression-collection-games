| 曾讨论方案 | 最终决定 |
| --- | --- |
| 从软糖/深海/玩具中选一种整游戏风格 | 四区域各自风格，另含魔幻区域 |
| 固定区域顺序或完全独立随机 | 随机起点，四区域每轮不重复，跨轮不连同一区域 |
| 普通按时间下降、固定发射次数或连续失败才补行 | 累计未消除次数补行 |

| 小布丁王 / 放大后把棋盘大幅下推 | 宽体大脸双拳，收紧高度保留玩法空间 |
| 发射器固定与旋转部分合成一张图 | 固定底座与可旋转炮台分层；当前球槽随炮台运动但球体纹样保持正立，下一球与交换图标独立 |
| 布丁王拳头使用明显三拳节/手套造型 | 使用接近确认图的近球形圆拳，只保留极弱的拳节暗示；左右拳按共同光源分别绘制 |

## 2. 待细化事项：不能当作已经冻结

### 玩法数值与边界

- 正式名称、gameId、单局分数、结算统计、排行榜、永久成长是否存在。
- 棋盘精确行数、初始高度、危险线按球边缘还是格位判定、最大发射角与反弹次数、触控取消操作。
- 进度计算权重、需求量、清空棋盘补充规则；普通补行阈值、Boss 行动间隔和耐久/伤害。
- 道具在普通阶段的“有效消除”与补行计数细节，炸弹无目标等异常发射；免费刷新入口和替换颜色算法。
- 万能球多色择优规则、无可匹配颜色情况；炸弹半径；“清底两行”是最低占用行还是固定棋盘底行、稀疏布局范围，必须结合预览确认。
- 全部同色在轨道/变色后相连但不自动消除时，后续发射触发匹配的精确条件。
- Boss 补行和技能合并行动中，目标已消除、被移动或本次补行触线等顺序与预告一致性。
- 轨道到点、变色到点、普通补行、进度满、触线同时发生的统一结算优先级。已有顺序草案不能替代完整边界设计。
- 轨道与行偏移/边界的准确坐标算法，满轨道仍反向的预告反馈。
- 章鱼抓取上限达到后的动作、锚点数量和合法布局；防止长期不可解。
- 普通独立区域机制计数在复活后如何复位；广告恢复时状态锁、后台、重复点击处理。
- 无限难度上限/增长曲线、单次越过多个进度阈值如何处理。

### 页面与体验

- 开始入口、暂停/设置、三选一道具奖励、场景过渡、复活/广告失败/结算等页面的功能与效果图。
- 退出/后台是否存档续局、重开、跨启动恢复、音效/音乐/震动开关。
- Boss 登场预告、首次新机制/图形计数教学；不把建议的一次性提示文字视为已冻结文案。
- 深海、玩具、魔幻完整美术；四区域声音；真实字体与色板值。

### 技术与制作

- 云端加高背景 v2 已获用户确认；场景分层、四色泡泡、糖霜和发射器底座已有原图候选。独立物件仍是 RGB 棋盘格背景，须统一做透明、裁切、枢轴和边缘校准；继续生成时检查状态可读性。进度见 ASSET_PROGRESS.md。
- 补齐普通/Boss 统一坐标、皇冠完整、真实胶囊映射、常见长短屏/像素密度验证。
- 游戏 Scene/Bundle/微信分包和区域资源管理方式、Manifest 接入、暂停广告状态机、释放流程。
- 稳定棋盘逻辑、供球、掉落、多事件结算应设计有意义的测试；当前设计文档不代表已实现。

1. 读取本目录及根 AGENTS，按用户当次要求继续；已确认项不再循环询问。
