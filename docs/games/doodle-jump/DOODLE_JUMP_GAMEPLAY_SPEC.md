# 《纸片跳跃》完整玩法规格

## 0. 文档信息

- 状态：待开发
- 目标平台：微信小游戏；浏览器预览仅作为测试者可选的键盘回退环境，不列入开发侧验收流程
- 设计基准：竖屏 750 × 1334，运行时以 Cocos Fit Width 适配
- 核心玩法：自动连续弹跳、重力感应横向移动、单击单发或长按连发、无限向上攀登
- 主题：纸片跃层·平面涂鸦
- 明确排除：触摸拖动移动、虚拟摇杆、立体纸艺/3D 体积表现、霓虹科幻/玻璃金属视觉、三发或五发射上限、局外商城

## 1. 目标与机制范围



### 1.1 一局游戏的核心体验

玩家控制一个自动弹跳的角色，在持续向上滚动的平台区中左右移动，落到平台上再次弹起；玩家不能主动跳跃，也不能通过拖拽角色移动。手机的左右倾斜决定横向运动；射击冷却结束时，在游戏区点击会立即向手指方向发射一发纸飞机，按住不抬手则继续按固定间隔向最新手指方向连发。

玩家需要同时处理四类空间信息：

1. 下一块可落平台的位置。
2. 怪物的头部、身体和移动路线。
3. UFO 光束、黑洞、捕兽夹等危险物。
4. 弹簧、蹦床、喷气背包、螺旋桨帽、火箭和护盾等道具。



### 1.2 核心机制


| 类别        | 游戏规则 |
| --------- | -------- |
| 自动跳跃      | 角色落地后自动反弹，不能手动跳跃 |
| 重力感应      | 左右倾斜控制横向移动 |
| 屏幕穿越      | 角色从左边离开后从右边出现，反向同理 |
| 射击        | 点击在冷却结束时单发；长按在首发后按 `200 ms` 全局冷却连发，无玩法层弹药上限 |
| 方向射击      | 子弹朝当前手指所在方向发射，允许 360 度方向 |
| 普通平台      | 稳定承接和反弹 |
| 移动平台      | 以固定路线左右移动 |
| 升降平台      | 以固定路线缓慢上下移动，出现概率随高度增加 |
| 断裂平台      | 第一次踩到后失去承接能力 |
| 消失平台      | 第一次落地后短暂保留，再消失 |
| 变位平台      | 在多个固定位置之间切换 |
| 爆炸平台      | 第一次落地后反弹并延迟爆炸 |
| 倒刺平台      | 顶面可正常踩踏，下方倒刺接触即失败；第四段背景开始出现 |
| 普通怪物      | 可踩头击杀，可射击击杀 |
| 大型怪物      | 多次射击才能击杀，可踩头击杀 |
| 悬浮怪物      | 在平台上方往复移动，可踩头或射击 |
| UFO       | 光束锁定、吸附、绑架失败 |
| 黑洞        | 多方向吸引，进入核心后失败 |
| 捕兽夹       | 放在平台表面的接触即死危险物 |
| 弹簧        | 下一次平台弹跳获得强力反弹 |
| 蹦床        | 下一次平台弹跳获得更强反弹 |
| 喷气背包      | 短时持续向上飞行，可穿过平台 |
| 螺旋桨帽      | 短时降低重力并提供持续上升 |
| 火箭        | 短时高速向上冲刺，可穿过平台 |
| 护盾        | 持续期内免疫指定危险和怪物碰撞 |
| 复活          | 开关开启时首次失败免费复活，第二次失败广告复活（无广告位直接成功），第三次失败结算 |
| 起步助推        | 作为游戏内道具保留确定规则 |

## 3. 游戏状态和一局流程



### 3.1 状态枚举

游戏运行态只有以下状态：


| 状态                | 含义             | 允许输入                   |
| ----------------- | -------------- | ---------------------- |
| Loading           | 场景和资源加载中       | 无                      |
| SensorCalibrating | 等待重力感应中性值      | 暂停按钮不可用                |
| Playing           | 正常进行           | 重力感应、触摸瞄准、点击单发、长按连发、暂停 |
| Paused            | 游戏暂停           | 继续、重开、退出               |
| Failing           | 失败已锁定，播放失败表现缓冲 | 无玩法输入，仅等待表现收束          |
| ResurrectPrompt   | 第一或第二次失败后的复活确认 | 免费复活/看广告复活、结束本局        |
| Resurrecting      | 正在恢复安全平台和局内系统  | 无玩法输入，仅等待恢复完成          |
| Result            | 已固化本局结果        | 重开、返回大厅                     |
| Error             | 初始化或运行异常       | 重试、返回大厅                |




### 3.2 开始流程

1. 应用状态机锁定进入入口。
2. 创建唯一 GameSession。
3. 加载 game-doodle-jump Bundle 和独立场景。
4. 定位 DoodleJumpGame 入口。
5. 通过 MiniGameContext 注入公共服务。
6. 初始化输入、传感器、对象池、随机种子和初始关卡。
7. 进入 SensorCalibrating。
8. 采集到足够传感器样本后立即进入 Playing；微信环境没有传感器样本则进入 Error，允许重试或返回大厅；浏览器预览若 `Platform` 不支持加速度计，则标记 `sensorDegraded`、启用键盘回退并立即进入 Playing。
9. 不设置 Ready 和二次点击开始步骤；P0 铺满设计宽度，角色使用跳跃图并从 P0 顶面立即向上弹起。



### 3.3 失败流程

1. 仅当当前状态为 Playing 时接受失败事件；重复失败事件直接忽略。
2. 保存本次失败原因、失败时高度、相机位置、当前可见平台和本局临时统计。
3. 进入 Failing，立即停止物理推进、传感器读数应用、子弹生成和敌人更新。
4. 失败后冻结相机和世界，仅驱动角色向下坠落；角色碰撞盒完全离开屏幕底边后，若本游戏复活开关关闭则直接进入 Result；开关开启时，第一次失败进入 ResurrectPrompt 并提供免费复活，第二次失败进入 ResurrectPrompt 并提供广告复活，第三次失败直接进入 Result。下坠表现最多持续 1.2 秒，超时仅作为异常兜底结束表现。
5. 复活确认后进入 Resurrecting，恢复到重新验证过的安全平台；恢复完成后回到 Playing。
6. 拒绝复活、复活开关关闭或第三次失败时进入 Result；结算和存档只能执行一次。
7. 退出时按 pause → 固化结果 → 保存/上报 → dispose → 返回大厅的顺序执行。



### 3.4 暂停规则

- 暂停时角色、平台、怪物、危险物、子弹、道具计时器全部停止。
- 暂停会取消当前攻击指针；恢复时必须重新点击或按住游戏区，点击重新只发射一发，按住才继续连发。
- 传感器监听可以保留，但样本不得推进角色速度。
- 广告暂停、前后台切换和主动暂停都经过应用状态机。
- 快速连续点击暂停、重开、退出不得创建第二个 Session。
- 暂停弹窗使用高于业务弹窗的独立覆盖层；教程、复活、错误或结果弹窗存在时，前后台暂停不得销毁或替换它，关闭暂停后原弹窗保持原状态和按钮能力。



## 4. 重力感应移动



### 4.1 输入原则

重力感应是正式移动输入，触摸拖动不参与角色移动。

手机端只能通过公共 Platform 接口访问传感器，不新增 Promise 返回值：

- `supportsAccelerometer(): boolean`
- `startAccelerometer(): void`
- `stopAccelerometer(): void`
- `onAccelerometerChange(callback): Unsubscribe`

游戏逻辑不得直接调用 wx.*。微信平台实现只存在于 WeChatPlatform；小游戏只消费 `AccelerometerSample` 的 x、y、z 数据。`startAccelerometer()` 本身不承诺异步成功，游戏通过“首个有限数值样本 + 1500 ms 超时”建立本局传感器会话结果；重试必须先 stop、取消旧订阅、清空旧样本，再重新订阅和 start。

### 4.2 传感器校准

Platform 每触发一次 `onAccelerometerChange` 回调并返回一组有限的 `x/y/z` 数值，就记为一个“传感器样本”。样本是手机在那个瞬间三个方向上的倾斜/重力读数，不是图片、录音或用户数据上传；游戏只临时使用横向 `x` 值判断手机中立位置和左右倾斜。

`AccelerometerSample` 的 x、y、z 单位统一为重力加速度 `g`，由 Platform 适配器按竖屏坐标归一化：设备向屏幕右侧倾斜时，`x` 的变化方向必须为正；设备旋转、iOS/Android 轴向差异和 SDK 字段差异不得由游戏逻辑分别处理。样本必须是有限数值，异常样本丢弃且不计入校准数量。

进入 SensorCalibrating 后执行以下固定流程：

1. 屏幕提示玩家保持手机自然竖直。
2. 最少采集 10 个有效样本。
3. 校准窗口默认 600 毫秒，最多等待 1500 毫秒。
4. 取样本 x 的平均值作为 neutralX。
5. 1500 毫秒内收到 1–9 个有效样本时，使用 neutralX = 0 并标记 sensorDegraded；完全没有收到有效样本时进入 Error。
6. 校准结束后立即进入 Playing，不要求玩家再次点击开始。
7. 从暂停恢复时不重新校准，只继续使用当前 neutralX；前后台切换回来若连续 1500 ms 没有新样本，进入 Error 而不是静默使用旧输入。



### 4.3 倾斜映射

定义：

- rawTilt = sample.x - neutralX
- invert = 用户设置中的左右反向开关
- 若 invert 为真，则 rawTilt = -rawTilt
- deadZone = 0.04
- fullTilt = 0.20

归一化规则：

- abs(rawTilt) ≤ 0.04 时，targetInput = 0
- abs(rawTilt) ≥ 0.20 时，targetInput = sign(rawTilt)
- 中间区间线性映射到 -1 至 1
- sensorSensitivity 只允许 0.75、1.00、1.25 三档；归一化结果乘以该值后再限制在 -1 至 1
- 使用时间无关的指数平滑：`alpha = 1 - exp(-dt / 0.08 s)`，禁止使用与帧率绑定的固定 `smoothFactor`。

方向约定：

- targetInput > 0：角色向屏幕右侧加速
- targetInput < 0：角色向屏幕左侧加速
- targetInput = 0：停止主动加速，保留惯性并逐渐减速



### 4.4 传感器异常和开发回退


| 情况             | 正式微信运行             | 浏览器预览                             |
| -------------- | ------------------ | --------------------------------- |
| 支持传感器且收到首个有效样本 | 使用重力感应             | 当前 WebPlatform 不提供原生加速度计，使用键盘开发回退 |
| 不支持、授权失败或超时无样本 | 进入 Error，提供重试和返回大厅 | 进入键盘开发回退并显示开发提示                   |
| 样本长时间不变化       | 保持最近有效输入并逐渐归零      | 显示开发提示                            |
| 模拟器无传感器        | 不将触摸拖动当作替代         | 仅允许键盘左右键回退                        |


浏览器开发回退只允许使用键盘左右键或调试面板；DeviceMotion 不作为公共能力，也不得因为浏览器没有传感器而恢复触摸拖动。

### 4.5 角色横向物理参数

所有物理推进使用固定步长：

- fixedDelta = 1 / 120 秒
- 单帧最多执行 4 个物理子步
- 超出最大子步的时间丢弃，避免切后台后瞬移

角色参数：


| 参数               | 数值                 |
| ---------------- | ------------------ |
| 重力 accelerationY | -1590 units/s²     |
| 普通反弹初速度          | 940 units/s        |
| 重力感应横向加速度        | 2100 units/s²      |
| 无输入减速度           | 1500 units/s²      |
| 最大横向速度           | 420 units/s        |
| 角色碰撞盒            | 52 × 68 units      |
| 角色脚底碰撞点          | 碰撞盒底边中点            |
| 初始位置             | P0 平台中心上方 34 units |
| 初始竖直速度           | 940 units/s        |


横向更新规则：

1. 有输入时，velocityX 向 targetInput × 420 以 2100 units/s² 靠近。
2. 无输入时，velocityX 向 0 以 1500 units/s² 靠近。
3. 角色不因碰到屏幕边缘反弹。
4. 角色不因平台、怪物或危险物改变横向速度，除非进入失败状态或使用道具。



### 4.6 竖直跳跃规则

- 只有平台、弹簧、蹦床和指定飞行道具能改变竖直速度。
- 角色只有在向下运动或竖直速度为 0 时，才允许触发平台落地。
- 向上穿过平台时不碰撞。
- 从平台底部穿过不碰撞。
- 倒刺平台是唯一例外：顶面仍按普通单向平台落地；角色位于平台下方并接触到底部倒刺时立即失败，飞行免疫或护盾生效时不失败。
- 普通平台落地后立即把 velocityY 设置为 940。
- 角色落地的判定窗口为本物理子步内脚底从平台顶面上方移动到平台顶面或以下，且与平台的水平重叠宽度至少达到角色碰撞盒宽度的 25%；角色超过四分之三身体悬在平台外时视为未踩中。
- 一次物理子步只能触发一次弹跳。

单位和高度换算固定如下：

- `WORLD_UNITS_PER_METER = 100`；所有速度、加速度、碰撞盒和平台坐标使用 world units。
- `startWorldY` 是 P0 顶面高度；`heightMeters = floor((maxWorldY - startWorldY) / 100)`，实际实现先对 world units 做非负保护再换算，不能使用屏幕像素。
- 文档中所有 `m` 高度段使用半开区间 `[start, end)`，实现时先乘以 100 转为 world units；`250 m 以上`表示 `[250, +∞)`。
- 普通反弹的理论最高升高为 `940² / (2 × 1590) ≈ 277.9 units`，与此前峰值基本一致但完整升降周期更慢；它比固定主路间距 240 units 高约 37.9 units，配置解析继续限制该余量必须处于 10～80 units，最终可达性仍由第 7.10 节的求解器验证。



## 5. 手指瞄准、点击单发与长按连续射击



### 5.1 输入职责

触摸输入只做两件事：

1. 记录手指当前所在位置作为瞄准方向。
2. 手指按下时尝试发射一发纸飞机；若全局射击冷却已结束则立即发射，即使随后马上抬起，这一发也必须保留。
3. 手指持续按住时，在全局射击冷却结束后继续发射；因此一次点击是单发，一次长按是“首发 + 冷却结束后的连发”。

触摸输入绝不用于：

- 拖动角色；
- 移动平台；
- 改变重力感应中性值；
- 触发跳跃；
- 替代暂停、重开或系统按钮。

攻击物从角色处发射，正式表现为纸飞机，负责击中怪物、单次命中后销毁并在飞行结束后回收。

### 5.2 瞄准坐标

1. 只接收游戏玩法区的第一个有效触点，指针 ID 记为 attackPointerId。
2. UI 安全区、暂停按钮、失败面板和帮助面板上的触摸不进入攻击系统。
3. 将触点位置转换到 Canvas 坐标，再转换到当前游戏世界坐标。
4. aimVector = fingerWorldPosition - playerWorldPosition。
5. aimVector 长度小于 18 units 时，方向固定为正上方。
6. 方向不限制在上半屏，允许向左、右、左上、右上、正上和必要时向下发射。
7. 手指移动时只更新 aimVector，不移动角色。
8. 手指抬起后清除 attackPointerId，停止自动发射。



### 5.3 射击时序

- `fireCooldown = 200 ms`，是整个本局共享的全局射击冷却，不按指针、不按点击/长按模式分别计算。
- 手指按下时尝试发射第一发；冷却结束则立即发射，这同时定义了点击单发行为。
- 若点击发生在冷却期间，该次点击不排队、不补发；抬手前没有再次尝试就不会产生纸飞机。
- 若长按发生在冷却期间，保留当前攻击指针，冷却结束时发射一发，之后每次成功发射后等待 200ms 再发射下一发。
- 发射调度不追赶暂停或卡顿期间错过的次数；恢复后只允许按当前冷却时间发射一发。
- 每次发射都读取最新 aimVector。
- 手指移动后，下一发使用新方向，已经生成的子弹不转向。
- 手指抬起、`TOUCH_CANCEL`、应用隐藏、暂停、失败、进入 Result 或退出时立即停止发射。
- 没有弹药值。
- 没有三发上限。
- 没有五发上限。
- 没有同时存在数量上限。
- 对象池 32 只是内存和复用的软目标，不得转化为玩法上限；超过软目标时必须继续创建或扩容，不能拒绝冷却已经结束的合法射击。200ms 冷却下长按 10 秒约产生 50～51 发，验收必须覆盖连续发射、回收和快速点击场景。



### 5.4 子弹参数


| 参数       | 数值                          |
| -------- | --------------------------- |
| 攻击物名称    | 纸飞机 |
| 子弹生成点    | 角色中心沿 aimVector 前移 34 units |
| 飞行速度     | 920 units/s                 |
| 碰撞形状     | 半径 7 units 的圆               |
| 存活时间     | 1.6 秒                       |
| 重力       | 0                           |
| 是否穿过平台   | 是                           |
| 是否穿过道具   | 是                           |
| 单发命中后    | 命中一个目标后销毁                   |
| 默认对象池软目标 | 32，非玩法限制                    |


子弹可命中普通怪物、大型怪物、悬浮怪物和 UFO 舱体。子弹不能破坏黑洞、捕兽夹、普通平台或道具，也不能通过射击直接改变平台类型。

### 5.5 子弹碰撞优先级

同一物理子步中发生多种碰撞时按以下顺序处理：

1. 角色失败状态检查已锁定，则忽略全部新碰撞。
2. 子弹与怪物命中，扣除怪物生命值并销毁子弹。
3. 子弹与 UFO 舱体命中，触发 UFO 短暂受击停顿并销毁子弹。
4. 子弹与其他不可破坏对象不产生效果。



### 5.6 多指、取消和鼠标

- 多指只保留最早进入游戏区的一个攻击指针。
- 第二个及之后的手指全部忽略，不抢占瞄准权。
- 第一根手指抬起后，如果仍有其他手指按住，也不自动接管；必须重新按下。
- 浏览器鼠标按下等同于一个指针。
- 浏览器按住 Space 是开发回退攻击，方向使用最近一次有效瞄准方向；没有瞄准方向时向正上方发射。

输入生命周期固定如下：

- 触摸起点在暂停、规则、复活、结算等 UI 区域时，归 UI 所有，不会转移到攻击系统。
- 触摸起点在玩法区时，攻击指针由该触摸事务持有；移动到 UI 区域不会把同一指针转交给 UI，必须抬手后重新点击 UI。
- 收到 `TOUCH_END`、`TOUCH_CANCEL`、窗口 hide、暂停请求、失败锁定或 dispose 时，必须清除 `attackPointerId`、连发计时器和当前瞄准点。
- 规则/复活/结算面板打开时，所有已有玩法指针立即取消，面板关闭后必须重新按下才能攻击。



## 6. 屏幕穿越、世界边界和相机



### 6.1 屏幕穿越

设计宽度为 750 units。角色碰撞盒半宽为 26 units，因此角色中心坐标按以下规则处理：

- playerX < -26：playerX += 802
- playerX > 776：playerX -= 802

穿越发生在物理位置更新后、碰撞检测前。穿越不改变 velocityX、velocityY、瞄准方向或当前道具。

### 6.2 只有主角穿屏

可以穿屏的对象只有主角。以下对象不可穿屏：

- 平台；
- 普通、大型、悬浮怪物；
- UFO；
- 黑洞；
- 捕兽夹；
- 道具；
- 子弹。

不可穿屏对象离开活动区域后按生命周期规则回收。

### 6.3 掉落和追踪

- 死亡线就是当前相机可见区域底边；角色碰撞盒顶端完全低于该边界时进入 fall 失败。
- 屏幕底边以下的平台不能再次把角色弹回画面，避免掉落后在屏幕底部循环反弹。
- 相机只向上跟随，不向下回弹。
- 角色超过屏幕纵向目标线时，相机随角色连续向上移动；目标线位于可见高度的 35%，使角色保持在屏幕下半部。
- 角色低于目标线时，相机不追下去；角色继续向下直到落到平台或失败。
- 世界坐标持续增加，不能用循环地图覆盖已经生成的高度。
- 视野上方至少保留 1.5 个角色正常跳跃高度的预生成空间。
- 玩法模型保存 `absoluteWorldY`、`maxAbsoluteWorldY` 和 `cameraAbsoluteY`；Cocos 节点只保存相对当前原点的渲染坐标。
- 当 `cameraAbsoluteY - renderOriginY >= 20000 units` 时执行一次 floating-origin rebasing：所有活动对象和相机的渲染坐标统一减去 20000，绝对坐标、分数、seed 和生成游标不变。
- rebasing 只能发生在物理子步结束、碰撞结算完成之后，并且必须对平台、怪物、危险物、道具、子弹和特效使用同一个偏移量，禁止单个对象单独重置。



### 6.4 安全区

- 游戏背景可以 cover 裁切。
- 背景采用两层独立视差：底层纸张以相机上升量的 12% 向下滚动，上层透明装饰以 28% 向下滚动；两层均慢于角色、平台和世界层。
- 只有底层使用满宽、纵向首尾无缝的重复纸张图片；上层是复用节点池，所有装饰实例必须先在屏幕上边界之外创建，再随视差滚动进入画面，离开屏幕下方后才能回收到顶部；禁止在当前可见区域内突然换图或生成。low/medium/high 分别最多保留 3/4/5 个装饰节点，纵向间距按 seed 在 420–720 units 间随机，显示宽度在 88–150 units 间随机，所有装饰 Alpha 固定为 50%，位置、旋转、素材和间距均由局内种子确定。不得把装饰预先合成整张循环贴图。四段背景必须使用各自独立的主题装饰池：暖纸为文具和彩笔符号，天空为太阳/风筝/彩虹/风线，深云为闪电/雨滴/警戒折线/月风，星空为星座/月亮/行星/彗星；装饰必须与对应底图形成可见的轮廓、明度或局部色彩对比，不能融入底纹看不清。
- 底层背景依次为暖白稿纸、天蓝天空纸、深色云层纸和星空剪贴纸；250m、600m、950m 的主题切换必须插入一张从下方主题到上方主题的纵向过渡图片，禁止直接闪切背景颜色。
- 玩法区域和所有可交互 UI 必须位于顶部微信胶囊下方和底部安全边界内。
- 左右不额外缩减通用玩法宽度。
- Canvas 必须绑定有效 UI Camera，UI Camera 使用正交投影。
- 不读取物理屏幕像素作为游戏世界坐标。

- 平台被消耗、爆炸或离开回收区后，不得重新启用碰撞。
- 平台不受子弹伤害。

### 7.10 程序化生成约束

每次生成新平台时，必须先通过可达性检查，再允许进入场景。可达性检查不是只比较两个中心点，而是模拟角色碰撞盒、横向加速度、最大速度、屏幕穿越和移动平台落点窗口：

- 平台纵向最短间隔固定为 60 units，所有平台顶面高度必须落在以 P0 顶面为原点的 60-unit 格点上；任意两块纵向相邻平台的间距只能是 `n × 60 units`。相邻主路平台固定相隔 `4 × 60 = 240 units`，恢复层和降级路线也不得改变该主路间距。
- 普通反弹在 `fixedDelta = 1 / 120 s` 下的连续理论最大升高约为 277.8 units；固定主路间距保留约 37.8 units 的理论竖直余量，离散积分下的实际余量略小，但必须由同一求解器确认可达。
- 运行配置中的相邻平台中心水平偏移不高于 200 units；最终检查使用角色脚底跨越目标顶面的真实时刻，并要求角色中心进入平台内部的安全落地区，而不是只擦到碰撞盒边缘。
- 求解器从前驱平台顶面上方的真实角色中心开始，模拟无输入、目标方向与反方向的 25%/50%/75%/100% 倾斜，以及中途换向控制包络；不能把角色中心误当作脚底，也不能只用满幅输入误判轻倾可达路线。
- Moving/VerticalMoving 平台按各自独立周期、振幅和相位预测落地时的位置；预测不到安全落点时候选无效。
- 屏幕穿越可以作为横向路径的一部分，但不能让不可穿屏平台依赖“穿屏后的中心距离”绕过碰撞区间检查。
- 视野内至少有一块确定可落平台；连续两块平台都不能只靠飞行道具才能到达。
- 任何平台不得与黑洞核心、捕兽夹、UFO 光束出生点重叠。
- 任何平台不得被生成在屏幕左右边界外；移动/变位平台的全程包围盒也必须在边界内。
- 每个主路线高度只生成一块平台，类型可以是 Normal、Moving 或 Shifting；Normal、Moving、Breakable、Disappearing、Shifting、Exploding 六种类型都可以作为前后两块主路之间的可选插入平台。
- 最高连续难度段必须保留一条不依赖道具且不会因一次性平台消耗而截断的通关路线。

生成器实现契约：

1. 使用 `seed` 派生 `platform/enemy/item/cosmetic` 四条独立伪随机流；每个候选记录 `seed`、`generatorCursor` 和前驱平台 ID，调试构建可以复现整局。
2. 每次先在前一块主路上方固定 240 units 处生成并验证一块 Normal/Moving/Shifting 主路平台；成功后再按 `16% / 36% / 32% / 16%` 的概率尝试放置 `0 / 1 / 2 / 3` 块可选平台。插入位置从 `+60 / +120 / +180 units` 三个格点中随机无重复选择，插入失败时直接放弃该块，不能影响主路。
3. 单个候选最多重试 24 次；失败后先扩大平台宽度、降低高度差或替换为 Normal，再重新求解，不能直接把不可达候选放入场景。
4. 24 次仍失败时，生成“当前前驱平台上方固定 240 units、宽度 175–210 units、无危险附着”的 Normal 兜底平台，并记录 `generator-degraded` 事件。
5. 本游戏不建立自动化批量 seed 测试。开发态必须提供 seed 输入、生成游标显示、单步生成、路线可达性可视化和失败现场导出，并整理覆盖各高度段、平台类型、连续类型约束、24 次重试和安全平台降级的代表性 seed 清单供人工验收；人工验收中发现无路可达、生成器死循环或越界的 seed 必须进入回归样本。
6. 主路间距、水平跨度和平台宽度随高度渐进变化。除每 4 层中的一层和每 10 层的恢复层外，候选必须额外证明“零水平输入无法自动落上去”，避免形成挂机直线上升路线；每 10 层必须插入一块更宽且无插入平台的 Normal 恢复平台。
7. 可选平台不得进行连续值纵向随机或扰动，只能占用固定格点；因此显示出的任意相邻平台间距可以是 60、120、180 或 240 units。可选平台可以提供补救落点，但下一块主路必须在不依赖它们的前提下直接可达。



### 7.11 高度段平台构成


| 高度 | 主路 Moving/Shifting 构成 | 插入数量概率 | 插入类型 |
| --- | --- | --- | --- |
| 0 至 120 m | Moving 随高度增加，主路无 Shifting | 0/1/2/3 块 = 16%/36%/32%/16% | 原六种平台 |
| 120 至 170 m | 同上 | 0/1/2/3 块 = 16%/36%/32%/16% | 升降平台从 4% 开始递增 |
| 170 至 950 m | 主路开始出现 Shifting | 0/1/2/3 块 = 16%/36%/32%/16% | 升降平台逐步增至 18%，其余权重等比缩放 |
| 950 m 以上 | Moving 约 33%，Shifting 约 14% | 0/1/2/3 块 = 16%/36%/32%/16% | 升降平台 18%，倒刺平台 10%，其余权重等比缩放 |


概率只决定插入数量和类型候选，不能绕过最小间距、可达性、反挂机和连续路线约束；连续两块动态主路平台时下一块主路强制 Normal。基础插入类型权重为 Normal 34%、Moving 17%、Breakable 13%、Disappearing 12%、Shifting 13%、Exploding 11%；升降和倒刺按当前高度先取得独立权重，剩余权重再按基础比例分配，每段主路间最多三块。

## 8. 怪物系统



### 8.1 共同规则

怪物是主动危险目标，也是可被玩家攻击的得分目标。所有怪物均遵循：

- 可以被子弹命中；
- 可以从头顶踩踏击杀；
- 从侧面或底部接触角色会导致失败；
- 子弹不能穿过怪物；
- 怪物不受平台子弹或其他怪物伤害；
- 怪物离开相机下方 420 units 后回收；
- 怪物不会因为屏幕左右边缘穿越；
- 怪物不发射普通敌方子弹，危险来自位置、移动和接触；
- 怪物被击杀后播放独立爆散效果，不能立即在同一位置重生。



### 8.2 普通怪物 Small Monster


| 参数    | 数值                 |
| ----- | ------------------ |
| 生命值   | 2                  |
| 碰撞宽高  | 54 × 50 units      |
| 生成高度  | 70 m 起             |
| 锚定对象  | 一块平台或固定空中点         |
| 移动    | 在锚点左右各 42 units 往复 |
| 往返时间  | 2.8 秒              |
| 头部踩踏区 | 顶部 16 units        |
| 子弹击中  | 每发扣 1 点生命          |
| 击杀分   | 50                 |


普通怪物在锚点范围内移动，不穿过平台边界。角色脚底从怪物头顶上方穿越到头顶平面时，直接击杀怪物并将角色竖直速度设置为 940。

### 8.3 大型怪物 Large Monster


| 参数    | 数值                 |

| 生命值   | 4                  |
| 碰撞宽高  | 78 × 70 units      |

| 移动    | 在锚点左右各 28 units 往复 |

大型怪物可被正常踩踏击杀，不要求先射击。大型怪物身体碰撞盒不得因受伤缩小；生命值归零后才关闭碰撞。

### 8.4 悬浮怪物 Hover Monster


| 参数   | 数值              |
| ---- | --------------- |
| 生命值  | 1               |
| 碰撞宽高 | 58 × 48 units   |
| 生成高度 | 150 m 起         |
| 锚点高度 | 平台顶面上方 90 units |
| 水平范围 | 锚点左右各 70 units  |
| 垂直波动 | 18 units        |
| 完整循环 | 3.2 秒           |
| 击杀分  | 75              |


悬浮怪物不是平台的一部分，角色可以从其上方踩踏。若角色从侧面、下方或波动路径中撞到，则失败。悬浮怪物不会被平台承接。

### 8.5 怪物生成规则


怪物从 70m 开始进入长难度曲线。每块合格平台的生成概率由 10% 缓慢线性提高，在 900m 达到 21% 后封顶；同屏上限在 320m 前为 1 个、320–700m 为 2 个、700m 以上为 3 个。连续怪物锚点的最短纵向距离由 720 units 缓慢缩短，在 900m 达到 360 units 后不再缩短。该距离记录最近一次成功生成的锚点，即使怪物被立即击杀或回收，也不能立刻在相邻平台补怪。

| 高度          | 普通   | 大型  | 悬浮  |
| ----------- | ---- | --- | --- |
| 0 至 70 m    | 0%   | 0%  | 0%  |
| 70 至 150 m  | 100% | 0%  | 0%  |
| 150 至 220 m | 70%  | 0%  | 30% |
| 220 至 260 m | 55%  | 15% | 30% |
| 260 至 400 m | 45%  | 25% | 30% |
| 400 m 以上    | 35%  | 35% | 30% |


同一平台最多附着一个地面怪物。Moving 和 Shifting 属于可移动平台，不得生成任何地面或悬浮怪物。悬浮怪物可以占用其他静态平台上方空间，但不得遮挡唯一可落平台的全部宽度。怪物高度区间同样按半开区间解释，生成器先过滤未解锁类型再归一化权重。

怪物只能在屏幕上边界之外生成：锚点平台逻辑顶面必须高于当前可见区顶边至少 24 units，实例创建后随相机滚动自然进入屏幕。平台一旦进入这条上方生成边界，尚未生成的怪物候选立即作废，之后即使屏幕内怪物被击杀也不能使用该平台补怪。活动数量出现空缺时，只能等待后续仍在屏幕外的新平台生成怪物，禁止在当前屏幕内原地补充。

### 8.6 怪物碰撞优先级

同一物理子步同时发生角色踩踏和身体接触时，按以下规则：

1. 先检查角色脚底是否进入怪物头部踩踏区。
2. 若是，怪物死亡，角色反弹，忽略该怪物身体碰撞。
3. 否则检查角色碰撞盒与怪物身体重叠。
4. 有重叠时，飞行类道具、护盾持续期和蹦床跳跃期间忽略致死；其他状态以 monster-contact 失败。

同一子步同时有子弹命中和角色接触时：

1. 子弹先扣生命并销毁；
2. 角色仍有身体重叠时，仍以 monster-contact 失败；
3. 只有角色踩踏条件成立时才优先击杀并保留游戏。



## 9. 危险物系统



### 9.1 危险物共同规则

- 危险物不受子弹破坏。
- 危险物都必须有清晰的预警颜色、碰撞区域和失败原因。
- 危险物生成后不会因为屏幕穿越。
- 敌方危险物从捕兽夹 180m 解锁点开始以每块合格平台 5.5% 的概率生成，至 1000m 线性提高到 15% 后封顶；各危险物按自身解锁高度独立进入候选池，UFO 只从第三个背景场景（600m 云层纸面）开始生成。同屏总上限在 600m 前为 1 个、600m 以上为 2 个，任何高度都不得超过 2 个。
- 连续危险物锚点的最短纵向距离由 960 units 缓慢缩短，至 1000m 达到 540 units 后封顶。最近生成锚点在危险物被触发、清除或回收后仍用于限制后续生成，确保危险段之间始终存在喘息区。
- 护盾持续期内免疫怪物、UFO、黑洞和捕兽夹；仍不能免疫 fall。
- 失败状态一旦锁定，所有危险物只播放表现，不再重复结算。



### 9.2 UFO

UFO 的危险机制是光束锁定、吸附和绑架，不是普通接触伤害。


| 参数     | 数值               |
| ------ | ---------------- |
| 初始解锁   | 600 m（第三个背景场景） |
| 舱体宽度   | 116 units        |
| 光束宽度   | 176 units        |
| 水平移动速度 | 130 units/s      |
| 锁定时间   | 0.5 秒            |
| 吸附加速度  | 460 units/s²     |
| 连续光束时间 | 1.35 秒           |
| 击杀方式   | 不可击杀             |
| 子弹反馈   | 停顿 0.18 秒并取消当前锁定 |
| 击杀/中断分 | 20               |


UFO 行为：

1. UFO 的目标高度取角色上方 160 至 300 units，但实例底边必须仍在当前屏幕顶边和生成边距之外，只能从屏幕外自然进入。
2. UFO 水平追踪角色，但最大移动速度为 130 units/s。
3. 光束覆盖 UFO 下方完整的 176 × 430 units 区域；角色碰撞盒与该区域有重叠时，先显示 0.5 秒锁定预警。
4. 角色在锁定预警期间离开光束宽度，锁定取消。
5. 锁定完成后，角色获得向光束中心的吸附速度。
6. 角色连续处于光束内 1.35 秒，进入 ufo-abduction 失败。
7. 角色离开光束超过 0.1 秒，清除本次吸附计时。
8. 子弹命中 UFO 舱体时，UFO 停顿 0.18 秒并清除锁定和吸附计时，但不能摧毁 UFO。
9. 角色不能踩踏 UFO。
10. 护盾可以在整个持续期内阻止吸附和绑架计时，但 UFO 光束仍可显示；护盾不会因接触 UFO 提前消耗。



### 9.3 黑洞

黑洞的危险机制是从多个方向把角色拉向中心，进入核心区域后失败。


| 参数      | 数值                |
| ------- | ----------------- |
| 初始解锁    | 250 m             |
| 外圈半径    | 250 units         |
| 吸引开始半径  | 250 units         |
| 最大吸引加速度 | 4200 units/s²      |
| 核心半径    | 42 units          |
| 核心失败原因  | black-hole        |
| 子弹效果    | 无                 |
| 护盾效果    | 持续期内免除核心失败并取消外圈吸引 |


黑洞吸引规则：

1. 角色进入外圈后，每个物理子步计算指向黑洞中心的向量。
2. 吸引加速度随距离减小而增强，外圈边缘仍保持约 52% 的最大吸引强度，最高达到 4200 units/s²。
3. 角色离开外圈后吸引立即清除。
4. 角色中心进入核心半径后失败。
5. 黑洞不因角色穿屏而改变位置。
6. 黑洞不能作为平台，也不能被角色踩踏。

| 参数   | 数值            |
| ---- | ------------- |
| 初始解锁 | 180 m         |
| 尺寸   | 54 × 24 units |
| 生成位置 | 平台顶面          |
| 触发方式 | 角色碰撞盒与夹口重叠    |
| 失败原因 | bear-trap     |
| 子弹效果 | 无             |
| 护盾效果 | 持续期内阻止失败且不消耗护盾 |


捕兽夹只占用平台一部分宽度。生成器必须确保同一平台仍保留至少 76 units 的可落宽度。角色从平台下方穿过不会触发捕兽夹；角色落地后脚底或身体碰到夹口才触发。

本游戏只允许使用以下失败原因：

## 10. 道具系统



### 10.1 全局碰撞和道具交互矩阵

同一物理子步内按以下顺序处理，避免飞行道具、踩踏、护盾和危险物出现平台实现各自判定的问题：

1. `Failing`、`ResurrectPrompt`、`Resurrecting`、`Result` 或 `Error` 状态不再结算新的玩法碰撞。
2. 先处理平台落地；只有平台 `collisionEnabled` 且当前道具允许平台碰撞时才执行。Breakable 的踩踏会关闭碰撞且不反弹，其他可落平台先产生一次反弹。
3. 再处理怪物头部踩踏；踩踏成功优先于同一怪物的身体接触，但子弹命中不会取消身体接触失败。
4. 再处理危险事件，优先级固定为 `UFO 光束锁定/绑架 → 黑洞核心 → 捕兽夹 → 怪物身体接触`。Shield 持续期、蹦床跳跃期和三种飞行道具激活期不产生上述危险失败。
5. 最后检查不可抵挡的 `fall`；进入死亡线即失败，不因护盾或飞行道具改变。


| 交互对象                      | Normal/Moving/Disappearing/Shifting | Breakable/Exploding | 怪物                 | UFO/黑洞             | 捕兽夹          |
| ------------------------- | ----------------------------------- | ------------------- | ------------------ | ------------------ | ------------ |
| 普通状态                      | 正常落地/反弹                             | 按平台自身一次性规则          | 可踩踏；身体接触失败         | 按危险物规则             | 接触失败         |
| Jetpack/Rocket            | 穿过，不触发落地                            | 穿过，不触发平台倒计时或爆炸      | 激活期间无敌，不触发接触失败 | 激活期间不锁定、不吸附、不受核心影响 | 激活期间不触发       |
| Head Start                | 穿过，不触发落地                            | 穿过，不触发平台倒计时或爆炸      | 按普通接触规则             | 按危险物规则             | 按普通触发规则       |
| Propeller Hat             | 正常保留平台碰撞                            | 按平台自身规则             | 激活期间无敌，不触发接触失败 | 激活期间不锁定、不吸附、不受核心影响 | 激活期间不触发       |
| Trampoline Jump           | 保留平台碰撞，下次有效落地结束状态                   | 按平台自身规则             | 该次跳跃期间无敌        | 该次跳跃期间不锁定、不吸附、不受核心影响 | 该次跳跃期间不触发      |
| Shield                    | 不改变平台碰撞                             | 不改变平台碰撞             | 持续时间内无敌        | 持续时间内不锁定、不吸附、不受核心影响 | 持续时间内不触发      |


Jetpack、Propeller Hat、Rocket、Shield 持续期间以及 Trampoline 触发后到下一次有效落地前都提供玩法无敌；Head Start 只改变竖直运动及平台碰撞，不提供无敌。所有上述无敌都不能阻止 fall。

### 10.2 道具公共规则

- 道具是漂浮在世界中的可收集物，不作为平台承接面。
- 角色碰撞盒与道具碰撞圆重叠时立即拾取；但 Jetpack、Propeller Hat 或 Rocket 已激活时，三种飞行拾取物都暂时忽略碰撞，不移除、不计数、不刷新或替换当前飞行状态，待飞行结束后才可拾取。
- 子弹穿过道具，不会触发拾取。
- 道具拾取后从场景中移除，不能重复拾取。
- 道具只在仍处于屏幕外的候选平台上方生成，水平位置落在平台可承载宽度内；生成后保持固定世界坐标，不跟随 Moving 或 Shifting 平台移动。
- 道具、怪物与 UFO、黑洞、捕兽夹等敌方危险物共享生成占位：无论哪一类后生成，其碰撞盒都不得与已经存在的另两类对象重叠。
- 每种道具都有固定图标、颜色、音效和 HUD 状态。
- 所有可拾取道具常驻一层暖黄色纸片星芒，按各自 seed 错峰缓慢缩放、轻微旋转和明暗呼吸；Alpha 约为 57%–88%，确保静止画面也能清晰辨认为拾取物，且不能遮住主体轮廓。
- Spring 拾取图使用暖珊瑚红弹簧和低饱和金黄色底座，不再复用 Normal 平台的蓝绿色主色。
- 飞行类道具互斥；护盾独立存在；一次性弹跳道具可处于待触发状态。
- Shield 使用独立透明覆盖 Sprite，运行时跟随玩家视觉根节点，可与基础图或任一飞行道具组合图同时显示，不改变角色碰撞盒。



### 10.3 弹簧 Spring


| 参数      | 数值                 |
| ------- | ------------------ |
| 初始解锁    | 0 m                |
| 出现位置    | 平台上方 20 至 70 units |
| 触发      | 下一次平台落地            |
| 反弹速度    | 1350 units/s       |
| 持续      | 一次性                |
| 与飞行道具关系 | 飞行中拾取，保留到下一次有效落地   |


拾取弹簧后，HUD 显示 springReady。下一次真实落地时先触发弹簧，再清除 springReady。平台上方的弹簧拾取判定必须先于同一物理子步的落地判定，因此下降时拾取并紧接着碰到承载平台，也会在本次落地正确触发。断裂平台不算有效落地，因为断裂平台不产生反弹。

### 10.4 蹦床 Trampoline


| 参数    | 数值                 |
| ----- | ------------------ |
| 初始解锁  | 70 m               |
| 出现位置  | 平台上方 20 至 70 units |
| 触发    | 下一次有效平台落地          |
| 反弹速度  | 1700 units/s       |
| 持续    | 一次性                |
| 与弹簧关系 | 蹦床覆盖弹簧，不叠加         |


如果角色已有 springReady，拾取蹦床后将 springReady 替换为 trampolineReady。蹦床触发后立即清除待触发状态，同时进入 trampolineJump：主角使用跳跃图，在 `bounceVelocity / |gravity|` 的完整上升时间内均匀旋转 720°；到达弹道最高点、竖直速度从上升切换为下降的同一物理步，翻滚刚好结束并显式归零为正面朝向，下降阶段保持正面，不能停留在等价但带浮点误差的 ±720° 旋转。该次跳跃的玩法无敌仍在下一次有效平台落地时结束。悬浮拾取、覆盖弹簧且下一次有效落地触发均为本项目统一规则。

### 10.5 喷气背包 Jetpack


| 参数      | 数值           |

| 持续时间    | 2.4 秒        |

| 平台碰撞    | 飞行期间穿过平台     |
| 与其他飞行道具 | 任一飞行状态激活时不可拾取 |


喷气背包激活后，角色竖直速度固定为 1050 units/s，并在持续时间内每个物理子步保持该速度，总上升高度为 25.2 m。时间结束后恢复普通重力和正常平台碰撞。喷气背包不会自动延长时间。

### 10.6 螺旋桨帽 Propeller Hat


| 参数      | 数值           |

| 初始解锁    | 120 m        |

| 与其他飞行道具 | 任一飞行状态激活时不可拾取 |


螺旋桨帽激活后，角色仍受向下重力，但 velocityY 不得低于 400 units/s；持续时间结束后恢复普通重力。若在激活时角色正在下落，立即将 velocityY 提升到 400。按拾取瞬间的上升速度不同，总上升高度约为 14.4 至 22.85 m；即使紧接蹦床拾取，也必须低于喷气背包的 25.2 m。

### 10.7 火箭 Rocket


| 参数      | 数值           |
| ------- | ------------ |

| 向上速度    | 1650 units/s |

| 与其他飞行道具 | 任一飞行状态激活时不可拾取 |


火箭是高速冲刺，不暂停世界生成。当前总上升高度为 33 m，高于喷气背包的 25.2 m；角色可以在火箭期间穿过平台所在高度，并按第 10.1 节获得持续期间无敌。配置解析必须保证三类飞行高度始终满足 `Rocket > Jetpack > Propeller Hat 最大可能高度`。

### 10.8 飞行道具互斥拾取

- Jetpack、Propeller Hat、Rocket 共用 flightPower 状态。
- 没有飞行道具时拾取任意一种，立即激活。
- 已有任意一种飞行道具时，角色与三种飞行拾取物的碰撞全部忽略；当前能力不替换、不续时，拾取物也不消失。
- 飞行道具结束后回到普通重力和平台碰撞。
- 被 UFO、黑洞或其他危险物影响时，飞行道具不自动取消。
- 飞行道具期间仍可点击单发或长按连发；这是本项目明确保留的控制规则。

### 10.11 复活 Resurrect

Resurrect 是局内失败恢复机制，不是道具，不存在持久库存：


| 参数     | 数值            |
| ------ | ------------- |
| 触发时机   | 第一次或第二次失败后    |
| 第一次复活  | 免费              |
| 第二次复活  | 完整观看激励广告后      |
| 恢复位置   | 从失败画面开始向上找到的安全平台 |
| 恢复竖直速度 | 940 units/s   |
| 复活后护盾  | 3.0 秒         |
| 每局上限   | 2 次           |


`ads.games.doodle-jump.enabled` 是本游戏唯一复活功能开关。开关关闭时第一次失败也不提供复活；开关开启时第一次失败可以免费复活，第二次失败通过 `AdService.showRewarded()` 请求独立广告位 `doodle-jump-revive`。已配置真实广告时只有结果为 `completed` 才能复活；`skipped` 或 `failed` 不消耗第二次复活机会，面板恢复可操作并允许重试或结束本局。没有配置广告位或路由时，公共广告服务直接返回 `completed`，不展示广告并立即复活成功。第三次失败不能复活。广告请求必须携带当前 `gameId` 和 `sessionId`，快速重复点击由游戏层按钮锁和 `AdService` 会话级去重共同拦截。

复活不依赖 `lastSafePlatformId` 成功与否，也不得向下回退。复活流程先在失败相机当前可见玩法区内，按绝对高度从低到高选择高于搜索起点的安全平台；当前屏幕没有候选时，保持物理、危险物和常规生成更新暂停，仅驱动复活相机向上移动并继续检查已预生成平台。越过预生成上边界仍没有安全平台时，生成器必须在上方创建一个无怪物、UFO、黑洞、捕兽夹、爆炸计时和道具附着的 Normal 安全平台，再把相机移动到该平台。安全平台生成是确定性复活降级路径，必须记录 seed、生成游标和 `resurrect-safe-platform-generated`，保证搜索必定终止，不能因找不到平台直接结算。

### 11.2 难度上限

难度随高度提升，但不能破坏可玩性：

- 横向平台距离不超过第 7.10 节约束。
- 普通跳跃始终存在至少一条可达路线。
- 单次跳跃最多同时处理 1 个主要危险物和 1 个怪物。
- UFO 和黑洞不得在同一屏同时占据唯一落点。
- 捕兽夹与 Exploding 平台不得形成无道具必死组合。
- 道具飞行期间不提高世界速度。
- 世界生成速度固定，不因分数或击杀数突然加速。

## 13. 失败、复活和结算



### 13.1 失败锁定

任何失败条件触发时：

1. 只有 `Playing` 状态可以从 `tryFail(reason)` 进入失败；`failureLocked` 或 `settlementCommitted` 为真时直接返回。
2. 设置 `failureLocked = true`，保存 `failureReason`。
3. 保存不可变 `failureSnapshot`：`absolutePlayerPosition`、`absoluteCameraY`、`maxAbsoluteWorldY`、`lastSafePlatformId`、当前分数、击杀数和道具剩余时间。
4. 状态切换为 `Failing`，停止输入对物理状态的影响、生成器、平台/怪物/危险物更新和新子弹生成。
5. 当前已有子弹和特效只允许播放结束表现，不再产生新碰撞结算；碰撞回调必须检查 `failureLocked`。
6. 冻结相机和世界坐标，仅驱动角色表现坐标立即转为向下速度并继续受重力影响；角色碰撞盒完全低于屏幕底边后结束失败表现，1.2 秒为防止异常状态卡死的最长兜底时间。
7. 角色完全离屏后才检查复活开关并显示面板：开关关闭时直接进入 Result。开关开启时根据本局已成功复活次数决定后续：0 次进入免费复活面板，1 次进入广告复活面板，其他情况一次性固化结果并进入 `Result`。弹窗不得覆盖仍在屏幕内下坠的角色。

失败状态机只允许以下转移：

`Playing → Failing → ResurrectPrompt → Resurrecting → Playing`；
`Playing → Failing → Result`；`ResurrectPrompt → Result`。

`Failing`、`Resurrecting` 和 `Result` 都是幂等状态；重复点击和重复回调不能重复恢复、重复结算或重复写档。

### 13.2 失败表现

- fall：沿触发失败时的下落状态继续向下，镜头和背景冻结；角色完全掉出屏幕后才显示复活或结算面板；
- monster-contact：不再横向击退；接触瞬间在主角前景播放一次专用纸片冲击图，随后角色立即转为向下坠落，冲击图在约 0.38 秒内跟随角色短促放大、轻微旋转并淡出；怪物保留在场景中，角色完全掉出屏幕后才显示复活或结算面板；
- ufo-abduction：光束收束，角色向上消散；
- black-hole：角色在约 0.9 秒内沿收紧的螺旋轨迹旋转、缩小并移入黑洞中心；吸入阶段黑洞核心渲染在角色上方，最后 28% 才淡出角色，完全进入核心后再显示失败面板；
- bear-trap：夹口闭合并播放红色闪光；

失败表现不得重新调用一次失败逻辑。

### 13.3 复活面板

第一次或第二次失败进入复活面板时，描述区只显示当前分数和当前高度。按钮包括第一次失败的“免费复活”或第二次失败的“看广告复活”，以及“重新开始”和“结束本局”；三个按钮统一为 320×82 units，不允许因功能层级改变按钮外框尺寸。失败原因、广告条件和复活护盾不在描述区重复展示。

复活面板不读取或展示任何库存。复活开关关闭时跳过该面板并直接进入 Result；开关开启但没有配置广告位时，第二次复活按钮仍可用，点击后直接成功复活。

点击复活按钮后：

1. 立即锁定面板按钮。第一次失败直接进入 `Resurrecting`；第二次失败先请求 `doodle-jump-revive` 激励广告，只有 `completed` 才进入 `Resurrecting`，`skipped`/`failed` 则解锁面板且不增加成功复活次数；取消或结束本局只进入 `Result`。
2. 以失败相机当前可见玩法区底边为搜索起点，只向上检查平台；候选必须仍 `active && collisionEnabled && !consumed`，且其上方和左右 160 units 内没有黑洞核心、UFO 光束、捕兽夹、爆炸计时或怪物身体。
3. 当前屏幕没有候选时，物理和危险更新保持暂停，复活相机向上移动并继续检查；越过预生成范围仍没有候选时创建确定性的 Normal 安全平台。搜索不得向下回退，不得因没有候选直接结算。
4. 回收复活点附近的敌人、危险物和旧子弹，清除失败表现；将角色放到安全平台中心上方 34 units，设置 `velocityY = 940`，把相机锚定到该平台，并保留已经向上推进的生成游标。
5. 添加 3.0 秒 Shield，清除 `failureLocked`，重置输入指针和瞄准点；生成、物理、计分和碰撞恢复后才切回 `Playing`，并在成功进入 Playing 时把本局成功复活次数加 1。
6. 复活不回退 `maxAbsoluteWorldY`、已获得分数或击杀统计；成功两次后下一次失败直接进入 Result。



### 13.4 结算面板

Result 的描述区只显示本局分数和最高高度；新纪录可以通过标题表达，不在描述中追加击杀、失败原因或其他统计。按钮只包括“再来一局”和“返回大厅”，微信与其他平台均不显示分享按钮。

结算面板的业务行为由公共契约提供，正式视觉由本游戏 Bundle 自己实现。

## 14. UI 和交互



### 14.1 Playing HUD

屏幕常驻显示，布局以视觉参考为基线并按安全区动态定位：

- 左上同一行横向排列两张纸片卡：分数和当前最高高度，使用 `score_card.png`、`height_card.png` 的实际素材构图，数值在各自深色数字区内水平、垂直居中，不能贴近黑色块下沿；
- 右上：暂停按钮；其左侧是同为 72×72 units、内部图标同为 64×64 units 的纸片规则入口，二者都必须避让胶囊；规则入口使用暖橙色调，与浅紫暂停图标明确区分；
- 分数卡下方显示持续道具状态：每项左侧为道具图标、右侧为无数字的图片进度条；护盾与当前飞行道具可横向并列，一次性 Spring/Trampoline 只显示图标；
- 拾取道具不在角色附近显示文字气泡，状态只通过 HUD 图标/计时和正式拾取特效反馈；
- 传感器异常时：顶部显示“请保持手机竖直并允许重力感应”。

HUD 必须避让微信胶囊和底部安全区。HUD 不得挡住角色脚下 1.2 个跳跃高度范围内的关键落点。

HUD 不使用右下角固定栏；顶部纸片层级、留白和暂停位置按安全区动态布局。所有纸片卡均为正面平面 Sprite，窄白边和柔和落影可以作为透明素材的预烘焙效果保留，不使用实时投影、厚重阴影或立体厚度。

### 14.2 首次引导

首次进入且 `tutorialCompleted = false` 时显示三步引导：

1. “左右倾斜手机，控制角色移动”；
2. “点击发射一架纸飞机，按住会持续发射”；
3. “踩怪物、躲开光束、黑洞和捕兽夹”。

引导必须明确写出“拖动不会移动角色”或用等价视觉说明，避免玩家误解输入方式。
“下一步”每次只推进一步，不能由同一次触摸的兼容鼠标事件连续推进；第 1 步必须进入第 2 步，之后才能进入第 3 步。“我知道了”完成并关闭引导；首次引导关闭后写入 `tutorialCompleted=true`。该字段独立于 `playCount`，不得用是否已经创建过 Session 代替。

### 14.3 局内规则入口

点击右上书本图标后暂停当前局并打开本游戏独立的长规则面板，关闭时通过公共暂停模型恢复当前局。规则面板使用 `rules_panel.png`，不得复用象棋或其他游戏的皮肤，只参考其“单页纵向滚动、规则分类横向翻页”的交互模式。

规则共四页，每页只承载一个分类：玩法规则、平台规则、道具规则、敌人与危险。规则面板设计高度为 787 units，约为标准弹窗的 4/3；背景使用九宫格拉伸，运行时切片边距按左 104、右 64、上 160、下 96 设置。标题区固定显示当前页和 `页码 / 4`；正文使用 24 units 字号、38 units 行高，位于带裁切蒙版的纵向 ScrollView 中，可上下滑动查看全文。面板左右滑动超过 76 屏幕 units 且横向位移大于纵向位移的 1.25 倍时切换上一页或下一页；底部同时保留“上一页 / 关闭 / 下一页”按钮，首尾页循环衔接。纵向阅读手势不能误触横向翻页，横向翻页后新页面从正文顶部开始。

### 14.4 触摸层级

从上到下的输入优先级：

1. 系统安全区和微信胶囊：不接收游戏输入；
2. 暂停、重开、返回等 UI 按钮：只处理 UI；
3. 首次指引、规则、复活、结算面板：只处理面板；暂停覆盖层存在时优先于这些业务面板；

### 14.5 可读性和非颜色提示

- 平台类型不能只依靠颜色区分：每类平台还必须有独立的线稿符号、边缘纹样或形状差异。

## 15. 动画、特效和声音反馈



### 15.1 角色

- 正式运行时交付一张全身基础 Sprite、Rocket/Jetpack/Propeller Hat 各一张完整“主角＋道具”组合 Sprite，以及一张独立透明 Shield Overlay。所有图片姿势固定为自然站立待机：身体保持直立、双腿自然下垂并略微分开，双脚最低点贴齐图片底部基线；头部/发型、脸部、躯干、围巾、双臂轮廓、比例和配色必须与参考图保持一致。
- 无道具时使用基础 Sprite，使用 Rocket、Jetpack 或 Propeller Hat 时切换对应组合 Sprite；使用 Shield 时不切换主角图，而是把 Shield Overlay 作为玩家视觉根节点的独立子节点叠加。Rocket 与 Jetpack 的静态本体都背在主角背部，Propeller Hat 位于头顶；Shield Overlay 环绕身体并与基础图、三张组合图共用玩家中心、局部坐标和碰撞盒参考线，不改变碰撞盒。
- 除一张独立落地帧外，基础图和飞行道具组合图不制作跳跃、下落、射击、受击、失败、复活或朝向动作帧，不旋转、不变形，也不改变参考图中的上半身、脸部或围巾形状；水平方向仍通过节点翻转。落地帧只在下降过程中成功踩中可反弹平台后显示约 0.06 秒，双腿自然向下且双脚最低点贴合平台可见上沿；开局自动起跳、从下方穿过平台、Breakable 断裂和飞行道具期间不显示。Shield Overlay 仍为独立静态环形覆盖图。
- 飞行道具必须同时叠加独立运动特效：Rocket/Jetpack 从下方喷出纸屑、彩笔火焰和短拖尾，拖尾跟随角色速度变化；Propeller Hat 叠加旋转线稿和向下气流；Shield 叠加护盾脉冲；这些特效不绘制进基础图、组合图或 Shield Overlay。
- Spring、Trampoline、Head Start 的待触发或助推表现使用脚下独立提示/冲刺特效；Resurrect 使用角色周围的复活特效；这些表现不改变基础图或组合图的身体姿势。
- 每次平台产生有效反弹时，在角色最低脚点和平台上沿交界处播放专用透明图 `landing-paper-debris-v3`：图形使用与既有怪物碎片、平台爆炸一致的粗暖白纸边、灰黑铅笔轮廓和彩铅排线，约 10～12 块不规则碎片从低位中心向左右呈扇形散开；运行时基础显示宽度为 172 units，并由约 72% 放大到 108%，每一帧都按当前缩放把图片最低可见点对齐平台上沿，前 18% 时段保持完整不透明度并在 0.42 秒内淡出。禁止使用写实纸材、代码绘制色块、水波或环形扩散。从下方穿过、Breakable 断裂以及非碰撞经过不触发。
- 允许叠加独立的铅笔擦线或残影特效，但这些特效不能烘进基础图或组合图。
- 射击时主角图不转向、不改变手臂姿势；纸飞机从固定发射点生成，朝当前手指方向飞行，瞄准点和飞行轨迹均为独立资源。
- 被护盾抵挡、失败和复活播放角色外部的护盾、压痕、失败或复活特效；护盾本体使用独立 Shield Overlay，护盾脉冲和格挡反馈继续使用独立 VFX，不得生成另一套身体动作姿势。



### 15.2 平台

- Moving：平台边缘有重复的铅笔方向线；
- Breakable：被踩前出现纸面裂纹预警；
- Disappearing：剩余 0.15 秒快速褪色并露出底层纸张；

- Exploding：落地后红色蜡笔环倒计时，爆炸时纸片向外散开。



### 15.3 怪物和危险物

- 怪物受伤显示短促铅笔擦痕或短暂反色；
- 怪物死亡只触发一次纸屑散开；
- 主角因怪物身体接触失败时使用独立透明图 `player-enemy-contact-impact`，不得复用子弹命中怪物的擦痕；图片位于主角前景并跟随失败下坠，基础显示宽度 176 units，约从 62% 放大到 114%，在 0.38 秒内淡出；普通 fall 不播放；

- 黑洞外圈使用低频旋转的平面剪纸环，核心不可与背景同色；
- 捕兽夹在触发前保持清晰的红色纸板夹口；
- 护盾状态必须有独立纸环轮廓，不能只依靠 HUD 文本。

## 16. 存档



### 16.1 数据命名空间

本游戏只能读写自己的命名空间：

- 根存档：由公共存档服务管理；
- 游戏存档：`doodle-jump`，与 Bundle/Manifest 的 gameId 保持一致；
- 禁止读写其他小游戏命名空间；
- 禁止因本游戏隐藏、回滚或字段不识别而清空根存档；读取和写回时保留未知字段。



### 16.2 游戏数据结构

公共 `StorageService` 要求每个游戏数据符合 `GameSaveData`：

```ts
{
  dataVersion: 1,
  playCount: number,
  highScore: number,
  lastPlayedAt: number,
  custom: {
    gameDataVersion: 2,
    bestHeightMeters: number,
    bestKillCount: number,
    totalShots: number,
    totalKills: number,
    sensorInvert: boolean,
    sensorSensitivity: 0.75 | 1 | 1.25,
    tutorialCompleted: boolean,
    headStartCount: number,
    settingsVersion: number,
  },
}
```

字段归属固定：公共 `highScore` 就是本游戏 `bestScore`，公共 `playCount` 就是 `totalRuns`，不得在 `custom` 再维护一份可冲突的 `totalRuns`；`lastPlayedAt` 使用毫秒时间戳。所有未知 `custom` 字段必须在读改写时原样保留。

默认值：`highScore = 0`、`playCount = 0`、`bestHeightMeters = 0`、`bestKillCount = 0`、`totalShots = 0`、`totalKills = 0`、`sensorInvert = false`、`sensorSensitivity = 1`、`tutorialCompleted = false`、`headStartCount = 0`、`settingsVersion = 1`。复活次数只属于当前局内存状态，不进入持久存档。

`custom.gameDataVersion` 当前版本固定为 2。读取 v1 时执行一次 `v1 → v2` 增量迁移：保留公共 `playCount/highScore/lastPlayedAt`、上述全部已知 `custom` 字段及未知 `custom` 字段，缺少 `tutorialCompleted` 时补为 false，再把 `gameDataVersion` 提升为 2。历史规划别名命名空间 `doodleJump` 只允许迁移到正式命名空间 `doodle-jump`；正式命名空间已存在时以正式命名空间为主，不覆盖其已知字段，仅补入其中不存在的未知兼容字段。历史规划数据中若存在 `resurrectCount`，将其视为不再读取的未知兼容字段原样保留，不得用于决定复活资格。迁移完成并通过 v2 校验后才能写回；迁移失败时先由公共存档服务备份原始根存档字符串，再为本游戏使用安全默认值，禁止清空根存档或其他游戏数据。

### 16.3 当前局定时检查点

本游戏持久化 `activeRound`，支持跨进程或跨会话恢复最近一次局面。Playing 期间每 3 秒保存一次局内检查点；死亡进入 `Failing` 前立即保存失败时的完整模拟快照并 `flush()`，复活成功切回 `Playing` 后立即保存复活后的完整模拟快照并 `flush()`。普通检查点从进入本局时的固定存档基线和本局绝对累计值重建，更新 `playCount/highScore/lastPlayedAt/bestHeightMeters/bestKillCount/totalShots/totalKills`，不得在上一次检查点结果上再次累加。暂停、微信 hide、结算、退出、重开和销毁时立即固化并 `flush()`；失败或复活提示阶段只 flush 已保存的活动局，不能清除该快照。重新进入时若活动局结构有效，恢复角色位置、相机、平台、敌人、危险物、道具和复活次数后继续游戏。

## 18. 技术边界和实现要求



### 18.1 Bundle 和入口

- Bundle：game-doodle-jump
- 场景：assets/games/doodle-jump/scenes/DoodleJump.scene
- 入口组件：DoodleJumpGame
- 资源目录：assets/games/doodle-jump
- 由 GameManifest 注册，不改写大厅加载流程。

大厅只依赖游戏清单和大厅展示副本，不导入 DoodleJumpGame、游戏场景或游戏内正式资源。

### 18.2 生命周期

DoodleJumpGame 必须实现统一 MiniGame 生命周期：

- initialize(context)
- begin()
- pause()
- resume()
- restart()
- dispose()

initialize 只建立引用和配置，不开始世界推进；begin 才开始传感器使用、生成世界和游戏计时。

### 18.3 平台和公共服务

小游戏只通过 `MiniGameContext.services` 使用仓库当前已经注入的服务键：

```ts
interface DoodleJumpServices {
  platform: Platform;
  audio: AudioService;
  feedback: FeedbackService;
  storage: StorageService;
  analytics: AnalyticsService;
  ads: AdService;
  deviceTier: DevicePerformanceTier;
}
```

- `platform`：加速度计、设备能力、安全区和分享；
- `audio` / `feedback`：独立 Bundle 音频注册和反馈播放；
- `storage`：通过 `getGameData('doodle-jump')` / `writeGameData()` 读写本游戏数据；
- `analytics`：上报本节事件，射击事件按批次冲刷；
- `ads`：第二次失败通过独立 `doodle-jump-revive` placement 请求激励广告；只有 `completed` 才发放第二次复活，游戏不直接访问平台广告 API；
- `deviceTier`：选择粒子、纸屑和特效质量。

触摸、鼠标和键盘回退由游戏 Bundle 内的 `DoodleJumpInputController` 管理，不虚构公共 `InputService`；暂停、前后台、广告和退出通过 `MiniGameContext.requestPause/requestExit/requestRestart/requestLobby` 及运行层状态机管理，不虚构 `AppStateService`。Bundle 加载、场景切换、资源引用追踪和释放由运行层/`AssetService` 管理，游戏不从 Context 直接取 `AssetService`。

不得在游戏逻辑中直接调用 `wx.*`、切场景、卸载 Bundle、创建全局单例或自行定义全局服务。小游戏可以拥有 Bundle 内部的输入控制器、生成器、状态机和视图 Presenter，但它们不得注册为全局服务。

## 19. 性能预算

在中低端微信设备上，运行时应满足：


| 项目         | 预算                                      |
| ---------- | --------------------------------------- |
| 目标帧率       | 60 FPS                                  |
| 单帧物理子步     | 最多 4                                    |
| 活动平台       | 最多 64；需覆盖完整视口及视口上方 620 units 缓冲 |
| 活动普通怪物     | 最多 3                                    |
| 活动 UFO     | 最多 2                                    |
| 活动黑洞       | 最多 2                                    |
| 活动捕兽夹      | 最多 2                                    |
| 活动道具       | 最多 5                                    |
| 子弹对象池软目标   | 32，不是玩法上限                               |
| 单屏粒子发射器    | 最多 18                                   |
| 单个怪物材质实例   | 1 个共享材质                                 |
| 活动渲染节点     | 最多 180，离屏对象立即回收                         |
| Draw Call  | 中低档真机稳定场景 P95 ≤ 45                      |
| 主循环帧耗时     | 中低档真机 P95 ≤ 18 ms，连续超过 33.4 ms 不得超过 3 帧 |
| Bundle 冷启动 | 本地包从进入加载到 SensorCalibrating ≤ 3 s，失败必须可重试 |
| 运行时纹理峰值    | 游戏 Bundle ≤ 24 MB，按实际设备档位记录             |
| 60 秒压力测试   | 不出现未回收纸飞机、计时器、监听或持续增长的节点数               |
| 单局不限制子弹总数  | 允许，按生命周期回收                              |


如果同时存在的子弹多于 32 个，必须继续支持发射和碰撞；可通过回收离屏子弹、批量渲染或动态扩容保障性能，但不得静默丢弃玩家已经触发的射击。长按 10 秒和多次连续点击必须纳入压力测试；视觉纸屑、轨迹和命中特效可以按 `deviceTier` 降级，但不能降级输入、碰撞或得分。

性能验收还要记录 P50/P95 帧耗时、Draw Call、节点峰值、纹理峰值、首次加载时间、GC/内存峰值，并连续执行“进入游戏 → 退出大厅”20 次，确认监听、计时器、Bundle 引用和音频实例没有单调增长。

## 20. 验收标准



### 20.1 输入与移动

- [ ] 微信设备可授权并读取重力感应。
- [ ] Platform 会在首个有效有限数值样本后确认传感器会话，1500 ms 无样本进入 Error。
- [ ] 校准使用至少 10 个样本，最多等待 1500 毫秒。
- [ ] 左倾稳定向左，右倾稳定向右。
- [ ] 中性姿态不会让角色持续漂移。
- [ ] 左右反向设置生效。
- [ ] 浏览器没有传感器时可用键盘开发回退。
- [ ] 触摸拖动不会移动角色。
- [ ] 角色自动弹跳，不能通过触摸主动跳跃。
- [ ] 角色从左边离开后从右边出现，反向同理。
- [ ] 平台、怪物、危险物、道具和子弹不穿屏。
- [ ] 掉落死亡线触发 fall。
- [ ] `TOUCH_CANCEL`、hide、暂停、失败和 dispose 都会清除攻击指针与连发计时器。



### 20.2 射击

- [ ] 射击冷却结束时，游戏区按下手指立即发射一发。
- [ ] 单击后抬手只产生一发，不因点击过短而丢失首发。
- [ ] 每次成功发射后都有 200ms 全局冷却，点击和长按不能绕过。
- [ ] 冷却期间的快速点击不排队、不补发。
- [ ] 手指保持按住时，冷却结束后每 200 毫秒继续发射。
- [ ] 长按 10 秒仍持续发射。
- [ ] 长按不会因为“三发”“五发”或同屏数量上限停止。
- [ ] 子弹初始方向指向当前手指位置。
- [ ] 手指移动后后续子弹使用新方向。
- [ ] 子弹允许左、右、斜向、正上和正下方向；紧贴角色下方点击也不能回退成向上发射。
- [ ] 抬手后立即停止发射。
- [ ] 暂停、失败和退出时停止发射。
- [ ] 多指不会抢占第一个瞄准指针。
- [ ] 子弹可以击杀普通、大型、悬浮怪物。
- [ ] 子弹命中 UFO 可中断锁定但不能摧毁 UFO。
- [ ] 连续点击和长按都能命中同一套目标，点击不会进入另一套射击逻辑。



### 20.3 平台

- [ ] Normal 落地反弹 940，在重力 -1590 下理论峰值约为 277.9 units；完整升降周期略慢，并在脚下喷散短促的纸屑灰尘，不出现水波或环形扩散。
- [ ] Moving 按固定路线移动且不可穿屏。
- [ ] Breakable 第一次踩到立即失去碰撞且不反弹。
- [ ] Disappearing 第一次落地反弹，0.35 秒后消失。
- [ ] Shifting 在三个固定位置之间切换。
- [ ] Exploding 第一次落地反弹，1.5 秒倒计时后爆炸并关闭碰撞，爆炸不会伤害角色。
- [ ] 程序化平台始终保留可达路线。
- [ ] 代表性 seed 清单可稳定复现平台序列、生成游标和降级路径，人工验收未发现死路、死循环或越界；失败 seed 已固化为回归样本。
- [ ] 断裂、消失和爆炸平台不会在本局重生。



### 20.4 怪物与危险物

- [ ] 普通怪物生命值为 2。
- [ ] 大型怪物生命值为 4。
- [ ] 悬浮怪物生命值为 1。
- [ ] 三种怪物都可以被子弹击杀。
- [ ] 三种怪物都可以被从头顶踩踏击杀。
- [ ] 侧面或底部接触怪物会失败。
- [ ] UFO 有锁定、吸附、连续绑架和失败计时。
- [ ] 子弹命中 UFO 可以中断当前锁定。
- [ ] 黑洞有外圈吸引和核心失败。
- [ ] 捕兽夹位于平台表面且接触失败。
- [ ] 每一种失败原因都能正确显示和统计。
- [ ] Failing/Resurrecting 状态只能各自进入和退出一次，重复回调不重复结算。



### 20.5 道具

- [ ] Spring 下一次有效落地反弹 1350，脚底正式反弹图更大且约持续 0.72 秒。
- [ ] Trampoline 下一次有效落地反弹 1700，主角在上升阶段翻滚两圈、最高点开始下落时刚好回正，且该次跳跃期间无敌，脚底正式反弹图约持续 0.72 秒。
- [ ] Jetpack 持续 2.4 秒并穿过平台。
- [ ] Propeller Hat 持续 3.6 秒并将最低上升速度保持为 400；所有合法拾取速度下的总上升高度都低于 Jetpack。
- [ ] Rocket 持续 2 秒并以 1650 向上冲刺，总上升高度高于 Jetpack。
- [ ] 任一飞行道具激活时，三种飞行拾取物均不可拾取、续时或替换，状态结束后恢复拾取。
- [ ] Jetpack、Propeller Hat、Rocket 激活期间不会被怪物、UFO、黑洞或捕兽夹致死。
- [ ] Shield 持续 6 秒并按各危险物规则抵挡。
- [ ] Shield 抵挡怪物后角色被移出碰撞盒，不会在下一物理子步立刻死亡。
- [ ] Shield 不能抵挡 fall。
- [ ] Head Start 规则可被开发配置验证。
- [ ] 复活开关关闭时所有失败直接结算；开关开启时第一次失败可免费复活，第二次失败在激励广告 `completed` 后复活，第三次失败直接结算。
- [ ] 复活开关开启但未配置广告位或路由时，第二次复活不展示广告并直接成功。
- [ ] 当前屏幕没有安全平台时，复活流程只向上移动查找；越过预生成范围后创建确定性的 Normal 安全平台，不向下回退或直接结算。
- [ ] 道具不作为平台、不被子弹破坏、不重复拾取。
- [ ] Jetpack/Rocket/Head Start 穿平台但不是全局无敌；Propeller Hat 保留平台碰撞。

## 21. 固定文案



### 21.1 控制

- 开始：保持手机竖直
- 移动：左右倾斜控制移动
- 攻击：点击发射一架纸飞机，按住会持续发射
- 穿屏：从屏幕一侧离开，会从另一侧出现
- 提示：拖动不会移动角色



### 21.2 传感器

- 正在校准：请保持手机自然竖直
- 校准成功：重力感应已准备
- 校准失败：未检测到稳定重力感应，请重试
- 权限失败：请在系统设置中允许重力感应
- 开发回退：当前为键盘开发控制



### 21.3 失败原因

- fall：没有落到下一块平台
- monster-contact：撞到了怪物
- ufo-abduction：被 UFO 光束带走
- black-hole：被黑洞吸入
- bear-trap：触发了捕兽夹



### 21.4 道具提示

- 弹簧：下一次落地强力弹跳
- 蹦床：下一次落地超强弹跳
- 喷气背包：短时间向上飞行
- 螺旋桨帽：降低重力并持续上升
- 火箭：高速向上冲刺
- 护盾：持续时间内无敌
