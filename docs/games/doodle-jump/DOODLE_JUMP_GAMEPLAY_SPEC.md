## 1. 目标与原版机制覆盖



### 1.1 一局游戏的核心体验

玩家控制一个自动弹跳的角色，在持续向上滚动的平台区中左右移动，落到平台上再次弹起；玩家不能主动跳跃，也不能通过拖拽角色移动。手机的左右倾斜决定横向运动；射击冷却结束时，在游戏区点击会立即向手指方向发射一发纸飞机，按住不抬手则继续按固定间隔向最新手指方向连发。

玩家需要同时处理四类空间信息：

1. 下一块可落平台的位置。
2. 怪物的头部、身体和移动路线。
3. UFO 光束、黑洞、捕兽夹等危险物。
4. 弹簧、蹦床、喷气背包、螺旋桨帽、火箭和护盾等道具。

## 3. 游戏状态和一局流程



### 3.1 状态枚举

游戏运行态只有以下状态：


| 状态                | 含义             | 允许输入                   |
| ----------------- | -------------- | ---------------------- |
| Loading           | 场景和资源加载中       | 无                      |
| SensorCalibrating | 等待重力感应中性值      | 暂停按钮不可用                |
| Ready             | 角色位于起始平台，等待开始  | 点击开始                   |
| Playing           | 正常进行           | 重力感应、触摸瞄准、点击单发、长按连发、暂停 |
| Paused            | 游戏暂停           | 继续、重开、退出               |
| Failing           | 失败已锁定，播放失败表现缓冲 | 无玩法输入，仅等待表现收束          |
| ResurrectPrompt   | 第一次失败后的复活确认    | 复活、结束本局                |
| Resurrecting      | 正在恢复安全平台和局内系统  | 无玩法输入，仅等待恢复完成          |
| Result            | 已固化本局结果        | 重开、返回大厅、分享入口           |
| Error             | 初始化或运行异常       | 重试、返回大厅                |




### 3.2 开始流程

1. 应用状态机锁定进入入口。
2. 创建唯一 GameSession。
3. 加载 game-doodle-jump Bundle 和独立场景。
4. 定位 DoodleJumpGame 入口。
5. 通过 MiniGameContext 注入公共服务。
6. 初始化输入、传感器、对象池、随机种子和初始关卡。
7. 进入 SensorCalibrating。
8. 采集到足够传感器样本后进入 Ready；微信环境没有传感器样本则进入 Error，允许重试或返回大厅；浏览器预览若 `Platform` 不支持加速度计，则标记 `sensorDegraded` 并直接启用键盘回退后进入 Ready。
9. 玩家点击开始后进入 Playing，角色从 P0 平台开始。Ready 状态的这次点击只负责开始，不发射纸飞机。



### 3.3 失败流程

1. 仅当当前状态为 Playing 时接受失败事件；重复失败事件直接忽略。
2. 保存首次失败原因、失败时高度、相机位置、最近安全平台和本局临时统计。
3. 进入 Failing，立即停止物理推进、传感器读数应用、子弹生成和敌人更新。
4. 完成 0.35 秒失败表现后，如果有可用复活位进入 ResurrectPrompt，否则进入 Result。
5. 复活确认后进入 Resurrecting，恢复到重新验证过的安全平台；恢复完成后回到 Playing。
6. 拒绝复活或第二次失败直接进入 Result；结算和存档只能执行一次。
7. 退出时按 pause → 固化结果 → 保存/上报 → dispose → 返回大厅的顺序执行。



### 3.4 暂停规则

- 暂停时角色、平台、怪物、危险物、子弹、道具计时器全部停止。
- 暂停会取消当前攻击指针；恢复时必须重新点击或按住游戏区，点击重新只发射一发，按住才继续连发。
- 传感器监听可以保留，但样本不得推进角色速度。
- 广告暂停、前后台切换和主动暂停都经过应用状态机。
- 快速连续点击暂停、重开、退出不得创建第二个 Session。



## 4. 重力感应移动



### 4.1 输入原则

重力感应是正式移动输入，触摸拖动不参与角色移动。

手机端只能通过公共 Platform 接口访问传感器；v2.5 对齐仓库当前实际接口，不新增 Promise 返回值：

- `supportsAccelerometer(): boolean`
- `startAccelerometer(): void`
- `stopAccelerometer(): void`
- `onAccelerometerChange(callback): Unsubscribe`

游戏逻辑不得直接调用 wx.*。微信平台实现只存在于 WeChatPlatform；小游戏只消费 `AccelerometerSample` 的 x、y、z 数据。`startAccelerometer()` 本身不承诺异步成功，游戏通过“首个有限数值样本 + 1500 ms 超时”建立本局传感器会话结果；重试必须先 stop、取消旧订阅、清空旧样本，再重新订阅和 start。

### 4.2 传感器校准

`AccelerometerSample` 的 x、y、z 单位统一为重力加速度 `g`，由 Platform 适配器按竖屏坐标归一化：设备向屏幕右侧倾斜时，`x` 的变化方向必须为正；设备旋转、iOS/Android 轴向差异和 SDK 字段差异不得由游戏逻辑分别处理。样本必须是有限数值，异常样本丢弃且不计入校准数量。

进入 SensorCalibrating 后执行以下固定流程：

1. 屏幕提示玩家保持手机自然竖直。
2. 最少采集 10 个有效样本。
3. 校准窗口默认 600 毫秒，最多等待 1500 毫秒。
4. 取样本 x 的平均值作为 neutralX。
5. 若样本数不足，使用 neutralX = 0 并标记 sensorDegraded。
6. 校准结束后立即进入 Ready，不要求玩家再次点击校准。
7. 从暂停恢复时不重新校准，只继续使用当前 neutralX；前后台切换回来若连续 1500 ms 没有新样本，进入 Error 而不是静默使用旧输入。



### 4.3 倾斜映射

定义：

- rawTilt = sample.x - neutralX
- invert = 用户设置中的左右反向开关
- 若 invert 为真，则 rawTilt = -rawTilt
- deadZone = 0.06
- fullTilt = 0.35

归一化规则：

- abs(rawTilt) ≤ 0.06 时，targetInput = 0
- abs(rawTilt) ≥ 0.35 时，targetInput = sign(rawTilt)
- 中间区间线性映射到 -1 至 1
- sensorSensitivity 只允许 0.75、1.00、1.25 三档；归一化结果乘以该值后再限制在 -1 至 1
- 使用时间无关的指数平滑：`alpha = 1 - exp(-dt / 0.08 s)`，禁止使用与帧率绑定的固定 `smoothFactor`。

方向约定：

- targetInput > 0：角色向屏幕右侧加速
- targetInput < 0：角色向屏幕左侧加速
- targetInput = 0：停止主动加速，保留惯性并逐渐减速



### 4.4 传感器异常和开发回退


| 情况             | 正式微信运行             | 浏览器预览                             |
| -------------- | ------------------ | --------------------------------- |
| 支持传感器且收到首个有效样本 | 使用重力感应             | 当前 WebPlatform 不提供原生加速度计，使用键盘开发回退 |
| 不支持、授权失败或超时无样本 | 进入 Error，提供重试和返回大厅 | 进入键盘开发回退并显示开发提示                   |
| 样本长时间不变化       | 保持最近有效输入并逐渐归零      | 显示开发提示                            |
| 模拟器无传感器        | 不将触摸拖动当作替代         | 仅允许键盘左右键回退                        |


浏览器开发回退只允许使用键盘左右键或调试面板；当前不把 DeviceMotion 视为 v2.5 的公共能力，也不得因为浏览器没有传感器而恢复触摸拖动。若未来扩展 WebPlatform，必须先更新 Platform 契约和架构记录。

### 4.5 角色横向物理参数

所有物理推进使用固定步长：

- fixedDelta = 1 / 120 秒
- 单帧最多执行 4 个物理子步
- 超出最大子步的时间丢弃，避免切后台后瞬移

角色参数：


| 参数               | 数值                 |
| ---------------- | ------------------ |
| 重力 accelerationY | -1800 units/s²     |
| 普通反弹初速度          | 820 units/s        |
| 重力感应横向加速度        | 2100 units/s²      |
| 无输入减速度           | 1500 units/s²      |
| 最大横向速度           | 420 units/s        |
| 角色碰撞盒            | 52 × 68 units      |
| 角色脚底碰撞点          | 碰撞盒底边中点            |
| 初始位置             | P0 平台中心上方 34 units |
| 初始竖直速度           | 820 units/s        |


横向更新规则：

1. 有输入时，velocityX 向 targetInput × 420 以 2100 units/s² 靠近。
2. 无输入时，velocityX 向 0 以 1500 units/s² 靠近。
3. 角色不因碰到屏幕边缘反弹。
4. 角色不因平台、怪物或危险物改变横向速度，除非进入失败状态或使用道具。



### 4.6 竖直跳跃规则

- 只有平台、弹簧、蹦床和指定飞行道具能改变竖直速度。
- 角色只有在向下运动或竖直速度为 0 时，才允许触发平台落地。
- 向上穿过平台时不碰撞。
- 从平台底部穿过不碰撞。
- 普通平台落地后立即把 velocityY 设置为 820。
- 角色落地的判定窗口为本物理子步内脚底从平台顶面上方移动到平台顶面或以下，且水平碰撞盒有重叠。
- 一次物理子步只能触发一次弹跳。

单位和高度换算固定如下：

- `WORLD_UNITS_PER_METER = 100`；所有速度、加速度、碰撞盒和平台坐标使用 world units。
- `startWorldY` 是 P0 顶面高度；`heightMeters = floor((maxWorldY - startWorldY) / 100)`，实际实现先对 world units 做非负保护再换算，不能使用屏幕像素。
- 文档中所有 `m` 高度段使用半开区间 `[start, end)`，实现时先乘以 100 转为 world units；`250 m 以上`表示 `[250, +∞)`。
- 普通反弹的理论最高升高为 `820² / (2 × 1800) = 186.8 units`，这不是生成器允许的安全落差；安全落差另由第 7.10 节的可达性求解器确定。



## 5. 手指瞄准、点击单发与长按连续射击



### 5.1 输入职责

触摸输入只做两件事：

1. 记录手指当前所在位置作为瞄准方向。
2. 手指按下时尝试发射一发纸飞机；若全局射击冷却已结束则立即发射，即使随后马上抬起，这一发也必须保留。
3. 手指持续按住时，在全局射击冷却结束后继续发射；因此一次点击是单发，一次长按是“首发 + 冷却结束后的连发”。

触摸输入绝不用于：

- 拖动角色；
- 移动平台；
- 改变重力感应中性值；
- 触发跳跃；
- 替代暂停、重开或系统按钮。

攻击物的功能位对应原版的 nose ball（从角色处发射的攻击物）。本项目不使用鼻子造型，正式表现改为纸飞机，但它仍承担原版攻击物的“击中怪物、消耗一次、飞行后回收”功能。

### 5.2 瞄准坐标

1. 只接收游戏玩法区的第一个有效触点，指针 ID 记为 attackPointerId。
2. UI 安全区、暂停按钮、失败面板和帮助面板上的触摸不进入攻击系统。
3. 将触点位置转换到 Canvas 坐标，再转换到当前游戏世界坐标。
4. aimVector = fingerWorldPosition - playerWorldPosition。
5. aimVector 长度小于 18 units 时，方向固定为正上方。
6. 方向不限制在上半屏，允许向左、右、左上、右上、正上和必要时向下发射。
7. 手指移动时只更新 aimVector，不移动角色。
8. 手指抬起后清除 attackPointerId，停止自动发射。



### 5.3 射击时序

- `fireCooldown = 120 ms`，是整个本局共享的全局射击冷却，不按指针、不按点击/长按模式分别计算。
- 手指按下时尝试发射第一发；冷却结束则立即发射，这同时定义了点击单发行为。
- 若点击发生在冷却期间，该次点击不排队、不补发；抬手前没有再次尝试就不会产生纸飞机。
- 若长按发生在冷却期间，保留当前攻击指针，冷却结束时发射一发，之后每次成功发射后等待 120ms 再发射下一发。
- 发射调度不追赶暂停或卡顿期间错过的次数；恢复后只允许按当前冷却时间发射一发。
- 每次发射都读取最新 aimVector。
- 手指移动后，下一发使用新方向，已经生成的子弹不转向。
- 手指抬起、`TOUCH_CANCEL`、应用隐藏、暂停、失败、进入 Result 或退出时立即停止发射。
- 没有弹药值。
- 没有三发上限。
- 没有五发上限。
- 没有同时存在数量上限。
- 对象池 32 只是内存和复用的软目标，不得转化为玩法上限；超过软目标时必须继续创建或扩容，不能拒绝冷却已经结束的合法射击。长按 10 秒约产生 84 发，验收必须覆盖这类压力场景。



### 5.4 子弹参数


| 参数       | 数值                          |
| -------- | --------------------------- |
| 攻击物名称    | 纸飞机（原版 nose ball 功能位）       |
| 子弹生成点    | 角色中心沿 aimVector 前移 34 units |
| 飞行速度     | 920 units/s                 |
| 碰撞形状     | 半径 7 units 的圆               |
| 存活时间     | 1.6 秒                       |
| 重力       | 0                           |
| 是否穿过平台   | 是                           |
| 是否穿过道具   | 是                           |
| 单发命中后    | 命中一个目标后销毁                   |
| 默认对象池软目标 | 32，非玩法限制                    |


子弹可命中普通怪物、大型怪物、悬浮怪物和 UFO 舱体。子弹不能破坏黑洞、捕兽夹、普通平台或道具，也不能通过射击直接改变平台类型。

### 5.5 子弹碰撞优先级

同一物理子步中发生多种碰撞时按以下顺序处理：

1. 角色失败状态检查已锁定，则忽略全部新碰撞。
2. 子弹与怪物命中，扣除怪物生命值并销毁子弹。
3. 子弹与 UFO 舱体命中，触发 UFO 短暂受击停顿并销毁子弹。
4. 子弹与其他不可破坏对象不产生效果。



### 5.6 多指、取消和鼠标

- 多指只保留最早进入游戏区的一个攻击指针。
- 第二个及之后的手指全部忽略，不抢占瞄准权。
- 第一根手指抬起后，如果仍有其他手指按住，也不自动接管；必须重新按下。
- 浏览器鼠标按下等同于一个指针。
- 浏览器按住 Space 是开发回退攻击，方向使用最近一次有效瞄准方向；没有瞄准方向时向正上方发射。

输入生命周期固定如下：

- 触摸起点在暂停、规则、复活、结算等 UI 区域时，归 UI 所有，不会转移到攻击系统。
- 触摸起点在玩法区时，攻击指针由该触摸事务持有；移动到 UI 区域不会把同一指针转交给 UI，必须抬手后重新点击 UI。
- 收到 `TOUCH_END`、`TOUCH_CANCEL`、窗口 hide、暂停请求、失败锁定或 dispose 时，必须清除 `attackPointerId`、连发计时器和当前瞄准点。
- 规则/复活/结算面板打开时，所有已有玩法指针立即取消，面板关闭后必须重新按下才能攻击。



## 6. 屏幕穿越、世界边界和相机



### 6.1 屏幕穿越

设计宽度为 750 units。角色碰撞盒半宽为 26 units，因此角色中心坐标按以下规则处理：

- playerX < -26：playerX += 802
- playerX > 776：playerX -= 802

穿越发生在物理位置更新后、碰撞检测前。穿越不改变 velocityX、velocityY、瞄准方向或当前道具。

### 6.2 只有主角穿屏

可以穿屏的对象只有主角。以下对象不可穿屏：

- 平台；
- 普通、大型、悬浮怪物；
- UFO；
- 黑洞；
- 捕兽夹；
- 道具；
- 子弹。

不可穿屏对象离开活动区域后按生命周期规则回收。

### 6.3 掉落和追踪

- 世界底部死亡线位于当前可见区域底部以下 160 units。
- 角色低于死亡线且没有飞行道具保护时，进入 fall 失败。
- 相机只向上跟随，不向下回弹。
- 角色屏幕纵向目标位置为可见高度的 62%。
- 角色低于目标位置时，相机不追下去；角色继续向下直到落到平台或失败。
- 世界坐标持续增加，不能用循环地图覆盖已经生成的高度。
- 视野上方至少保留 1.5 个角色正常跳跃高度的预生成空间。
- 玩法模型保存 `absoluteWorldY`、`maxAbsoluteWorldY` 和 `cameraAbsoluteY`；Cocos 节点只保存相对当前原点的渲染坐标。
- 当 `cameraAbsoluteY - renderOriginY >= 20000 units` 时执行一次 floating-origin rebasing：所有活动对象和相机的渲染坐标统一减去 20000，绝对坐标、分数、seed 和生成游标不变。
- rebasing 只能发生在物理子步结束、碰撞结算完成之后，并且必须对平台、怪物、危险物、道具、子弹和特效使用同一个偏移量，禁止单个对象单独重置。



### 6.4 安全区

- 游戏背景可以 cover 裁切。
- 玩法区域和所有可交互 UI 必须位于顶部微信胶囊下方和底部安全边界内。
- 左右不额外缩减通用玩法宽度。
- Canvas 必须绑定有效 UI Camera，UI Camera 使用正交投影。
- 不读取物理屏幕像素作为游戏世界坐标。



## 7. 平台系统



### 7.1 平台公共参数

平台碰撞只使用顶部水平碰撞面，不使用整块矩形作为角色落地面。平台有以下公共字段：

- platformId
- type
- worldX
- worldY
- width
- height = 18 units
- active
- collisionEnabled
- movementState
- consumed
- spawnSeed

角色水平碰撞盒与平台顶面有重叠，且角色向下穿越平台顶面时，才判定落地。

### 7.2 普通平台 Normal

- 每个平台只有一个 type。
- Moving、Shifting 是位置运动属性，不能与其他平台类型叠加。

- 平台被消耗、爆炸或离开回收区后，不得重新启用碰撞。
- 平台不受子弹伤害。

| ID  | X 中心 | Y 顶面 | 宽度  | 类型        |
| --- | ---- | ---- | --- | --------- |
| P0  | 375  | 80   | 220 | Normal    |
| P1  | 170  | 215  | 150 | Normal    |
| P2  | 400  | 350  | 145 | Normal    |
| P3  | 620  | 485  | 160 | Moving    |
| P4  | 420  | 625  | 140 | Normal    |
| P5  | 200  | 765  | 150 | Breakable |
| P6  | 440  | 900  | 150 | Moving    |
| P7  | 250  | 1035 | 140 | Normal    |


角色出生在 P0 中心上方 34 units，向上弹起。P0 至 P2 不生成怪物、UFO、黑洞、捕兽夹或爆炸平台。修正后的相邻平台中心水平距离最大为 240 units，P0 至 P7 的相邻高度差均为 135 units，进入同一套可达性求解器验证。

### 7.10 程序化生成约束

每次生成新平台时，必须先通过可达性检查，再允许进入场景。可达性检查不是只比较两个中心点，而是模拟角色碰撞盒、横向加速度、最大速度、屏幕穿越和移动平台落点窗口：

- 相邻平台顶面高度差：不低于 85 units，不高于 160 units。
- 普通反弹在 `fixedDelta = 1 / 120 s` 下的理论最大升高为 186.8 units；生成器保留至少 26.8 units 的竖直安全余量。
- 相邻平台中心水平距离不高于 240 units；最终检查必须使用“平台水平区间 + 角色碰撞盒半宽”的实际重叠区间。
- 求解器分别模拟左移、右移、无输入和中途换向四组控制包络；角色在向下运动时必须在目标顶面高度跨越窗口内与目标平台保持至少 0.12 秒连续重叠。
- Moving、Shifting 平台按预测落地时间采样其位置；如果整段运动没有 0.12 秒安全落地窗口，候选无效。
- 屏幕穿越可以作为横向路径的一部分，但不能让不可穿屏平台依赖“穿屏后的中心距离”绕过碰撞区间检查。
- 视野内至少有一块确定可落平台；连续两块平台都不能只靠飞行道具才能到达。
- 任何平台不得与黑洞核心、捕兽夹、UFO 光束出生点重叠。
- 任何平台不得被生成在屏幕左右边界外；移动/变位平台的全程包围盒也必须在边界内。
- 一次连续 5 块平台中至少 2 块为 Normal 或 Moving。
- 不允许连续 3 块都是 Breakable、Disappearing 或 Exploding。
- 最高连续难度段必须保留一条不依赖道具的通关路线。

生成器实现契约：

1. 使用 `seed` 派生 `platform/enemy/item/cosmetic` 四条独立伪随机流；每个候选记录 `seed`、`generatorCursor` 和前驱平台 ID，调试构建可以复现整局。
2. 先按当前高度的半开区间过滤已解锁类型，再按权重抽取；抽取后依次执行位置、碰撞、可达性、屏幕遮挡和路线连续性检查。
3. 单个候选最多重试 24 次；失败后先扩大平台宽度、降低高度差或替换为 Normal，再重新求解，不能直接把不可达候选放入场景。
4. 24 次仍失败时，生成“当前前驱平台上方 110–140 units、宽度 180–220 units、无危险附着”的 Normal 兜底平台，并记录 `generator-degraded` 事件。
5. 开发验收至少批量模拟 10,000 个 seed；任何 seed 出现无路可达、生成器死循环或越界都必须进入回归样本。

## 8. 怪物系统



### 8.1 共同规则

怪物是主动危险目标，也是可被玩家攻击的得分目标。所有怪物均遵循：

- 可以被子弹命中；
- 可以从头顶踩踏击杀；
- 从侧面或底部接触角色会导致失败；
- 子弹不能穿过怪物；
- 怪物不受平台子弹或其他怪物伤害；
- 怪物离开相机下方 420 units 后回收；
- 怪物不会因为屏幕左右边缘穿越；
- 怪物不发射普通敌方子弹，危险来自位置、移动和接触；
- 怪物被击杀后播放独立爆散效果，不能立即在同一位置重生。

### 8.6 怪物碰撞优先级

同一物理子步同时发生角色踩踏和身体接触时，按以下规则：

1. 先检查角色脚底是否进入怪物头部踩踏区。
2. 若是，怪物死亡，角色反弹，忽略该怪物身体碰撞。
3. 否则检查角色碰撞盒与怪物身体重叠。
4. 有重叠则以 monster-contact 失败。

同一子步同时有子弹命中和角色接触时：

1. 子弹先扣生命并销毁；
2. 角色仍有身体重叠时，仍以 monster-contact 失败；
3. 只有角色踩踏条件成立时才优先击杀并保留游戏。



## 9. 危险物系统



### 9.1 危险物共同规则

- 危险物不受子弹破坏。
- 危险物都必须有清晰的预警颜色、碰撞区域和失败原因。
- 危险物生成后不会因为屏幕穿越。
- 护盾只按各危险物的明确规则生效，不默认免疫全部内容。
- 失败状态一旦锁定，所有危险物只播放表现，不再重复结算。



### 9.2 UFO

UFO 的危险机制是光束锁定、吸附和绑架，不是普通接触伤害。


| 参数     | 数值               |
| ------ | ---------------- |
| 初始解锁   | 150 m            |
| 舱体宽度   | 116 units        |
| 光束宽度   | 86 units         |
| 水平移动速度 | 130 units/s      |
| 锁定时间   | 0.35 秒           |
| 吸附加速度  | 460 units/s²     |
| 连续光束时间 | 1.4 秒            |
| 击杀方式   | 不可击杀             |
| 子弹反馈   | 停顿 0.18 秒并取消当前锁定 |
| 击杀/中断分 | 20               |


UFO 行为：

1. UFO 在角色上方 160 至 300 units 处生成。
2. UFO 水平追踪角色，但最大移动速度为 130 units/s。
3. 光束进入角色横向范围时，先显示 0.35 秒锁定预警。
4. 角色在锁定预警期间离开光束宽度，锁定取消。
5. 锁定完成后，角色获得向光束中心的吸附速度。
6. 角色连续处于光束内 1.4 秒，进入 ufo-abduction 失败。
7. 角色离开光束超过 0.1 秒，清除本次吸附计时。
8. 子弹命中 UFO 舱体时，UFO 停顿 0.18 秒并清除锁定和吸附计时，但不能摧毁 UFO。
9. 角色不能踩踏 UFO。
10. 护盾可以阻止吸附和绑架计时，但 UFO 光束仍显示，护盾消耗前不会产生失败。



### 9.3 黑洞

黑洞的危险机制是从多个方向把角色拉向中心，进入核心区域后失败。


| 参数      | 数值                |
| ------- | ----------------- |
| 初始解锁    | 250 m             |
| 外圈半径    | 150 units         |
| 吸引开始半径  | 150 units         |
| 最大吸引加速度 | 700 units/s²      |
| 核心半径    | 28 units          |
| 核心失败原因  | black-hole        |
| 子弹效果    | 无                 |
| 护盾效果    | 免除进入核心失败，但不取消外圈吸引 |


黑洞吸引规则：

1. 角色进入外圈后，每个物理子步计算指向黑洞中心的向量。
2. 吸引加速度随距离减小而增强，达到 700 units/s² 后封顶。
3. 角色离开外圈后吸引立即清除。
4. 角色中心进入核心半径后失败。
5. 黑洞不因角色穿屏而改变位置。
6. 黑洞不能作为平台，也不能被角色踩踏。



### 9.4 捕兽夹 Bear Trap


| 参数   | 数值            |
| ---- | ------------- |
| 初始解锁 | 250 m         |
| 尺寸   | 54 × 24 units |
| 生成位置 | 平台顶面          |
| 触发方式 | 角色碰撞盒与夹口重叠    |
| 失败原因 | bear-trap     |
| 子弹效果 | 无             |
| 护盾效果 | 阻止本次失败并消耗护盾   |


捕兽夹只占用平台一部分宽度。生成器必须确保同一平台仍保留至少 76 units 的可落宽度。角色从平台下方穿过不会触发捕兽夹；角色落地后脚底或身体碰到夹口才触发。

### 9.5 爆炸平台作为危险物

爆炸平台既属于平台类型，也属于延迟危险物。爆炸倒计时、警告表现和 56 units 爆炸半径见第 7.7 节。爆炸本身只对仍处于范围内的角色造成 exploding-platform 失败，不会伤害怪物、UFO 或其他平台。

正式版本只允许使用以下失败原因：


| 值                  | 触发                 |
| ------------------ | ------------------ |
| fall               | 角色低于死亡线            |
| monster-contact    | 角色从侧面或底部撞到怪物       |
| ufo-abduction      | UFO 光束连续绑架达到 1.4 秒 |
| black-hole         | 角色中心进入黑洞核心         |
| bear-trap          | 角色接触捕兽夹            |
| exploding-platform | 角色在爆炸平台爆炸时处于爆炸半径   |




## 10. 道具系统



### 10.1 全局碰撞和道具交互矩阵

同一物理子步内按以下顺序处理，避免飞行道具、踩踏、护盾和危险物出现平台实现各自判定的问题：

1. `Failing`、`ResurrectPrompt`、`Resurrecting`、`Result` 或 `Error` 状态不再结算新的玩法碰撞。
2. 先处理平台落地；只有平台 `collisionEnabled` 且当前道具允许平台碰撞时才执行。Breakable 的踩踏会关闭碰撞且不反弹，其他可落平台先产生一次反弹。
3. 再处理怪物头部踩踏；踩踏成功优先于同一怪物的身体接触，但子弹命中不会取消身体接触失败。
4. 再处理危险事件，优先级固定为 `UFO 光束锁定/绑架 → 黑洞核心 → 捕兽夹 → 爆炸半径 → 怪物身体接触`。同一子步若有多个可抵挡事件，护盾只消耗一次，剩余事件按护盾消失后的规则继续检查。
5. 最后检查不可抵挡的 `fall`；进入死亡线即失败，不因护盾或飞行道具改变。


| 交互对象                      | Normal/Moving/Disappearing/Shifting | Breakable/Exploding | 怪物                 | UFO/黑洞             | 捕兽夹          |
| ------------------------- | ----------------------------------- | ------------------- | ------------------ | ------------------ | ------------ |
| 普通状态                      | 正常落地/反弹                             | 按平台自身一次性规则          | 可踩踏；身体接触失败         | 按危险物规则             | 接触失败         |
| Jetpack/Rocket/Head Start | 穿过，不触发落地                            | 穿过，不触发平台倒计时或爆炸      | 仍执行怪物接触/踩踏规则，不提供无敌 | 仍受光束和黑洞影响          | 仍检查触发体，护盾可抵挡 |
| Propeller Hat             | 正常保留平台碰撞                            | 按平台自身规则             | 仍执行怪物接触/踩踏规则       | 仍受光束和黑洞影响          | 仍检查触发体       |
| Shield                    | 不改变平台碰撞                             | 不改变平台碰撞             | 抵挡一次身体接触并消耗        | UFO/黑洞按各自条目清除锁定或弹离 | 抵挡一次并弹离      |


Jetpack、Rocket 和 Head Start 只改变竖直运动及平台碰撞，不是全局无敌；这条是本项目的明确自定义规则。护盾抵挡黑洞核心时不清除外圈吸引，只在核心失败事件上消耗。

### 10.2 道具公共规则

- 道具是漂浮在世界中的可收集物，不作为平台承接面。
- 角色碰撞盒与道具碰撞圆重叠时立即拾取。
- 子弹穿过道具，不会触发拾取。
- 道具拾取后从场景中移除，不能重复拾取。
- 每种道具都有固定图标、颜色、音效和 HUD 状态。
- 飞行类道具互斥；护盾独立存在；一次性弹跳道具可处于待触发状态。
- Shield 使用独立透明覆盖 Sprite，运行时跟随玩家视觉根节点，可与基础图或任一飞行道具组合图同时显示，不改变角色碰撞盒。
- 角色已经拥有同类飞行道具时再次拾取，按该道具的“刷新规则”处理。

### 10.8 飞行道具互斥和刷新

- Jetpack、Propeller Hat、Rocket 共用 flightPower 状态。

- 已有一种飞行道具时拾取另一种，立即结束旧状态并激活新状态。
- 拾取同一种飞行道具，计时刷新为该道具的完整持续时间，不叠加倍增。
- 飞行道具结束后回到普通重力和平台碰撞。
- 被 UFO、黑洞或其他危险物影响时，飞行道具不自动取消。
- 飞行道具期间仍可点击单发或长按连发；这是本项目明确保留的控制规则。

| 参数   | 数值                           |

## 13. 失败、复活和结算



### 13.1 失败锁定

任何失败条件触发时：

1. 只有 `Playing` 状态可以从 `tryFail(reason)` 进入失败；`failureLocked` 或 `settlementCommitted` 为真时直接返回。
2. 设置 `failureLocked = true`，保存 `failureReason`。
3. 保存不可变 `failureSnapshot`：`absolutePlayerPosition`、`absoluteCameraY`、`maxAbsoluteWorldY`、`lastSafePlatformId`、当前分数、击杀数和道具剩余时间。
4. 状态切换为 `Failing`，停止输入对物理状态的影响、生成器、平台/怪物/危险物更新和新子弹生成。
5. 当前已有子弹和特效只允许播放结束表现，不再产生新碰撞结算；碰撞回调必须检查 `failureLocked`。
6. 进入 0.35 秒失败表现缓冲，计时只由状态机推进一次。
7. 缓冲结束后，若本局仍有一次复活机会则进入 `ResurrectPrompt`，否则一次性固化结果并进入 `Result`。

失败状态机只允许以下转移：

`Playing → Failing → ResurrectPrompt → Resurrecting → Playing`；
`Playing → Failing → Result`；`ResurrectPrompt → Result`。

`Failing`、`Resurrecting` 和 `Result` 都是幂等状态；重复点击、重复回调、重复广告结果（未来接入时）不能重复恢复、重复结算或重复写档。

### 13.2 失败表现

- fall：角色下坠，镜头短暂跟随，背景速度降低；
- monster-contact：角色被击退，怪物保留在场景中；
- ufo-abduction：光束收束，角色向上消散；
- black-hole：角色缩小并向黑洞中心收束；
- bear-trap：夹口闭合并播放红色闪光；
- exploding-platform：平台碎裂，角色被冲击波推出。

失败表现不得重新调用一次失败逻辑。

### 13.3 复活面板

当 availableResurrect > 0 且本局未复活时，显示：

- 失败原因；
- 当前分数；
- 当前高度；
- “使用复活”；
- “结束本局”；
- 复活后 3 秒护盾说明。

如果没有复活库存，不显示误导性的免费复活按钮。

点击“使用复活”后：

1. 立即锁定面板按钮并消耗本局复活机会，进入 `Resurrecting`；取消或结束本局则只进入 `Result`。
2. 从 `failureSnapshot.lastSafePlatformId` 开始，重新验证平台仍 `active && collisionEnabled && !consumed`，且其上方和左右 160 units 内没有黑洞核心、UFO 光束、捕兽夹、爆炸计时或怪物身体。
3. 若原平台不安全，向下按绝对高度寻找最近的有效平台；最多检查 8 块。找不到时进入 `Result` 并记录 `resurrect-fallback`，不得把角色放在无平台空中。
4. 回收复活点附近的敌人、危险物和旧子弹，清除失败表现；将角色放到安全平台中心上方 34 units，设置 `velocityY = 820`，重新锚定相机并恢复生成游标。
5. 添加 3.0 秒 Shield，清除 `failureLocked`，重置输入指针和瞄准点；生成、物理、计分和碰撞恢复后才切回 `Playing`。
6. 复活不回退 `maxAbsoluteWorldY`、已获得分数或击杀统计，也不能再次触发复活。



### 13.4 结算面板

Result 必须显示：

- 本局分数；
- 最高高度；
- 击杀数；
- 失败原因的中文文案；
- 是否刷新最高分；
- “再来一局”；
- “返回大厅”；
- “分享成绩”（微信端调用注入的 Platform 分享能力，浏览器隐藏或显示开发占位）。

结算面板的业务行为由公共契约提供，正式视觉由本游戏 Bundle 自己实现。

## 14. UI 和交互



### 14.1 Playing HUD

屏幕常驻显示，布局以已确认效果图为基线并按安全区动态定位：

- 左上纸片卡：分数；其下方同组纸片卡：当前最高高度；
- 顶部中间：暂停按钮；
- 右上纸片条：护盾、当前飞行道具和剩余时间；空间不足时折叠为图标和数字，不移入玩法落点区；
- 角色附近：短暂显示拾取的道具名称；
- 传感器异常时：顶部显示“请保持手机竖直并允许重力感应”。

HUD 必须避让微信胶囊和底部安全区。HUD 不得挡住角色脚下 1.2 个跳跃高度范围内的关键落点。

HUD 不使用右下角固定栏作为正式布局；效果图中的顶部纸片层级、留白和暂停位置优先于旧方案的四角布局。所有纸片卡均为正面平面 Sprite，窄白边和柔和落影可以作为透明素材的预烘焙效果保留，不使用实时投影、厚重阴影或立体厚度。

### 14.2 首次引导

首次进入且没有完成传感器校准时显示三步引导：

1. “左右倾斜手机，控制角色移动”；
2. “点击发射一架纸飞机，按住会持续发射”；
3. “踩怪物、躲开光束、黑洞和捕兽夹”。

引导必须明确写出“拖动不会移动角色”或用等价视觉说明，避免玩家误解输入方式。

### 14.3 规则面板

规则页至少分为四组：

- 控制：重力感应、手指瞄准、点击单发/长按连发、左右穿屏；
- 平台：普通、移动、断裂、消失、变位、爆炸；
- 怪物和危险：普通怪、大型怪、悬浮怪、UFO、黑洞、捕兽夹；
- 道具：弹簧、蹦床、喷气背包、螺旋桨帽、火箭、护盾。

规则页中的图标、颜色、材质和动效属于本游戏独立视觉资产，不复用其他游戏正式资源。

### 14.4 触摸层级

从上到下的输入优先级：

1. 系统安全区和微信胶囊：不接收游戏输入；
2. 暂停、重开、返回等 UI 按钮：只处理 UI；
3. 规则、复活、结算面板：只处理面板；
4. 游戏玩法区：作为瞄准和攻击指针；
5. 玩法区的点击：冷却结束时按下立即单发；冷却期间点击不排队；玩法区的拖动：只更新瞄准位置并保持连发，不产生移动。



### 14.5 可读性和非颜色提示

- 平台类型不能只依靠颜色区分：每类平台还必须有独立的线稿符号、边缘纹样或形状差异。
- 怪物、道具和危险物都必须同时提供轮廓、图形符号和碰撞反馈；色弱模式下仍能区分可落平台、危险物和可拾取物。
- 纸飞机、UFO 光束、黑洞核心和捕兽夹的碰撞边界必须比背景至少保持一个固定对比度等级，并在设置/规则页提供图形说明。



## 15. 动画、特效和声音反馈



### 15.1 角色

- 正式运行时交付一张全身基础 Sprite、Rocket/Jetpack/Propeller Hat 各一张完整“主角＋道具”组合 Sprite，以及一张独立透明 Shield Overlay。所有图片姿势固定为自然站立待机：身体保持直立、双腿自然下垂并略微分开，双脚最低点贴齐图片底部基线；头部/发型、脸部、躯干、围巾、双臂轮廓、比例和配色必须与参考图保持一致。
- 无道具时使用基础 Sprite，使用 Rocket、Jetpack 或 Propeller Hat 时切换对应组合 Sprite；使用 Shield 时不切换主角图，而是把 Shield Overlay 作为玩家视觉根节点的独立子节点叠加。Rocket 与 Jetpack 的静态本体都背在主角背部，Propeller Hat 位于头顶；Shield Overlay 环绕身体并与基础图、三张组合图共用玩家中心、局部坐标和碰撞盒参考线，不改变碰撞盒。

- Spring、Trampoline、Head Start 的待触发或助推表现使用脚下独立提示/冲刺特效；Resurrect 使用角色周围的复活特效；这些表现不改变基础图或组合图的身体姿势。
- 允许叠加独立的铅笔擦线或残影特效，但这些特效不能烘进基础图或组合图。
- 射击时主角图不转向、不改变手臂姿势；纸飞机从固定发射点生成，朝当前手指方向飞行，瞄准点和飞行轨迹均为独立资源。
- 被护盾抵挡、失败和复活播放角色外部的护盾、压痕、失败或复活特效；护盾本体使用独立 Shield Overlay，护盾脉冲和格挡反馈继续使用独立 VFX，不得生成另一套身体动作姿势。



### 15.2 平台

- Moving：平台边缘有重复的铅笔方向线；
- Breakable：被踩前出现纸面裂纹预警；
- Disappearing：剩余 0.15 秒快速褪色并露出底层纸张；
- Shifting：切换节点时显示平面翻页线稿轨迹，不产生真实翻页或立体旋转；
- Exploding：落地后红色蜡笔环倒计时，爆炸时纸片向外散开。



### 15.3 怪物和危险物

- 怪物受伤显示短促铅笔擦痕或短暂反色；
- 怪物死亡只触发一次纸屑散开；
- UFO 锁定时使用窄红色蜡笔框，吸附时使用紫色纸带束缚线；
- 黑洞外圈使用低频旋转的平面剪纸环，核心不可与背景同色；
- 捕兽夹在触发前保持清晰的红色纸板夹口；
- 护盾状态必须有独立纸环轮廓，不能只依靠 HUD 文本。



### 15.4 声音

本游戏需要独立的声音方向：

- BGM：低密度铅笔轻敲、纸张摩擦和木质小敲击循环；
- 普通落地：短促纸卡回弹和软纸面落点；
- 强力道具：轻快的彩笔上行音阶；
- 连续射击：低音量纸飞机掠过声，不遮挡危险提示；
- 怪物受伤和击杀：区分轻击和重击；
- UFO 锁定：纸带绷紧般的窄频预警；
- 黑洞：低频纸页卷入声；
- 失败：根据失败类型有不同尾音。

声音不能直接复用大厅或其他小游戏的正式文件。

## 16. 存档和版本



### 16.1 数据命名空间

本游戏只能读写自己的命名空间：

- 根存档：由公共存档服务管理；
- 游戏存档：`doodle-jump`，与 Bundle/Manifest 的 gameId 保持一致；
- 禁止读写其他小游戏命名空间；
- 禁止因本游戏隐藏、回滚或字段不识别而清空根存档；旧规划中的 `doodleJump` 只作为迁移别名读取，迁移成功后写入 `doodle-jump`，不删除其他游戏数据。



### 16.2 v2 数据结构

公共 `StorageService` 要求每个游戏数据符合 `GameSaveData`：

```ts
{
  dataVersion: 2,
  playCount: number,
  highScore: number,
  lastPlayedAt: number,
  custom: {
    gameDataVersion: 2,
    bestHeightMeters: number,
    bestKillCount: number,
    totalShots: number,
    totalKills: number,
    sensorInvert: boolean,
    sensorSensitivity: 0.75 | 1 | 1.25,
    headStartCount: number,
    resurrectCount: number,
    settingsVersion: number,
  },
}
```

字段归属固定：公共 `highScore` 就是本游戏 `bestScore`，公共 `playCount` 就是 `totalRuns`，不得在 `custom` 再维护一份可冲突的 `totalRuns`；`lastPlayedAt` 使用毫秒时间戳。所有未知 `custom` 字段必须在读改写时原样保留。

默认值：`highScore = 0`、`playCount = 0`、`bestHeightMeters = 0`、`bestKillCount = 0`、`totalShots = 0`、`totalKills = 0`、`sensorInvert = false`、`sensorSensitivity = 1`、`headStartCount = 0`、`resurrectCount = 0`、`settingsVersion = 1`。

### 16.3 迁移

旧版本迁移到 v2 时：

1. 先备份原始存档字符串。
2. 优先读取 `doodle-jump`，不存在时才读取旧规划别名 `doodleJump`；不把别名数据复制到其他游戏。
3. 将旧 `bestScore`/`highScore` 映射到公共 `highScore`，将 `runCount`/`playCount` 映射到公共 `playCount`。
4. 将 `bestHeight` 映射到 `custom.bestHeightMeters`；无法判断单位时按旧版字段说明处理，不擅自乘除。
5. 将旧游戏字段放入 `custom`，保留未知字段，不直接删除；为本次数据增加 `gameDataVersion = 2`。
6. 新增字段使用默认值，并验证公共 `dataVersion/playCount/highScore/lastPlayedAt/custom` 类型和范围。
7. 通过当前 `GameSaveData` 结构校验后才覆盖主存档；写入后调用同步 `flush()`。
8. 迁移失败时恢复安全默认值，并保留原始备份；不能因为单个游戏迁移失败重置根存档。

旧版霓虹主题字段只作为历史数据保留，当前 v2 数据结构不能重新加载霓虹视觉资源。

### 16.4 当前局不写历史

v2.5 不持久化 `activeRound`，因此不支持跨进程/跨会话恢复中途局面。Playing 期间可以把当前局保存在内存的 `failureSnapshot`，但不得把未结算的临时分数写入 `highScore` 或 `custom.bestHeightMeters`。暂停、微信 hide、结算、退出和重开时先固化已完成的历史字段并 `flush()`；进程崩溃或加载失败时当前局按中断处理，不产生最高记录。未来若要支持 activeRound，必须新增游戏数据版本，定义 seed、生成游标、绝对坐标、道具计时和状态迁移后才能实现。

## 18. 技术边界和实现要求



### 18.1 Bundle 和入口

- Bundle：game-doodle-jump
- 场景：assets/games/doodle-jump/scenes/DoodleJump.scene
- 入口组件：DoodleJumpGame
- 资源目录：assets/games/doodle-jump
- 由 GameManifest 注册，不改写大厅加载流程。

大厅只依赖游戏清单和大厅展示副本，不导入 DoodleJumpGame、游戏场景或游戏内正式资源。

### 18.2 生命周期

DoodleJumpGame 必须实现统一 MiniGame 生命周期：

- initialize(context)
- begin()
- pause()
- resume()
- restart()
- dispose()

initialize 只建立引用和配置，不开始世界推进；begin 才开始传感器使用、生成世界和游戏计时。

### 18.3 平台和公共服务

小游戏只通过 `MiniGameContext.services` 使用仓库当前已经注入的服务键：

```ts
interface DoodleJumpServices {
  platform: Platform;
  audio: AudioService;
  feedback: FeedbackService;
  storage: StorageService;
  analytics: AnalyticsService;
  ads: AdService;
  deviceTier: DevicePerformanceTier;
}
```

- `platform`：加速度计、设备能力、安全区和分享；
- `audio` / `feedback`：独立 Bundle 音频注册和反馈播放；
- `storage`：通过 `getGameData('doodle-jump')` / `writeGameData()` 读写本游戏数据；
- `analytics`：上报本节事件，射击事件按批次冲刷；
+ `ads`：当前 v2.5 的复活只使用库存，不注册广告位；未来接入必须先增加配置和 placement，再经过公共 `AdService`；
- `deviceTier`：选择粒子、纸屑和特效质量。

触摸、鼠标和键盘回退由游戏 Bundle 内的 `DoodleJumpInputController` 管理，不虚构公共 `InputService`；暂停、前后台、广告和退出通过 `MiniGameContext.requestPause/requestExit/requestRestart/requestLobby` 及运行层状态机管理，不虚构 `AppStateService`。Bundle 加载、场景切换、资源引用追踪和释放由运行层/`AssetService` 管理，游戏不从 Context 直接取 `AssetService`。

不得在游戏逻辑中直接调用 `wx.*`、切场景、卸载 Bundle、创建全局单例或自行定义全局服务。小游戏可以拥有 Bundle 内部的输入控制器、生成器、状态机和视图 Presenter，但它们不得注册为全局服务。

- 平台：Normal、Moving、Breakable、Disappearing、Shifting、Exploding 的正常/预警/消耗状态；
- 怪物和危险物：Small、Large、Hover、UFO、光束、Black Hole、Bear Trap 的状态帧和碰撞辅助图；

- UI：大厅展示副本、游戏图标、HUD 纸片卡、暂停、规则、传感器 Error、复活、结算、分享和返回大厅状态；

资产验收必须包含正常、加载、空、禁用、失败和资源缺失错误态；不能把整张效果图直接当运行时界面，也不能引用大厅或其他小游戏的正式皮肤。

## 19. 性能预算

在中低端微信设备上，正式版本必须满足：


| 项目         | 预算                                      |
| ---------- | --------------------------------------- |
| 目标帧率       | 60 FPS                                  |
| 单帧物理子步     | 最多 4                                    |
| 活动平台       | 最多 28                                   |
| 活动普通怪物     | 最多 3                                    |
| 活动 UFO     | 最多 2                                    |
| 活动黑洞       | 最多 2                                    |
| 活动捕兽夹      | 最多 2                                    |
| 活动道具       | 最多 5                                    |
| 子弹对象池软目标   | 32，不是玩法上限                               |
| 单屏粒子发射器    | 最多 18                                   |
| 单个怪物材质实例   | 1 个共享材质                                 |
| 活动渲染节点     | 最多 180，离屏对象立即回收                         |
| Draw Call  | 中低档真机稳定场景 P95 ≤ 45                      |
| 主循环帧耗时     | 中低档真机 P95 ≤ 18 ms，连续超过 33.4 ms 不得超过 3 帧 |
| Bundle 冷启动 | 本地包从进入加载到 Ready ≤ 3 s，失败必须可重试           |
| 运行时纹理峰值    | 游戏 Bundle ≤ 24 MB，按实际设备档位记录             |
| 60 秒压力测试   | 不出现未回收纸飞机、计时器、监听或持续增长的节点数               |
| 单局不限制子弹总数  | 允许，按生命周期回收                              |


如果同时存在的子弹多于 32 个，必须继续支持发射和碰撞；可通过回收离屏子弹、批量渲染或动态扩容保障性能，但不得静默丢弃玩家已经触发的射击。长按 10 秒和多次连续点击必须纳入压力测试；视觉纸屑、轨迹和命中特效可以按 `deviceTier` 降级，但不能降级输入、碰撞或得分。

性能验收还要记录 P50/P95 帧耗时、Draw Call、节点峰值、纹理峰值、首次加载时间、GC/内存峰值，并连续执行“进入游戏 → 退出大厅”20 次，确认监听、计时器、Bundle 引用和音频实例没有单调增长。

## 21. 固定文案

- 弹簧：下一次落地强力弹跳
- 蹦床：下一次落地超强弹跳
- 喷气背包：短时间向上飞行
- 螺旋桨帽：降低重力并持续上升
- 火箭：高速向上冲刺
- 护盾：抵挡一次危险



## 22. 版本冻结结论

v2.5 的玩法与视觉基线如下：

1. 角色横向移动只使用重力感应，触摸拖动不移动角色。
2. 触摸只负责瞄准和射击：冷却结束时点击立即单发，按住则冷却结束后首发并每 120 毫秒连发；点击和长按共享 120ms 全局冷却，无玩法层数量上限；抬手、取消、暂停或失败立即停止。
3. 子弹朝当前手指方向发射，手指移动会影响后续子弹方向。
4. 角色具备左右屏幕穿越能力，其他对象不穿屏。
5. 平台完整包含 Normal、Moving、Breakable、Disappearing、Shifting、Exploding 六类。
6. 怪物完整包含 Small、Large、Hover 三类，均可踩踏或射击。
7. 危险物完整包含 UFO、Black Hole、Bear Trap，以及爆炸平台的延迟爆炸机制。
8. 道具完整包含 Spring、Trampoline、Jetpack、Propeller Hat、Rocket、Shield，并保留 Head Start 和 Resurrect 兼容位。
9. 视觉采用纸片跃层·平面涂鸦主题，以 `art_sources/涂鸦跃层/flat-paper-ui-reference-v1.png` 为已确认效果图基线；所有正式资源独立归属本游戏。
10. 实现前必须同步更新 docs/common/ARCHITECTURE.md，记录新 Bundle、传感器依赖、公共服务键、存档 v2、生命周期和回滚方式。
11. 主角使用一张固定自然站立基础全身 Sprite，以及 Rocket、Jetpack、Propeller Hat 各自独立的完整“主角＋道具”组合 Sprite；Shield 使用独立透明覆盖 Sprite，运行时叠加到基础图或任一飞行道具组合图上。所有图片的头部/发型、脸部、躯干、围巾、双臂轮廓、比例和配色必须与参考图一致；不制作“主角＋护盾”组合图。跳跃、射击、受击、失败和复活仍只使用位置与独立特效表现，不制作动作姿势图。

这份文档是后续场景、脚本、配置、素材、UI、测试和验收的唯一玩法依据。
