# 《涂鸦跃层》图片素材生成提示词

> 版本：v1.3
> 状态：提示词待人工生成、清理、验收和来源记录；本文不代表任何图片已经生成或获得发布许可。  
> 对应玩法规划：docs/games/doodle-jump/DOODLE_JUMP_GAMEPLAY_SPEC.md v2.5  
> 资源归属：所有正式图片进入 game-doodle-jump Bundle。

本文只覆盖图片、Sprite、图集、UI 和视觉特效提示词，不覆盖音频。

本项目的固定方案如下：

- 主角需要两套基础姿势素材：游戏运行时沿用原型参考图姿势的跳跃图，以及有效踩中平台时短暂显示的自然站立落地图。游戏没有 Ready 状态，开局直接使用跳跃图起跳。
- Rocket、Jetpack、Propeller Hat 的完整“主角＋道具”组合 Sprite 全部沿用游戏运行时原型图姿势，不改成自然站立姿势；Shield 使用独立透明 Shield Overlay，运行时叠加到原型主角图或任一飞行道具组合图上。
- 除独立落地帧外，跳跃、下落、射击、受击、失败、复活不制作新的动作帧、朝向帧或状态姿势图；运行时原型图、落地图和三张道具组合图各自固定，不在状态之间额外变形。
- 组合图只包含静态的原型姿势主角和 Rocket、Jetpack、Propeller Hat 本体；Shield Overlay 只包含护盾环本体；火箭、喷气、纸屑、气流、旋转线、拖尾和护盾脉冲继续作为分开的独立特效。
- 纸飞机是独立投射物，可由运行时旋转 360 度；瞄准点和拖尾独立于纸飞机。

## 0. 使用说明

### 0.1 视觉参考

优先参考：

1. [平面纸片 UI 参考图](../../../art_sources/涂鸦跃层/flat-paper-ui-reference-v1.png)
2. [修正版素材总览参考图](../../../art_sources/涂鸦跃层/game-asset-overview-v2.png)

第一张图用于锁定纸张、线稿、色彩、角色和界面的视觉方向。第二张图只用于核对素材分类和数量，不作为主要风格参考。不要使用已废弃的 game-asset-overview-v1.png。

如果图片生成工具不能读取本地路径，应先手动上传上述参考图，再使用对应提示词。

### 0.2 统一风格锁定

    严格匹配参考图的“纸片跃层·平面涂鸦”视觉风格：纯 2D 正交视角、正面平面纸片、暖白稿纸色、低饱和彩笔平涂、细且略微不规则的铅笔轮廓、窄白色纸边、参考图同款的低对比软边偏移落影、轻微纸张纹理和清晰可读的游戏轮廓。角色上半身必须沿用参考图中的头部/发型、脸部、躯干、围巾、双臂轮廓、比例和配色，不得重新设计。落影必须是透明素材自身的预烘焙贴纸落影，不能形成纸张厚度、透视、硬边投影或立体纸艺。整体轻盈、手绘、简洁，适合微信小游戏的小尺寸显示。

    禁止：3D、透视、立体建模、实时或强烈场景投影、金属材质、玻璃材质、霓虹发光、渐变高光、厚重硬白边、文字、水印、Logo、复杂背景、其他游戏或原版 Doodle Jump 的可识别素材。

### 0.3 通用输出约束

- 独立角色、道具、特效和图标优先输出透明背景 PNG。
- 图集类提示词必须明确“规则网格、单元格间距一致、每格只放一个完整素材、不得跨格”。
- UI 背景、全屏背景和大厅封面按指定比例输出；运行时文字、数字、按钮文案和动态计时器不要烘焙进图片。
- 生成后必须人工清理透明边缘、重绘错误线稿、统一锚点和尺寸，再进入 Cocos 资源目录。
- 每张正式图片记录生成平台、模型、生成日期、完整提示词、输出版本、来源和许可状态。
- 若一条提示词要求多个单元格，最终应按单元格裁切为独立 Sprite 或 SpriteFrame；纸片实体的窄白边与柔和落影必须随透明边缘一并保留，不能在裁切时抹掉。

## 18. 生成与验收顺序

### 18.1 推荐生成顺序

1. 平台落地自然站立帧。
2. 游戏运行时原型姿势全身图。
3. 纸飞机、瞄准点和拖尾。
4. 主角使用 Rocket、Jetpack、Propeller Hat 的三张原型姿势组合图和 Shield Overlay。
5. 8 种道具拾取物与 HUD 图标。
6. 六种平台基础图和平台状态特效。
7. 三类敌人。
8. UFO、黑洞和捕兽夹危险物。
9. 道具运动特效、通用反馈特效和失败特效。
10. 四套全屏背景和分主题透明装饰。
11. HUD、弹窗面板和教程插图。
12. 大厅封面与游戏图标。

### 18.2 每张图的验收清单

- 是否保持纯 2D、正交、平面纸片和彩笔平涂？
- 是否出现了不允许的 3D、透视、厚度、强烈实时投影、金属、玻璃或霓虹？实体纸片是否保留了参考图同款低对比、软边、轻微偏移的预烘焙落影？
- 是否误生成文字、数字、Logo、水印或无法清理的伪文字？
- 透明背景的边缘是否干净，是否存在白底、黑底或半透明脏边？
- 图集单元格是否互不越界，素材是否可以独立裁切？
- 落地站立图是否只用于有效落地瞬间，双脚最低点是否落在底部基准线并能自然贴合平台可见上沿？
- player_runtime_prototype.png 与三张组合图是否严格保持原型参考图姿势，是否没有被改成自然站立姿势？
- Rocket、Jetpack、Propeller Hat 组合图是否都是原型姿势的完整主角＋道具图片，Shield Overlay 是否是独立透明护盾环且没有把主角烘焙进去？
- Shield Overlay 是否与运行时原型图和三张组合图共用玩家中心、局部挂载基准和碰撞盒参考线，且不会遮挡主角主要轮廓？
- 火箭和喷气背包的纸屑、火焰、气流和拖尾是否向下，并且与组合图中的静态道具本体分离？护盾脉冲和螺旋桨旋转线是否也保持独立？
- 纸飞机是否没有自带拖尾，是否预留运行时 360 度旋转空间？
- UI 是否没有烘焙动态文案，面板内容区是否足够宽，是否适合安全区？
- 在微信小游戏的手机小尺寸下，角色、道具、平台和危险物是否能快速区分？

### 18.3 入库前处理

生成结果只能作为原始候选。入库前需要：

- 人工擦除多余对象、伪文字、背景和生成错误。
- 统一 Sprite 尺寸、锚点、透明边距和像素密度。
- 为图集拆分 SpriteFrame，并检查每格的裁切边界。
- 在 Cocos Creator 3.8.8 预览中检查落地站立图、运行时原型图与飞行道具组合图切换、Shield Overlay 叠加、纸飞机射击、纸屑向下喷出、拖尾、平台碰撞、HUD 和弹窗。
- 将生成平台、模型、日期、提示词、候选图、最终图、清理记录和许可状态写入素材来源记录。

### 18.4 与玩法规划的对应关系

最终资源清单和使用位置以 [DOODLE_JUMP_GAMEPLAY_SPEC.md](DOODLE_JUMP_GAMEPLAY_SPEC.md) 的 18.6 节为准；若提示词与玩法规划发生冲突，应先修订玩法规划和视觉规范，再生成正式素材。
