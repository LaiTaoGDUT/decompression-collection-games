# 《涂鸦跃层》开发计划

## 0. 计划目标

本文把 [DOODLE_JUMP_GAMEPLAY_SPEC.md](DOODLE_JUMP_GAMEPLAY_SPEC.md) 拆成可实施、可手动验证、可回归的开发阶段。玩法规格仍是规则和数值的唯一依据；本文只定义实施顺序、交付物和阶段门禁，不重复定义玩法。

项目固定使用 Cocos Creator 3.8.8，目标平台为微信小游戏；不执行开发侧浏览器冒烟检查，浏览器键盘回退只作为最终手测清单中的可选环境。游戏 ID 为 `doodle-jump`，Asset Bundle 为 `game-doodle-jump`，入口场景为 `assets/games/doodle-jump/scenes/DoodleJump.scene`，入口组件为 `DoodleJumpGame`。

开发采用纵向切片：先完成一局最小可玩闭环，再增加内容广度。任何阶段都不得用临时逻辑破坏 `MiniGame` 生命周期、应用状态机、独立 Bundle、独立存档命名空间和资源释放边界。

### 当前开发进度（2026-08-29）

- 已完成 M0 工程接入：Manifest、独立 Bundle/微信分包、`DoodleJump.scene`、显式 Canvas/UI Camera 绑定、入口生命周期和基础错误态；
- 已完成 M1 核心原型代码：传感器样本校准、键盘开发回退、固定步长模拟、P0–P7、自动弹跳、相机上移、角色左右穿屏、首指针 360° 瞄准、200ms 全局冷却、点击/长按发射和无硬上限纸飞机池；
- 已提前完成掉落失败的复活主链：开关关闭直接结算；开启后免费一次、广告一次、第三次结算；未配置广告时第二次直接成功；安全平台只向上查找并可确定性创建；
- 已接入纸张背景、站立角色、Normal 平台、纸飞机、瞄准点和大厅图标/封面首批正式图片；其余类型仍待后续阶段接入；
- 已通过 Cocos 3.8.8 自带 TypeScript 编译器和 Bundle 边界检查；画面与交互尚未手测，不标记为玩法验收通过。

### M1 收口状态（2026-08-30）

- M1 收口时曾将 `generation.enabled` 设为 `false`，只运行固定 P0–P7；进入阶段 4 后交付配置已重新开启持续生成；如需单独回归 M1，应在测试前临时关闭该开关；
- HUD 正常游玩时只保留高度和暂停两个主要入口，标题/状态提示在 Playing 隐藏；背景按 cover 等比铺满，覆盖层按顶部胶囊与底部安全区的可用高度等比缩放；
- 补齐显式鼠标按下/移动/抬起攻击回退，同时保留触摸优先和 500ms 去重；按钮从 MOUSE_DOWN 开始拦截，避免点击暂停等 UI 时误射；
- 调试 HUD 显示动态节点、活动/池化纸飞机、监听和计时器数量以及丢帧累计，用于执行 M1 生命周期与长按射击手测；
- M1 的实现边界已冻结；当前只推进阶段 4，不进入阶段 5 的怪物开发。

### 阶段 4 开发状态（2026-08-30）

- 已接入 platform/enemy/item/cosmetic 四条独立伪随机流；当前阶段仅消费 platform 流，其他游标保持为 0，后续内容接入不会改变既有平台序列；
- 已启用带角色加速度、最大速度、碰撞盒、左右穿屏和动态平台位置预测的 1/120 秒候选可达性求解；控制包络覆盖无输入、25%/50%/75%/100% 双向倾斜和中途换向，避免只模拟满幅输入导致误判；候选最多尝试 24 次，后半程逐步降差并切换 Normal，最终生成带 `degraded=true` 记录的安全平台；
- 已将活动平台预算提高到 64、视口上方预生成缓冲提高到 620 units，并保留相机下方 420 units 回收，为每段最多 3 块插入平台保留生成余量，避免平台预算先耗尽后视口上半部延迟出图；
- 已提供 `seedOverride`、`singleStep`、`showRouteDebug`、`forceDegradedFallback` 和失败现场 JSON 导出入口；代表性配置见 `DOODLE_JUMP_STAGE4_SEEDS.md`；
- 已结合原版视频画面和开源实现再次重构生成器：每个高度只生成一块主路平台，两块主路间按区间容量插入 0–3 块可选平台，六种平台类型均可进入插入池；所有相邻平台顶面至少相隔 60 units，且插入平台不参与主路可达性前提；多数普通主路拒绝零输入可达路线，每 10 层提供安全恢复层，调研记录见 `DOODLE_JUMP_PLATFORM_GENERATION_RESEARCH.md`；
- 普通反弹和复活起跳速度设为 940 units/s，重力调整为 -1590 units/s²，理论最高升高约 277.9 units，保持原跳跃高度但放慢完整升降节奏；配置解析会断言理论峰值必须比主路间距高 10～80 units；平台纵向最短间隔固定为 60 units，所有平台间距只能是该值的整数倍，主路间距固定为 `4 × 60 = 240 units`，固定 P0–P7 同样使用 240 units；
- 生成 Normal 主路平台和插入平台的宽度整体缩短约 5～15 units；普通主路范围为约 130～210 units（随高度收窄），插入 Normal 为 125～210 units，恢复层仍保留 185～215 units 的较宽范围；
- 固定开局段禁止在 P0 与 P1 之间插入任何平台；P1 固定偏离屏幕中心，并由初始化校验断言零水平输入不可落地，避免角色开局自动连续上升；插入平台从 P1→P2 区间开始；
- 镜头连续上升跟随的角色纵向目标线降到可见高度 35%；角色图向下校准 4 units，使最低脚点压住平台上沿；每次有效落地播放专用 `landing-paper-debris-v3` 手绘纸屑爆散图，在脚下短促展开并于 0.42 秒内淡出；
- P0 仍使用一整块稳定碰撞面，但画面由 5 段宽度不一的平台拼满 750 设计宽度；六类平台改为各自带预烘焙透明软影的 RGBA 图片，不再由运行时代码追加阴影；Disappearing 和 Exploding 接入独立纸屑环、倒计时环和爆裂碎片图；
- 阶段 4 代码完成后只执行 Cocos 资源刷新、TypeScript 和静态边界检查；实际序列、画面、手感与六类平台状态待测试者按清单手动确认。

### 阶段 5 开发状态（2026-08-30）

- 已新增不依赖 Cocos 节点的 `DoodleJumpCombatSystem`，三类怪物使用独立 enemy 随机流生成；Small/Large/Hover 按 70/220/150m 解锁，生命值分别为 2/4/1，并按各自锚点范围和周期确定性运动；
- 怪物只在预算允许时消费生成判定，预生成缓冲中的候选不会因为暂时达到活动上限而永久失去生成机会；同屏活动数按高度限制为 1/2/3，离开相机下方 420 units 后回收；
- 怪物只允许在可见区上边界 24 units 之外实例化；候选平台进入屏幕后即作废，击杀怪物只释放活动预算，不会在当前屏幕内立刻补怪；
- 纸飞机使用上一位置到当前位置的线段扫掠命中扩张碰撞盒，命中后立即回收，不能穿怪；同帧先结算已有纸飞机，再进入固定子步的踩踏和身体接触判定；
- 平台落地后按原始下降轨迹检查怪物头部，踩踏直接击杀并以 940 units/s 反弹；未满足踩踏条件的身体重叠以 `monster-contact` 进入一次性失败锁；
- 已接入三类怪物各两帧正式图片、纸飞机命中擦痕和怪物爆散图片；开发态路线显示开启时同时显示身体盒和头部踩踏区；
- 得分已合并高度分、怪物击杀分和踩踏额外 25 分；失败日志、统计和结算附带命中、击杀、分类击杀、踩踏及平台落地数据。
- 怪物生成采用长难度曲线：70–900m 间生成率由 8% 升至 18%，同屏上限按 1/2/3 分段解锁，生成喘息距离由 720 缩至 360 units 后封顶；击杀或回收不会清除最近生成锚点，避免立即补怪。

### 阶段 6 开发状态（2026-08-30）

- 已新增独立纯 TypeScript `DoodleJumpHazardSystem`；危险物与平台生成共用 threat/enemy 随机流但不消费 platform/item/cosmetic 流，UFO、黑洞、捕兽夹均按活动预算、解锁高度、纵向排斥和相机下方 420 units 回收；P0–P2 不生成危险物；
- UFO 延后到第三个背景场景 600m 解锁；目标高度按角色上方 160–300 units 计算，但实例底边必须仍处在相机顶边之外；使用补全右侧轮廓的新飞碟图，176 × 430 units 的下方光束区按角色碰撞盒重叠锁定，以不超过 130 units/s 水平跟踪；光束内先锁定 0.5 秒，再以 460 units/s² 吸附，连续 1.5 秒触发 `ufo-abduction`；
- 黑洞实现 170 units 外圈的距离递增吸力、770 units/s² 上限和 28 units 核心失败；捕兽夹前置到 180m，固定在平台可见顶面并跟随 Moving/Shifting，生成时至少保留 76 units 无陷阱落脚宽度，从平台下方上穿不触发；危险物总生成门槛取三类危险物的最早解锁值，不再错误绑定 UFO 解锁高度；
- 失败原因扩展为 `fall`、`monster-contact`、`ufo-abduction`、`black-hole`、`bear-trap` 五种，并固化不可变 failureSnapshot；UFO 失败向光束收束淡出，黑洞失败缩小旋入核心，捕兽夹先闭合闪光再下坠，fall/monster-contact 仍完全掉出屏幕后才出现面板；
- 复活资格继续只由游戏复活开关和本局成功次数决定：首次免费、第二次广告、第三次结算；没有真实广告位时公共广告服务返回 completed；安全平台验证同时排除怪物和全部危险物，只向上搜索，必要时确定性创建 Normal 安全平台并清除复活半径内怪物、危险物和旧纸飞机；
- 已接入 `art_sources/涂鸦跃层/危险物` 和 `特效/failure_vfx` 的正式纸片素材，完成 Alpha 裁边和 Cocos 导入；危险物在 180–1000m 间由 4% 缓升至 12%，600m 前同屏最多 1 个、之后最多 2 个，喘息距离由 960 缩至 540 units 后封顶。

### 阶段 7 开发状态（2026-08-31）

- 已新增纯 TypeScript `DoodleJumpItemSystem`，道具使用独立 item 随机流；Spring、Trampoline、Jetpack、Propeller Hat、Rocket、Shield 均按冻结高度解锁和六段权重生成，拾取后立即从世界移除，活动上限为 5；道具、怪物和危险物的生成系统双向读取彼此占位，任何后生成对象都不能与已有对象碰撞盒重叠；
- Spring/Trampoline 分别把下一次有效落地反弹改为 1350/1700 units/s，Trampoline 覆盖 Spring；蹦床起跳后主角在完整上升时间内翻滚两圈，到达最高点开始下落时显式回到 0° 正面，该次跳跃仍持续无敌到下一次有效落地；两者脚底正式反弹图放大并延长至 0.72 秒；Breakable 不产生反弹，因此不会错误消耗待触发状态；
- Jetpack、Propeller Hat、Rocket 保留原有 1.8 秒主动阶段、速度和上升距离；主动阶段结束后不再立即移除道具，而是沿用原本就存在的普通重力减速段，到竖直速度 0 的弹道顶点才脱落。由此三者的完整可见时间可以不同，但不改变改造前的角色运动轨迹和总上升距离。飞行能力互斥且同类拾取刷新完整持续时间；高度层级继续由配置解析校验为 Rocket > Jetpack > Propeller Hat；Jetpack/Rocket/Head Start 穿平台，Propeller Hat 在主动阶段保留平台碰撞，三种飞行道具从激活到顶点统一免疫怪物、UFO、黑洞和捕兽夹，Head Start 不提供无敌；
- Shield 持续 6 秒，持续期内免疫怪物、UFO、黑洞和捕兽夹，不因第一次接触消耗；fall 不可抵挡；复活成功额外获得配置的 3 秒持续无敌护盾；
- 道具改为候选平台可承载宽度内的上方位置生成，生成完成后保持固定世界坐标，不再跟随 Moving/Shifting 平台；运行时每帧重申平台＜道具＜主角的渲染层级；
- Head Start 在传感器校准后、进入 Playing 前显示确认；确认才从 `doodle-jump` 存档或开发库存扣 1，跳过不扣，每局最多使用一次，持续 1.2 秒并以 1450 units/s 穿平台上升；复活不读取或消耗该库存；
- 已接入 `art_sources/涂鸦跃层` 内三张角色飞行组合图、独立 Shield Overlay、六种拾取物和对应运动/拾取/抵挡特效；处理脚本统一裁除透明留白并把四张角色图归一到同一脚底中心基线，运行时按状态切图并在 HUD 显示待触发能力和剩余时间；
- 失败日志、结算和统计已读取真实 `items/itemStatus`，道具拾取上报 `doodle_jump_item_pickup`；开发配置提供 `typeOverride`、`debugPowerPreset`、`debugHeadStartCount`，可与怪物、危险物和平台覆盖项组合执行阶段 7 手测矩阵。

阶段 7 代码与素材接入已完成；玩法组合、数值手感、正式画面和真机状态仍由测试者按阶段 7 手测清单逐项确认，不以自动游戏测试代替。

### 阶段 9 开发状态（2026-08-31）

- HUD 已换为本游戏独立的纸片涂鸦视觉：左上分数/高度卡按实际素材横向排列，右上保留暂停与指引入口；其下持续道具以“左图标＋右图片进度条”横向排列，不展示时间数字，一次性 Spring/Trampoline 只展示图标；无活动能力时道具区隐藏，拾取不再显示文字气泡；
- 首次引导已接入倾斜移动、点击/长按发射、危险规避三步图文，明确说明拖动不控制移动；“下一步”按 1→2→3 单步推进，“我知道了”可完成并关闭引导，右上指引入口可在局内重新打开同一套三步引导；

## 2. 模块边界

建议按职责拆分，具体文件可在实现时合并，但不得让入口组件承载全部玩法逻辑：

| 模块 | 主要职责 |
| --- | --- |
| `DoodleJumpGame` | MiniGame 生命周期、状态编排、Context 接入、一次性结算 |
| `DoodleJumpConfig` | 解析和校验全部配置化数值、文案、事件名和预算 |
| `DoodleJumpStateMachine` | 规格定义的 9 个运行态及合法转移 |
| `DoodleJumpInputController` | 传感器会话、校准、键盘回退、首个攻击指针和射击意图 |
| `DoodleJumpSimulation` | 1/120 秒固定步长、角色运动、落地、穿屏、相机和碰撞顺序 |
| `DoodleJumpWorldGenerator` | 独立随机流、平台候选、可达性求解、降级生成和复现信息 |
| `DoodleJumpCombatSystem` | 子弹调度、对象池、怪物伤害、踩踏和碰撞优先级 |
| `DoodleJumpHazardSystem` | UFO、黑洞、捕兽夹和爆炸平台危险逻辑 |
| `DoodleJumpItemSystem` | 弹簧、蹦床、飞行道具、护盾和起步助推 |
| `DoodleJumpSave` | 版本化读取、校验、未知字段保留、一次性历史固化 |
| `DoodleJumpPresentation` | HUD、引导、暂停、错误、复活、结算和独立视觉状态 |
| `DoodleJumpTelemetry` | 统计事件、射击批次聚合和退出冲刷 |
| `DoodleJumpPools` | 平台、子弹、怪物、危险物、道具和特效的创建与回收 |

纯规则、随机数、生成器、存档迁移和计分应尽量写成不依赖 Cocos 节点的 TypeScript 模块，并提供开发态输入、状态查看和复现入口，便于人工验证。进入微信小游戏构建的代码不得展开 `Map`/`Set` 迭代器。

### 阶段 11：稳定性、性能与手测交付

目标：完成开发侧编译和静态检查，并把浏览器可选回退、微信开发者工具、真机、完整玩法及压力场景整理成可直接执行的手动测试交付物。

任务：

- 执行 TypeScript 编译、配置校验、Bundle 边界、微信分包体积和 `Map`/`Set` 迭代器展开静态检查；不为本游戏建立自动化玩法测试、批量 seed 测试或自动交互测试；
- 提供可手动触发指定状态、失败原因、道具组合、传感器样本、资源缺失、加载超时和指定 seed 的开发调试入口；
- 输出 10 秒连发、60 秒对象回收、重复暂停/重开/退出、两次失败/复活和长局压力测试的操作步骤、预期结果及观察指标；
- 输出中低档真机 FPS、主循环 P95、Draw Call P95、纹理峰值、活动节点和冷启动时间的采集方法与通过阈值，由测试者在真机记录结果；
- 输出微信传感器方向、授权/超时、前后台 1500 ms 无新样本、胶囊区和底部安全区的测试步骤；
- 检查 `assets` 中不存在 `Map`/`Set` 迭代器展开；
- 运行 Bundle 边界和微信分包体积检查；
- 每次新增或修改资源后刷新对应 `db://assets` 目录，确保 Cocos 完成导入；不启动开发侧 browser 预览；
- 完成资源缺失、加载超时、入口缺失、异常重试和安全返回大厅测试；
- 发布前把 Manifest 从 development 调整到目标可见性，并保留一键隐藏回滚路径。

阶段门禁：开发侧编译和静态检查通过；完整手测清单、代表性 seed、调试入口使用说明和性能采集说明交付给测试者。浏览器、微信真机和完整玩法是否通过，由测试者执行清单后确认，未确认前不得把游戏标记为发布完成。

## 5. 首批实施任务

开始编码时按以下顺序建立首批小任务，避免一开始并行铺开全部内容：

1. 审核公共 Platform 加速度计实现的轴向归一化、监听解绑和错误可观测性。
2. 建立 `game-doodle-jump` Bundle、场景、Canvas/UI Camera 和 `DoodleJumpGame` 生命周期空壳。
3. 建立 gameplay 配置与校验器，录入物理、输入、固定 P0–P7 和性能预算。
4. 建立状态机、会话锁、失败锁和开发调试面板。
5. 实现纯 TypeScript 固定步长角色模拟，并提供固定输入轨迹、单步推进和状态观察入口供手动验证。
6. 接入传感器校准和浏览器键盘回退。
7. 渲染角色、P0–P7 占位平台、相机和左右穿屏，完成 M1 的移动半程。
8. 实现攻击指针、全局冷却、纸飞机池和 10 秒连发压力验证，完成 M1。

在 M1 验收通过前，不开始怪物、危险物和道具接入；正式图片已位于 `art_sources/涂鸦跃层`，可并行完成清点、切分和元数据整理，进入项目前必须完成来源、尺寸、锚点和碰撞参考验收。缺失图片按冻结规范直接生成补齐；正式音频等待产品后续提供。

## 6. 风险与前置决策

| 风险 | 处理策略 |
| --- | --- |
| 微信加速度计 API 不返回启动失败结果 | 以首个有限样本作为成功信号，1500 ms 超时进入 Error；重试先完整 stop/unsubscribe/reset |
| 平台可达性算法复杂且难靠目测验证 | 先做纯逻辑求解器、固定 seed 回放、路线可视化和失败现场导出，再接入场景节点；以覆盖各高度段和降级路径的代表性 seed 清单进行人工回归 |
| 飞行道具、护盾和危险物组合爆炸 | 以规格 10.1 为单一表驱动规则源，禁止在多个组件中散落条件分支 |
| 连发导致节点、碰撞和统计压力 | 子弹池允许扩容，命中/超时立即回收，统计按 1 秒批次聚合 |
| Cocos 坐标、安全区和相机混用 | 世界单位、Canvas 坐标、平台布局坐标明确分层；所有转换集中封装并覆盖长短屏验证 |
| 正式资源较多，阻塞玩法开发 | M0–M3 使用本游戏独立开发占位；正式资源按冻结清单并行生产，在 M4 统一验收替换 |
| 工作区已有其他游戏未提交改动 | 所有改动限制在 doodle-jump 与必要公共接口；公共文件修改前逐项审查现有差异，禁止覆盖无关改动 |
