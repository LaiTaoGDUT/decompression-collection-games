# 纸片跳跃分阶段性能优化方案

> 目标平台：Cocos Creator 3.8.8 / 微信小游戏
> 设计基准：单手竖屏 750 × 1334，运行时 Fit Width
> 计划固化日期：2026-09-09
> 当前状态：阶段 1、阶段 2、阶段 3、阶段 4、阶段 5 已完成；阶段 6 待确认

## 1. 执行规则

优化按 7 个阶段执行，并采用严格确认门：

1. 每次只实施一个阶段。
2. 阶段内完成代码修改、TypeScript 编译检查、`git diff --check` 和 Cocos 资源刷新。
3. 完成后立即停止，不进入下一阶段。
4. 每阶段汇报修改内容、修改文件、验证结果、行为或视觉风险，以及当前工作区差异摘要。
5. 只有收到明确的“继续”“确认”或指定下一阶段的指令后，才实施下一阶段。
6. 如果某阶段验证失败，停留在该阶段修正；不得带着失败结果进入后续阶段。
7. 不自动创建 Git commit，除非另有明确要求。

始终优先做根因优化，不通过关闭效果、降低实体数量或降低画质掩盖卡顿。

## 2. 阶段 1：固定模拟频率改为 60 Hz（已完成）

- 将 `fixedStep.seconds` 从 `1 / 120` 调整为 `1 / 60`。
- `maxSubSteps` 保持 `4`。
- accumulator 和固定步结构保持不变。
- 重力、弹跳速度、横向运动、相机、道具和危险物参数保持不变。
- 检查平台落地、敌人踩踏、尖刺、捕兽夹和纸飞机的跨步判定。
- 如果 60 Hz 下存在高速穿透，只修复对应连续碰撞检测，不扩大碰撞盒、不调整玩法参数。
- 覆盖普通跳跃、蹦床、喷气背包、火箭和开局冲刺。

预期收益：正常 60 FPS 下，模拟子步由每个渲染帧约 2 次降为约 1 次，固定步内的世界同步、碰撞遍历和临时分配次数接近减半。

实施结果：`fixedStep.seconds` 已改为 `1 / 60`，`maxSubSteps` 保持 `4`；同时修复敌人踩踏在 60 Hz 下可能越过离散头部区域的问题。

## 3. 阶段 2：移除逐帧完整快照分配（已完成）

- 将完整快照职责拆分为 presentation view 和 persistent snapshot。
- presentation view 复用对象，供逐帧画面同步使用。
- persistent snapshot 仅在存档、暂停、失败、复活、结算和调试导出等生命周期边界创建不可变深快照。
- `DoodleJumpGame.update()` 每帧只读取一次 presentation view。
- 落地效果捕获、渲染和 HUD 共用该视图。
- 保持 `DoodleJumpSimulationSnapshot` 的持久化字段和恢复语义不变。
- 不改变模拟更新、随机生成或碰撞逻辑。
- 对比固定种子下的生成序列、计分、失败原因和 RNG 游标。

预期收益：消除每帧多次 `map()`、对象创建、数组创建和 `Object.freeze()`，重点缓解不定时 GC 卡顿。

实施结果：已新增复用的 `DoodleJumpSimulationPresentationView`；固定种子双模拟、视图与快照字段对照、深冻结及恢复往返验证均已通过。

## 4. 阶段 3：合并固定步内的重复世界同步（已完成）

只治理 Combat、Hazard、Item 的模拟热路径：

- 把综合 `syncWorld()` 拆为更新已有实体，以及相机和平台生成完成后评估新增平台并回收旧实体。
- 每个固定步只建立或更新一次平台 ID 索引，由三个 System 共享。
- 平台投影和占位碰撞数据改为复用 scratch buffer。
- 避免为 Combat、Hazard、Item 分别创建同内容的平台数组。
- 热路径中的 `filter().sort()` 改为确定性的显式扫描。
- 保持现有碰撞与事件优先级。
- 严格保持随机流调用顺序、每个平台的评估次数和生成时机。
- 遵循微信小游戏转换兼容要求，不使用 `Map`/`Set` 迭代器展开语法。

预期收益：减少每个 60 Hz 子步中的重复遍历、`Map` 构建、排序和临时数组。

实施结果：已建立由三个系统共享的持久化平台索引和确定性有序平台视图；综合同步已拆分为现有实体更新与生成后协调；占位碰撞体、危险物类型排序均使用复用 scratch buffer；阶段 2 基线与优化后实现的逐步完整快照对照已通过。

## 5. 阶段 4：缓存 Cocos 组件和渲染状态（已完成）

- 动态视觉池保存结构化 visual record：`Node`、`UITransform`、`Sprite`、`UIOpacity`、常用子节点和子组件。
- 移除热循环中的重复 `getComponent()`、`getChildByName()`。
- 只有值发生变化时才设置 `spriteFrame`、`active`、`contentSize`、Sprite 类型、HUD 文本、静态颜色和透明度。
- 位置、旋转、缩放和真实动画透明度仍按渲染帧更新。
- 缓存可见尺寸，只在初始化和尺寸变化时重新读取。
- 使用颜色常量或缓存颜色，避免逐实体每帧 `new Color()`。
- 不改变节点结构的可见结果、动画速度和视觉尺寸。

预期收益：减少 JavaScript 到 Cocos 引擎层的调用和短命对象分配。

实施结果：动态平台、道具、敌人、危险物及战斗/落地效果已建立结构化 visual record，缓存节点、`UITransform`、`Sprite`、`UIOpacity`、`Graphics` 和常用子节点；贴图、Sprite 类型、激活状态、尺寸、HUD 文本和静态颜色改为值变化时才写入；可见尺寸只在初始化与画布变化时读取；逐帧动画颜色改用缓存颜色。位置、旋转、缩放和动画透明度仍按渲染帧更新。

## 6. 阶段 5：固定渲染层级并增加无损剔除（已完成）

- 为背景、平台、道具、弹道、世界特效、玩家和准星建立固定层级容器。
- 初始化时确定容器顺序，移除逐帧 `setSiblingIndex()`。
- 渲染层只激活并更新可见区域及安全预留范围内的实体；模拟层继续保留全部实体。
- 按真实视觉边界为 UFO 光束、黑洞外环、平台爆炸、落地和纸屑效果、高速弹道保留额外范围。
- 离屏对象重新进入时，根据当前模拟时间计算动画相位，不让动画从头播放。
- 使用实体 ID 到 visual slot 的稳定映射，避免回收后贴图或状态错位。
- 对照截图或录屏确认画面边缘没有提前出现或消失。

预期收益：世界持续增长或到达较高高度后，逐帧渲染工作量仍保持稳定。

实施结果：世界节点已拆分为平台、实体、弹道、世界效果、玩家和准星六个固定层级，并在初始化时冻结玩家内部视觉顺序，移除了运行期 `setSiblingIndex()`；平台、道具、敌人、危险物按真实视觉边界和类型专用预留范围无损剔除，UFO 光束、黑洞外环、平台破裂/爆炸、落地/拾取/战斗反馈及飞行道具掉落均保留额外范围；实体 ID 与视觉槽建立稳定映射，离屏实体保留模拟和槽位，重新进入时直接使用当前模拟时间及当前效果进度恢复画面。

## 7. 阶段 6：预热首次使用节点和效果池（待实施）

- 在资源加载完成、正式游戏开始前预创建平台破裂状态、UFO、黑洞、捕兽夹、敌人反馈、落地/拾取/穿屏/失败效果、纸飞机与尾迹、玩家飞行/护盾/动力效果。
- 预热期间保持加载界面，不让临时节点闪现。
- 游戏中优先从池中获取；回收时完整复位 active、SpriteFrame、颜色、透明度、尺寸、缩放和旋转。
- 重开时复用池；退出时销毁节点并清空引用。
- 验证第一次出现各类实体和效果时没有视觉残留或明显创建尖峰。

预期收益：消除刚开始游玩或某类特效第一次出现时的节点初始化尖峰。

## 8. 阶段 7：整理静态图集与渲染批次（待实施）

- 只在 `game-doodle-jump-assets` Bundle 内，按共同使用的视觉模块建立小型 Auto Atlas：平台、敌人及战斗反馈、道具及拾取反馈、尺寸合适的危险物部件。
- HUD 和道具状态图标继续使用现有图集。
- 不把背景、面板、大尺寸黑洞或不同时使用的素材强行合入同一图集。
- 图集内资源直接加载 SpriteFrame，避免先加载 Texture2D 再创建 `packable = false` 的运行时 SpriteFrame。
- 动态 Atlas 仅负责剩余且适合动态合批的资源。
- 对照原素材确认裁切、九宫格、透明边缘、锚点和尺寸完全一致。
- 检查 Bundle 边界，不跨小游戏或大厅合图。

预期收益：降低 Draw Call、材质切换和动态 Atlas 运行时整理压力。

## 9. 接口与兼容性

- `MiniGame`、`MiniGameContext`、Manifest、公共服务和小游戏生命周期接口不变。
- `DoodleJumpSimulationSnapshot` 的存档格式保持兼容。
- Bundle 内部允许新增 presentation view、共享平台索引、scratch buffer 和 visual record。
- 固定模拟频率从 120 Hz 改为 60 Hz，因此不要求优化前后每个子步的浮点坐标完全相同。
- 相同种子和等价输入下必须保持平台、敌人、危险物和道具的生成类型及顺序、RNG 游标顺序、计分和奖励结果、拾取/击杀/失败/复活语义，以及游戏画面和特效表现。

## 10. 每阶段统一验证

每个阶段完成后必须执行并汇报：

- TypeScript 编译无错误。
- `git diff --check` 通过。
- 使用 `cocos_creator_stdio` 刷新资源。
- 确认刷新后没有新增 Cocos 导入或脚本错误。
- 检查本阶段没有混入下一阶段的改动。
- 列出已有但与本阶段无关的用户工作区改动，不覆盖或清理它们。
- 不自动进入下一阶段。

确定性回归使用相同 seed 和输入序列，对比生成顺序、计分、失败原因、完整快照和所有 RNG 游标。

## 11. 验收重点

- 普通跳跃、移动平台和横向穿屏。
- 弹簧、蹦床、喷气背包、螺旋桨帽、火箭、护盾和开局冲刺。
- 敌人踩踏、直接接触、纸飞机命中和击杀。
- 尖刺、UFO、黑洞和捕兽夹。
- 暂停、重开、退出、前后台切换、失败、复活、结算和活动局恢复。
- 微信真机长时间运行时不出现随高度或时长持续恶化的分配、GC 或渲染卡顿。
