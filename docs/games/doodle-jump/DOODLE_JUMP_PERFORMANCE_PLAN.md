# 纸片跳跃 60 Hz 固定步长与性能优化计划

> 状态：待实施  
> 目标平台：Cocos Creator 3.8.8 / 微信小游戏  
> 记录日期：2026-09-07  
> 当前阶段：仅固化方案，尚未修改游戏代码、配置或资源

## 1. 背景与结论

纸片跳跃目前容易出现持续掉帧和间歇卡顿。静态检查发现，主要压力来自固定模拟热路径中的大量短命对象、重复世界同步，以及表现层对屏外节点和未变化状态的逐帧重复处理。

当前物理以 120 Hz 固定步长运行。每个固定步会在玩家移动前后分别同步战斗、危险物和道具系统；每次同步又会复制完整平台列表、建立新的平台索引，并通过快照复制敌人、危险物和道具数据。在正常 60 FPS 下，这会持续产生大量数组、对象和 `Map`，容易在微信小游戏 JavaScript 运行时引发频繁垃圾回收。

本次计划明确采用以下核心决策：

- 固定物理频率从 120 Hz 调整为 60 Hz。
- `fixedStep.seconds` 从 `0.008333333333333333` 调整为 `0.016666666666666666`。
- `fixedStep.maxSubSteps` 从 `4` 调整为 `2`。
- 最大追帧窗口仍保持约 33.3ms；超过窗口的累计时间计入 `droppedFrameSeconds` 后丢弃，避免长帧形成追帧风暴。
- 同时从根因上消除固定步中的重复平台复制、逐帧完整快照、屏外节点提交和重复组件状态写入。
- 不通过减少玩法内容、降低生成数量或粗暴关闭正式视觉效果掩盖问题。

## 2. 60 Hz 固定模拟

### 2.1 配置调整

在纸片跳跃玩法配置中设置：

```json
{
  "fixedStep": {
    "seconds": 0.016666666666666666,
    "maxSubSteps": 2
  }
}
```

调整后的运行语义：

- 60 FPS 时，每个渲染帧通常执行 1 个固定步。
- 30 FPS 时，每个渲染帧通常执行 2 个固定步。
- 更长的卡顿帧最多补算 2 步，多余累计时间记入 `droppedFrameSeconds` 并清零。
- 暂停恢复或前后台切换产生的大间隔不得触发超过 2 步的集中补算。

### 2.2 保持不变的玩法参数

以下配置均以秒或每秒为单位，改为 60 Hz 后保持原值，不额外乘除系数：

- 重力、横向加速度、横向减速度和速度上限。
- 普通跳跃、弹簧、蹦床、喷气背包、螺旋桨帽和火箭速度。
- 射击冷却、弹体速度和弹体寿命。
- 道具、护盾、危险物、复活及平台效果持续时间。
- 平台和敌人的移动周期。
- 相机跟随和世界生成所使用的距离参数。

继续使用固定步长积分，不改成可变步长物理，也不在一个 60 Hz 固定步内部再次拆分隐式子步。

## 3. 模拟热路径优化

### 3.1 共享实时世界索引

在 `DoodleJumpSimulation` 内维护唯一的实时世界索引：

- `DoodleJumpWorldPlatform[]` 保存平台的实时位置、尺寸、类型和碰撞状态。
- `Map<string, DoodleJumpWorldPlatform>` 保存平台 ID 到实时平台的索引。
- 使用拓扑版本或明确的新增/移除集合表示平台变化。

平台移动时原地更新字段；仅在重置、恢复、生成和回收平台时增量维护数组及索引。战斗、危险物和道具系统共用同一份世界索引，不再各自创建平台投影数组及平台 `Map`。

### 3.2 拆分更新与拓扑同步

将当前单个固定步内的两轮完整世界同步改为：

1. 更新现存平台的位置和状态。
2. 更新现存敌人、危险物和附着道具的位置。
3. 执行玩家移动、碰撞、拾取和危险物作用。
4. 回收旧平台并生成新平台。
5. 只将本步新增或移除的平台增量通知各实体系统。

新平台仍按照原有顺序接受敌人、危险物和道具生成判定。每个平台只能判定一次，不能因增量同步而重复消费随机流或重复生成实体。

### 3.3 消除稳定帧分配

- 各系统提供只读实时碰撞体视图，或写入由模拟层复用的碰撞体缓冲区，不通过 `getSnapshots()` 交换内部碰撞信息。
- 将碰撞逻辑中的 `filter().sort()` 改为单次确定性遍历，继续按原有高度、命中时间和 ID 规则选取目标。
- 缓存无事件时的空数组、固定道具物理结果和常用碰撞结果。
- 不在固定步热路径中对临时结果执行 `Object.freeze()`。
- 在平台拓扑和玩法事件均未变化的固定步中，不产生与平台数量成正比的新数组、对象或 `Map`。

## 4. 实时帧视图与持久化快照

保留 `getSnapshot(): DoodleJumpSimulationSnapshot` 的现有完整结构和存档语义。完整快照只用于：

- 周期性进度存档。
- 失败、复活和结算边界。
- 暂停、切前后台、退出和销毁。
- 活动局恢复及调试验证。

新增复用的 `DoodleJumpFrameView`，用于当前渲染帧读取：

- 玩家位置和速度。
- 相机位置。
- 分数及玩法统计。
- 道具状态。
- 平台、敌人、危险物和道具的实时只读列表。

帧视图只保证在下一次 `advance()` 前有效，调用方不得修改或长期持有。`DoodleJumpGame.update()` 每帧只获取一次帧视图，并将同一视图传给落地反馈、世界渲染和 HUD 更新。

补充以下轻量事件或查询：

- 模拟级落地事件直接携带平台 ID、类型、位置和最新落地次数。
- 战斗事件携带最新累计命中次数。
- 射击通过轻量玩家/相机状态读取出生点。

上述改动用于移除落地、射击、命中和渲染过程中的额外完整快照。

`DoodleJumpSimulationSnapshot` 的字段和存档 schema 不变。旧版本保存的活动局仍可恢复；恢复后的后续模拟从第一个新固定步开始采用 60 Hz。

## 5. 表现层优化

### 5.1 稳定渲染层级

为以下类型建立固定子层级：

1. 平台。
2. 道具。
3. 敌人和危险物。
4. 世界特效。
5. 弹体。
6. 玩家。
7. 准星和前景反馈。

节点创建时一次性确定父节点和绘制顺序，删除逐帧 `setSiblingIndex()` 重排。事件特效继续使用节点池，但始终归入固定特效层。

### 5.2 缓存节点组件和视觉状态

节点池条目改为渲染槽位，缓存：

- `Node`
- `UITransform`
- `Sprite`
- `UIOpacity`
- 当前实体类型和资源键
- 当前宽高、颜色、透明度及激活状态

热路径不再重复执行 `getChildByName()` 和 `getComponent()`。贴图、类型、静态尺寸和静态子节点只在实际变化时更新。

### 5.3 屏外裁剪

- 根据相机上下边界增加预加载余量，裁剪平台、敌人、危险物和道具。
- 屏外节点设为不激活，并跳过尺寸、颜色、贴图和动画更新。
- 永不回收的 P0–P7 固定平台离开视野后也不再提交渲染。
- 高速上升、火箭、复活和长短屏情况下，节点需在进入可见区域前恢复，避免闪入。
- 节点池继续保留，裁剪只影响显示和逐帧更新，不改变模拟实体生命周期。

### 5.4 避免重复属性写入

- 为每个渲染槽位复用颜色状态，或仅在最终 RGBA 字节变化时写入组件颜色，移除逐帧 `new Color()`。
- 背景瓦片缓存当前贴图和尺寸；仅在瓦片跨主题时重新设置。
- 背景装饰的随机图、尺寸、位置和旋转仅在节点被循环复用或跨主题时重算。
- 高度、分数、道具图标和进度条仅在最终显示值变化时写入组件。
- 可见区域尺寸在初始化和 `canvas-resize` 时缓存，稳定帧不重复查询。

## 6. 静态图集合批

为以下同一游戏 Bundle、同一视觉模块且游戏中共同使用的小型 SpriteFrame 集合分别建立 Auto Atlas：

- 平台。
- 敌人。
- 道具。
- 危险物。
- 纸飞机及瞄准相关弹体资源。

背景、面板、教程图和不共同显示的大型资源保持独立，不跨游戏、跨大厅或跨视觉模块合图。

加载策略：

- 微信构建优先加载静态图集帧，以共享纹理并降低 Draw Call。
- 编辑器预览或图集暂不可用时，继续回退到单张 `Texture2D`。
- 从静态图集复制出的运行时帧保持 `packable = false`，不再进入动态 Atlas。
- 保留现有微信兼容逻辑，避免原生图片数据回收后动态合图读取纹理尺寸导致崩溃。
- 图集构建应移除 Bundle 中重复的源纹理，避免增加微信分包体积。

资源和 `.meta` 变更后必须通过 `cocos_creator_stdio` 刷新资源，并核对图集产物与 `game-doodle-jump-assets` Bundle 归属。

## 7. 接口与兼容性

计划新增以下纸片跳跃 Bundle 内部接口：

- `DoodleJumpWorldPlatform`
- `DoodleJumpWorldIndex`
- `DoodleJumpFrameView`
- 携带落点数据的模拟事件

战斗、危险物和道具系统的世界同步接口改为接收共享世界索引以及平台增量变化。这些接口仅服务纸片跳跃内部，不向大厅或公共模块暴露。

保持以下内容不变：

- `DoodleJumpSimulationSnapshot` 字段和存档 JSON。
- `MiniGame` 生命周期。
- 大厅清单和核心加载流程。
- 玩家速度、重力、跳跃高度、生成概率、得分和复活规则。
- 随机流的用途及平台生成判定顺序。

60 Hz 会改变离散积分轨迹，因此不要求新版本和旧 120 Hz 版本的浮点快照逐字段相等。要求玩法行为、随机内容和最终结果等价；允许接触和计时出现不超过一个 60 Hz 固定步，即约 16.7ms 的量化差异。

## 8. 测试计划

### 8.1 编译与工程检查

- TypeScript 无编译错误。
- `git diff --check` 通过。
- `npm run verify:game-bundles` 通过。
- 生成最新微信构建后运行 `npm run verify:wechat-package-size`。
- 修改资源后执行 Cocos 资源刷新，并确认场景和 Bundle 没有失效引用。

### 8.2 确定性回归

- 同一 seed、同一 60 Hz 输入序列运行两次，最终完整快照逐字段一致。
- 30 FPS 输入每帧执行约 2 步，60 FPS 输入每帧执行约 1 步；在等价输入时间下得到一致结果。
- 每个平台只进行一次敌人、危险物和道具生成判定。
- 增量世界同步不得额外消费随机流或改变平台路线。
- 存档、恢复、失败和复活之后继续保持确定性。

### 8.3 物理与碰撞回归

覆盖以下场景：

- 静止、持续左倾、持续右倾和方向快速切换。
- 普通、移动、垂直移动、破碎、消失、位移、爆炸和倒刺平台。
- 横向穿屏。
- 弹簧、蹦床、喷气背包、螺旋桨帽、火箭和护盾。
- 敌人踩踏、直接接触、纸飞机命中和击杀。
- UFO、黑洞和捕兽夹。
- 暂停、重开、退出、切前后台、失败、复活、结算和活动局恢复。

重点验证 60 Hz 下的高速连续碰撞：

- 玩家下落不得穿过平台或敌人头部。
- 火箭、喷气背包和蹦床状态不得漏掉倒刺、危险物或平台接触。
- 纸飞机继续使用线段扫掠检测，不因步长增大漏过敌人或 UFO。
- UFO 光束、黑洞核心和捕兽夹边界不得出现明显漏判。
- 如发现 60 Hz 导致穿透，应修正对应连续碰撞逻辑，不通过修改重力、速度或扩大所有碰撞框补偿。

### 8.4 渲染回归

- 常见长屏、短屏和不同像素密度下，屏外裁剪不得产生实体闪入。
- 平台、道具、敌人、危险物、玩家、纸飞机、世界特效和准星的遮挡顺序保持正确。
- 检查平台破碎、消失和爆炸动画，以及 UFO、黑洞、道具状态和背景主题过渡。
- 编辑器预览验证单图回退；微信构建验证静态图集实际加载且没有缺图。

### 8.5 性能验收

使用固定 seed 在微信真机连续运行至少 10 分钟，覆盖高处动态平台、三名敌人、两个危险物、三个道具和持续射击。

中档设备目标：

- 稳定接近 60 FPS。
- P95 帧耗时不高于 20ms。
- 不出现周期性 100ms 以上 GC 卡顿。

低档设备目标：

- 至少稳定 30 FPS。
- 不出现随游戏时长持续恶化的掉帧或多帧冻结。

需要对比优化前后的：

- 每秒固定步数量。
- 脚本 P50/P95 耗时。
- JS 堆分配速率和 GC 次数。
- Draw Call。
- `droppedFrameSeconds` 增长速度。

稳定运行期间不得再创建平台投影数组、平台投影对象或平台索引 `Map`；完整模拟快照不得出现在逐帧渲染热路径。

### 8.6 生命周期回归

- 快速暂停、重开、退出和复活不得创建重复 Session 或重复结算。
- 反复进入、退出纸片跳跃后，节点池、事件、监听、计时器、运行时帧和图集引用均正确释放。
- 返回大厅后不得残留纸片跳跃的逐帧更新或资源引用。

## 9. 实施约束与默认选择

- 固定模拟明确采用 60 Hz，最大补算步数明确采用 2。
- 不根据设备动态改变物理频率。
- 不因步长变化调整现有重力、速度、冷却或持续时间配置。
- 如果测试确认某项规则因离散积分产生实质偏差，修复对应碰撞或状态逻辑，不以玩法数值补丁掩盖问题。
- 保留当前工作区已有的 `maximumSuccessfulRevives: 1` 修改和所有其他无关未提交改动。
- 默认按微信小游戏真机性能验收；浏览器预览只用于功能和自动化辅助验证。
- 本文档只记录后续实施方案，不代表上述改动已经完成。
