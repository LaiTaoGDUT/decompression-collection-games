## 1. 使用规则

- 开发者工具、微信真机和用户试玩均复制本模板填写，不直接改写空白模板。
- 每份记录只对应一个构建版本和一组明确的测试条件；构建或配置变化后新建记录。
- 主观观察、功能通过/失败和量化测量分栏记录，不用“流畅”“还行”等主观描述替代帧率、内存或时长数据。
- 未采集的数据填写“未测”，不得填写 `0`、猜测值或根据其他设备推断。
- 每个失败项必须附复现步骤、期望结果、实际结果和证据位置。
- 涉及广告时使用测试广告位或受控 Mock；记录中不得包含正式广告位密钥、用户标识或其他敏感信息。
- 真机量化记录必须包含设备、系统、微信版本、网络和测量方法，否则只能作为主观或功能证据。

## 14. 阶段放行规则

- 任一未解决的阻塞级问题均不得进入用户试玩候选版本。
- 首局理解度必须基于无主动教学的真实行为记录；测试人员提供提示的样本需单独标记。
- 广告非完成结果出现奖励、同一请求重复奖励或广告失败阻断结算/导航，均按阻塞问题处理。
- 无法重开、无法回大厅、必须重启小游戏才能恢复的主路径异常，均按阻塞问题处理。
- 没有设备、网络、工具和原始证据的性能描述不能作为量化放行依据。
- 第 34 步的低、中、高设备具体性能门槛必须结合实测基线单独确认；本模板不预先伪造尚未测量的阈值。
- 第 35 步用户试玩需汇总样本数、分子/分母和问题严重度，不能用单一参与者反馈代表总体结论。
