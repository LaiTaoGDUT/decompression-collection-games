# 游戏玩法介绍

把指定小游戏的真实规则和现有美术，整理成一套可以直接发到游戏圈的图文素材。文章由当前任务撰写；图片排版统一由脚本执行，避免每次重新设计封面。

## 先确认内容

- 将用户给出的中文名称或 ID 对应到 `assets/resources/configs/games.json` 的唯一条目。用户已明确游戏时直接继续；出现重名或无法匹配时，只澄清影响选择的信息。
- 从清单读取正式名称、当前 `cover` 资源及公开状态。到 `assets/games/<目录>/scripts`、`configs` 中读取规则模型、新手引导、操作文案和主题；部分目录与 ID 不同，例如 `game2048` 对应 `twenty48`。
- 名称像传统玩法也要读实现。例如本项目的猫咪数独是每行、每列、每种颜色各一只猫，猫咪不能相邻（包括对角），不能按数字数独来写。
- 只把确认存在的规则、操作和功能写进文章。不要承诺奖励、更新日期、零广告或不存在的模式。用户已说明线上状态时沿用；尚未上线的内容按实际情况标明。

## 撰写与选图

- 默认中文，一款游戏一篇。标题通常使用「游戏名｜玩法亮点」，不超过微信页面的 45 字限制。正文默认约 250～450 字，用户的长度、语气与重点优先。
- 先提炼当前实现中最有辨识度的操作、规则或反馈；用户强调的特色作为文章主线，体现在标题、正文开头、封面和正文要点卡中。基础操作与通用技巧随后补充。
- 本项目的合成大西瓜果冻重点是果冻挤压形变、回弹，以及摇晃手机搅动容器内的水果。写到晃动时核对体感回调与 `stir()`，说明实际操作和可能带来的合成机会，不承诺摇动必定合成或解局。
- 自然地说明玩法目标、最少必要规则、手指操作和 2～3 个入门技巧，末尾可以邀请分享关卡、成果或问题。无需固定小标题或为了凑数重复写法。
- 封面提炼 3～4 个短要点；副标题是一句玩法概述，底部一句操作提示或交流邀请。文章和图片的规则必须一致。
- 优先使用 Manifest 当前引用的官方封面和项目现有美术。原画可作为宣传配图；只有实际运行截图才能称为实机界面。用户指定截图或其他原图时可传给脚本。
- 玩法介绍的补充实机配图默认选择关卡进行中的真实画面，展示核心操作、排除标记或阶段性进度；多张图选择有区别的有效局面。确认核心玩法清楚可见，选关页、通关弹窗等画面仅在用户要求介绍对应功能时使用。
- 缺少合适美术时，先检查已有素材与用户提供的参考。确实需要新原画再使用可用的图像生成能力；统一封面的品牌、中文文字和版式仍由脚本排版。

## 生成统一素材

1. 需要首次确认版式或修改模板时，查看 [封面参考](assets/cover-reference.jpg) 和 [固定布局](assets/cover-layout-v1.json)。正常生成直接沿用模板。
2. 阅读 [输入格式与命令](references/input-format.md)，为本次文章准备 JSON。可参考 [猫咪数独示例](references/example-meowdoku.json)；它是用法示例，新的文章须重新读取当前游戏规则。
3. 使用 `load_workspace_dependencies` 获得本机 Node 和 Node 包目录，传给 `scripts/build.cjs`。脚本按 `gameId` 自动定位 Manifest 当前封面，不依赖历史 `output`、临时目录或某位用户的绝对路径。
4. 使用同一个 `cover-layout-v1` 模板：1200 × 900、顶部品牌区、正式游戏名与副标题、左侧要点卡、右侧原画、底部短句。只替换内容和有依据的游戏主题配色；普通生成不修改坐标、尺寸、圆角或字体层级。
5. 脚本同时输出两张正文配图：原画/用户指定图，以及 1200 × 1200 的玩法要点卡。补充实机截图时放入 `bodyImages`；模板不会伪造游戏 UI。脚本保存复制预览页、输入数据、来源记录及 ZIP。

除非用户要求，素材放在 `output/gameplay-articles/<gameId>`；重名时自动新建带数字后缀的目录。用户指定目的地时优先使用。生成不修改游戏代码、Bundle、图集或原始美术。

## 核对与交付

- 查看生成的封面和要点卡，确认品牌完整、文字清楚、没有越界，核心角色/棋盘没有被裁掉。脚本会检查文字框溢出；这不能替代视觉检查。
- 核对正文、封面要点、正文要点卡和实际规则一致。输入中的 `sources` 是本次事实依据，不要把文件存在误当成内容已经核实。
- 最低交付：标题 TXT、正文 TXT、封面 JPG、至少两张正文配图、可复制的 HTML 预览、完整 ZIP。回复给出素材链接、封面预览和一个简短的发布操作说明。
- 默认交付待发布素材。用户明确要求发布时，沿用当前会话授权，另用可用的微信后台能力操作；制作素材本身不等于已经发布。
